## 2025 阅读与分发（摘要）

- **推荐流量权重上升**：完读率、停留、**推荐 ♡**（原「在看」）、留言/转发影响「朋友推荐」与「看一看」；小号优质文可获超过推送的推荐量
- **流量主**：底部/文中广告按曝光与 eCPM 计费；**完读率低 = 看不到广告 = 无收益**（见下节「流量主优化」）
- **跳读习惯**：很多人先看标题 → 滑到底看结尾 → 再扫中间小标题（刘润团队 2025 法则）
- **搜一搜**：标题、公众号名、摘要含领域词有助搜索；勿堆砌关键词（约 1%–3% 密度即可）
- **AI 直发风险**：纯 AI 不修改易被识别、限流；本仓库用 **LLM 草稿 + humanize/静态精修 + 人工审**
- **发稿频次**：工作日 **2～3 篇/天** 为宜；超过 3 篇后推荐流量往往明显衰减

## 标题（吸睛但不标题党）

| 类型 | 示例结构 | 本仓库 |
|------|----------|--------|
| 数字+结果 | 「5 只观察标的，明日盯啥？」 | Top5 标题池 |
| 疑问+悬念 | 「情绪退潮怎么玩？」 | 龙头/宏观池 |
| 场景+反差 | 「收盘推送和证书续签，原来在同一套 git 里？」 | 工作区池 |
| 痛点+承诺 | 「脚本越写越散？后来全收进了一个仓库」 | 工作区池 |

**检查（发布前）**

- [ ] 核心信息在前 15 字内（手机列表截断）
- [ ] 长度 ≤ **32 字**（代码 `_clip_wechat_title`；行业常写 15–28 字，我们以平台上限为准）
- [ ] 含 `？` 或 `！` 之一（行情三篇吸睛池；工作区同理）
- [ ] **`market` 与 `news` 标题不同调**：前者盘面/结构，后者 10 条快讯；勿同日雷同（见 `_titles_too_similar`）
- [ ] **`market` 标题按时段**：`edition=pre` 可用「盘前/开盘」；`midday` 可用「午间」；`close` 用「收盘/盘后」——**禁止**把盘前稿写成「收盘复盘」
- [ ] 不虚假夸张（「震惊」「100 倍」）；不塞 git 目录名
- [ ] 与封面、摘要主题一致

## 开头（前 3–5 句定生死）

优先 **具体场景 / 结果**，少用空泛痛点：

- ✅ 「收盘后大约一刻钟，会跑完入库、战报、四条草稿覆写……」
- ❌ 「在当今数字化时代，自动化越来越重要……」

可选用 **SCQA**（情境 → 冲突 → 问题 → 下文答案），工作区/宏观都适用。

行情稿：首段给「今天盘面一句话」或「数据日 + 次日跟踪」；技术稿：给「读者看完能知道什么」。

## 正文结构与排版

**三三原则**（移动端）：

- 每段尽量 **≤3 行**（手机屏）；代码默认 **≤120 字/段**（`WECHAT_MP_PARA_MAX_CHARS`，`wechat_mp_readability.py` 在进 HTML 前自动拆段）
- **`1. 2. 3.` 序号列表每项单独一行**（禁止「1. A 2. B」挤一行）；Top5 的 `逻辑归属/量价结构/…` 同行多标签也会自动拆行
- 每 **2–3 段** 有一个视觉锚点：**居中分节标题**（`> 标题` → 17px、加粗、主题色 `#1a5276`），涨跌幅用红绿色
- **小标题禁止「一、二、三」序号**；LLM 若输出「一、筛选名单」，成稿流水线会转为 `> 筛选名单`（`demote_numbered_section_lines`）
- **品牌头**：每篇顶部 banner + slogan；框体底部不留多余留白（图片与 slogan 条紧贴）
- **正文插图**：banner 下第一节前不再插图；中段图 **max-height 200px**（`WECHAT_MP_FIGURE_MAX_HEIGHT`）
- **插图主题**：全部须与 **A 股 / 科技 / AI / 交易屏 / 财经数据** 相关；禁止风景、泛办公、与生活无关的图（manifest `tags` + `figure_matches_domain` 校验）
- 关键点：**加粗** / 着色；**不用 emoji**（本账号硬约束）
- **禁止**在正文写「评论 N」「阅读 N」——互动数仅用于内部排序

**market 成稿优化（代码自动，`wechat_mp_market_polish.py`）**

| 步骤 | 作用 |
|------|------|
| `reflow_market_structure_section` | 「我们认为 / 值得关注的是 / 向后看」各起一段 |
| `inject_market_opening_lede` | 在 `> 盘面速览` **前**插入 2 句结论（含数字） |
| `split_long_paragraphs` | 超 180 字段在句号处拆段 |
| `align_market_title_mood` | 标题禁「普跌/暴涨」等与盘面数字不符的词 |
| `finalize_market_body` | 以上串联；`build_market_article` 内调用 |

**彩色开篇（HTML，`opening_lede_paragraph_style`）**

| 稿 | 彩色段位置 |
|----|------------|
| `market` | `> 盘面速览` 之前的 2 句 |
| `top5` | `> 筛选名单` 下第一段 |
| `dragons` | `> 情绪与盘面` 下第一段 |

样式：17px、加粗、居中、`#1a5276`。详见 [evening-trilogy-templates.md](evening-trilogy-templates.md)。

**晚间稿完读钩子（代码，默认开）**

共享：`wechat_mp_read_hooks.py`；总开关 `WECHAT_MP_READ_HOOKS=1`；分稿型可覆盖如 `WECHAT_MP_SECTOR_READ_HOOKS=0`。

| 稿型 | 模块 | 钩子 |
|------|------|------|
| `top5` | `wechat_mp_top5_polish.py` | 名单路径预告 → 逐只「·」轻过渡 → 组合引向待验证 → 末段若则 |
| `sector` | `wechat_mp_sector_polish.py` | 五节路径 + 节间「·」 + 「向后看」末段悬念 |
| `dragons` | `wechat_mp_dragons_polish.py` | 情绪路径 + 节间/龙头间「·」 + 明日纪律末段 |
| `market` | `wechat_mp_market_polish.py` | 盘面→外围→结构路径 + 节间「·」 + 结构判断末段 |
| `news` | `wechat_mp_news_polish.py` | 十条递进导语 + 条间「·」 |

段间句**不用**「往下看」「→」；用「·」+ 对比/验证口吻，像研究员手记而非导流。

文末互动问句仍由 `polish_for_traffic` 追加。

**返佣 CPS**：插在正文约 **2/3** 处（`inject_cpsad_at_body_ratio`），勿回退到「结构判断 / 待验证事项」分节后。

**行情稿建议结构**

| 稿 | 分块 |
|----|------|
| 宏观 `market` | **彩色结论 2 句** → `> 盘面速览` → `> 外围与资金` → `> 结构判断` |
| 要闻 `news` | `> 要闻精选` → 10 条（标题 **18px** + **摘要 230–250 字** + **AI 点评 120–220 字**；行距 1.78） |
| Top5 | `> 筛选名单` → `> 个股拆解` → `> 组合特征` → `> 待验证事项` |
| 龙头 | `> 情绪与盘面` → `> 龙头拆解` → `> 主线与梯队` → `> 明日计划与纪律` |

节标题写法：代码里用 `mp_section_header("盘面速览")` 或 LLM 输出后 `ensure_blockquote_sections` 补 `> ` 前缀。

**工作区稿**：`> 它是什么` / `> 里面分几块` … 静态维护，**不调行情 LLM**。

**技术稿文末（workspace / temp）**

- 正文与 `*_article.py` 里**不要**写「不构成投资建议」「市场有风险」
- 推稿时由 `disclaimer_for_kind()` 自动追加一句：`本文为作者个人工程笔记，仅供学习交流。`
- 返佣商品（CPS）插在正文约 **2/3** 处（与行情稿同一 `inject_cpsad_at_body_ratio` 机制）

**技术稿禁止 Agent / 运维话术（读者向）**

- **品牌头 slogan**（`wechat_mp_masthead.KIND_SLOGANS`）：写给读者，禁止「临稿栏」「五槽」「覆写」等编排用语
- **正文禁止**：给 Agent 用、链接给用户、转给用户点、不碰日更、临时槽、后台跑命令把链接……
- **可写**：本机配置、浏览器授权、Cursor Skill、bot/user 分工（产品能力描述）
- 兜底：`sanitize_tech_mp_meta()`（`build_article` → `finalize_public_body_text(..., kind=)`）

## 摘要 `digest`（订阅号列表第二行）

- 上限 **128 字**（代码截断）
- 写清：**谁该读 + 看完得到什么**（相当于列表页 SEO）
- 勿与标题完全重复；可含「工具工作区」「收盘」「草稿」等领域词
- **自动 SEO**：`wechat_mp_seo.enrich_digest` 按稿型补核心词（如 market→`A股`+`收盘复盘`）；词表见 `stock-ai/docs/wechat_mp_seo_topics.md`

## 去 AI 味（合并 [Qson8/wechat-writing-skill](https://github.com/Qson8/wechat-writing-skill) + 本仓库实践）

| AI 味 | 改法 |
|-------|------|
| 首先/其次/最后 连用 | 改用「不过」「说到」「其实」 |
| 综上所述、值得注意的是 | 删掉或改成一句结论 |
| 对称金句「既要…也要…」 | 改成一次具体踩坑 |
| 程度词堆砌（非常、极其） | 换数字或场景 |
| 说明书式「一、二、三」排比 | 短段 + 引用块标题；工作区用 `>` |
| 赋能 / 一站式 / 链路 / 体例 | 禁用（见 `test_wechat_mp_workspace_article._AI_PHRASES`） |
| 文末「欢迎留言」「点赞让我知道」 | 本账号技术稿可省略；行情稿一句免责即可 |
| 文末免责声明 | **行情四槽**（market/news/top5/dragons）：投资日记免责；**技术稿**（workspace/temp）：**禁止**投资免责，仅用工程笔记一句（见下） |
| 无数字、无工具名、无时间线 | 补：一刻钟、四坑位、MySQL、微信推送等 |

**工作区稿额外**：勿 `humanize_mp_text`；勿 LLM 重写静态正文。

### 要闻 AI 点评（走心，禁模板）

- **像盘中微信**：说清会动谁、为什么、下一交易日盯什么（竞价/龙头/首小时量）
- **可点名**细分板块或产业链，**禁止**买卖建议
- **禁套话**（代码 `_AI_COMMENT_BANNED`）：情绪定价、结构分化、主题脉冲、向后看建议跟踪、若与当前主线共振…
- **每条写法要有变化**，禁止「第1句板块、第2句机制、第3句验证」填空
- 字数 **120–220**，密度优先，**不**用通用垫句凑满 200 字

### Top5 个股拆解（客观，非荐股）

- **逻辑归属**：写题材与触发信号，不写「建议关注/买入」
- **量价结构**：收盘、成交额、换手、主力流向——用数字
- **技术位置**：均线、压力、涨停价
- **待核实**：次日或缺什么数据，不写操作建议
- **禁**：综合得分、排名分数、持仓计划（`sanitize_top5_analysis_text`）

### 龙头稿（游资复盘腔）

- **地位**：连板高度、断板/晋级、与主线关系
- **博弈**：接力/兑现/分歧，像收盘笔记
- **全文不得出现**：`6/7`、`7/7`、`X/7`、`系统筛选用分`、`龙头确认`、`内部认可`
- `checklist_pass` 仅数据库内部字段，不进公众号正文

**自检**：读一遍出声；若像「产品官网」则删形容词、加一句踩坑。

## 与本账号硬约束（覆盖行业通用建议）

| 行业常见建议 | 本仓库 |
|--------------|--------|
| 文末强互动引流 | 不强制；行情稿投资免责；技术稿仅工程说明 |
| 多用 emoji 做重点 | **禁止** emoji |
| 标题越震惊越好 | 吸睛但 **不标题党**；禁「震惊」「重磅」 |
| AI 一键出稿 | 行情 LLM + **humanize**；工作区 **手写** |
| 文末放外链二维码 | 敏感/翻墙工具不写；**默认无**「阅读原文」（`WECHAT_MP_READ_SOURCE_URL=0`） |
| 个人持仓增强信任 | **禁止** 持仓、执行卡、「我」的仓位 |

公开稿红线全文：`stock-ai/scripts/tools/wechat_mp_public.py` → `PUBLIC_MP_WRITER_RULE`。

## 冲阅读量清单（自动 + 后台）

**发布前五步（人工，`wechat_mp_publish_checklist.py`；`--dry-run` 会打印）**

1. **预览**：后台手机预览排版/插图  
2. **标题**：与正文数字一致；无普跌/暴涨等与盘面不符  
3. **开头**：首段 2 句结论在「盘面速览」之前  
4. **原创**：勾选原创，分类财经/科技  
5. **话题**：加 `#` + 可选引导「推荐 ♡」  

**什么文章读的人多（财经垂直）**

| 类型 | 读者动机 | 本账号对应稿 |
|------|----------|--------------|
| 24h 热点 + 对 A 股影响 | 焦虑、要答案 | market / news（快讯融入评论） |
| 结论先行 | 手机扫一眼 | 盘前「开局盯什么」、盘后「结构判断」 |
| 数字 + 结构 | 像复盘笔记 | 涨跌家数、板块、龙头梯队 |
| 名单/梯队 | 易收藏转发 | top5、dragons |
| 深度干货 | 完读高、进推荐池 | workspace / temp（低频冲量） |

**自动检查**（推稿 `--dry-run` 或 `wechat_mp_eval --traffic` 会打印）：

| 项 | 标准 |
|----|------|
| 标题 | ≤32 字；前 15 字有信息；含 `？`/`！`；无标题党 |
| 摘要 | ≤128 字；含稿型 SEO 词（A股 + 盘前/午间/收盘复盘） |
| 开头 | 结论先行，含数字或盘面词，≥35 字 |
| 结构 | ≥2 个 `>` 分节；无超 180 字长段 |
| 完读 | 纯文字约 400–3200 字（≈3 分钟） |
| 垂直词 | 自然出现复盘/结构/龙头/盯盘 等 ≥1 个 |
| 互动 | 文末 1 句具体问句 + **1 句「推荐 ♡」引导**（`append_recommend_hook`，默认开；非「点赞在看」套路） |

## 原创与话题标签（API 做不到的部分）

脚本 `wechat_mp_draft` 写入草稿箱的字段（日更五槽 + `temp` 字段规则一致）：

| 字段 | 当前值 | 说明 |
|------|--------|------|
| `title` / `author` / `digest` / `content` | ✅ 已写 | 标题 ≤32、摘要 ≤128、作者 `WECHAT_MP_AUTHOR` |
| `thumb_media_id` + crop | ✅ 已写 | 各 kind 独立封面 |
| `content_source_url` | 默认**不写**（`WECHAT_MP_READ_SOURCE_URL=1` 且配 URL 才开） | 勿默认链 home-hub 看板 |
| `need_open_comment` | **0**（关评论） | 可 env 改（见 reference） |
| `only_fans_can_comment` | 0 | 全员可评（若开评论） |
| **原创声明** | ❌ **未标记** | 微信 `draft/add` **无** `is_original` 字段；须在后台发布时勾选，或群发时走原创校验 |
| **话题标签 `#`** | ❌ **未加** | 平台规定：**仅原创文**可加，最多 5 个；无草稿 API，发布后后台 `#` 入口手动加 |

**人工发布顺序建议**（mp.weixin.qq.com）：

1. 打开草稿 → 预览排版/插图  
2. 点「发布」→ **勾选原创**（选分类，如财经/科技）  
3. 发布成功后 → 文章右侧 **`#`** 加话题（如 `A股` `收盘复盘` `龙头` 等，按稿型选 3–5 个）  
4. 可选：加入合集（同样无稳定 draft API，后台操作）

若需 API 自动发布（`WECHAT_MP_AUTO_PUBLISH=1` / `freepublish/submit`），原创仍可能在发布环节失败（`publish_status=2` 原创失败），须后台补声明或改稿后重发。

## 流量主优化（财经垂直号）

本账号已是 **金融 + 科技** 垂直（eCPM 通常高于娱乐号）。代码 `wechat_mp_monetization.py` 在推草稿时自动做：

| 策略 | 实现 | 人工补充 |
|------|------|----------|
| 垂直领域 | 正文/摘要自然出现：复盘、结构、避坑、盯盘、攻略、量化、自动化 | 发布时勾 **原创 + 财经/科技** 分类 |
| 完读率 | LLM prompt 要求「结论先行 + 末段悬念」 | 流量主开通后 **底部/文中广告由微信自动插入**，正文无需留 `· · ·` |
| 高价值词 | 禁堆砌；按稿型植入财经/科技词（非「神器」 spam） | 数码类词仅工作区稿多用 |
| 互动 | 文末 1 句问句 + 默认 **打开留言**（`WECHAT_MP_NEED_OPEN_COMMENT=1`） | 正文文末一行 `#A股 #…`；可选引导 **推荐 ♡** |

**广告说明**：开通流量主后，发布时微信会在 **底部**（及符合条件时 **文中**）自动插广告，与草稿正文无关；**不要在正文留人工广告位标记**。

**环境变量**

```bash
WECHAT_MP_MONETIZE=1              # 0=关闭流量优化后处理
WECHAT_MP_ENGAGEMENT_HOOK=1       # 0=不加文末问句
WECHAT_MP_NEED_OPEN_COMMENT=1     # 留言（促互动）；0=关
WECHAT_MP_ONLY_FANS_COMMENT=0     # 1=仅粉丝可留言
# WECHAT_MP_AD_CHECKPOINT=1       # 极少用：正文插 · · ·（默认关，一般不需要）
```

**红线不变**：互动问句禁荐股、禁「点赞在看」套路；文末仍有免责声明。

## 自动评分（`wechat_mp_eval`）

```bash
cd stock-ai
uv run python -m scripts.tools.wechat_mp_eval --kind all
uv run python -m scripts.tools.wechat_mp_eval --kind workspace --min-score 70 --max-ai-flavor 40
```

| 维度 | 满分 | 要点 |
|------|------|------|
| 标题 | 15 | ≤32 字、吸睛标点、无标题党禁词 |
| 开头 | 15 | 场景/结果、有数字或名词 |
| 正文 | 25 | 分块标题、短段、具体名词 |
| 去 AI | 30 | 禁词/连接词/程度词（另报 AI 味 0–100） |
| 结尾 | 10 | 合规句、少模板互动 |

**判定**：无合规失败 + 总分 ≥75 + AI 味 ≤40 → `可进草稿箱`；否则按终端建议改稿。

**阅读量清单**：`wechat_mp_eval --traffic` 或 `wechat_mp_draft --dry-run`（见上节「冲阅读量清单」）。

CI/脚本可加：`--min-score 70 --max-ai-flavor 45` 失败时 exit 1。
