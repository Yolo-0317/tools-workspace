# DeepSeek 浏览器写稿与 Agent 推草稿设计

## 目标

为公众号建立一条可重复、可审计、失败关闭的浏览器写稿流程，覆盖：

- 热点深评 `hotspot`。
- 典籍节目与一般文学内容共用的新独立稿型 `literary`。

DeepSeek 网页负责标题和正文初稿；Agent 负责选题研究、提示词、事实核验、编辑、高亮、公开来源配图、质量门禁和微信公众号草稿写入。流程不得在 DeepSeek 失败时回退 Codex、DeepSeek API、其他模型或模板兜底。

## 用户交互

流程固定包含两次人工确认：

1. Agent 完成选题、资料研究和提示词，向用户展示后等待确认。
2. 用户确认后，Agent 通过 OpenCLI 绑定当前 Chrome 标签中的固定 DeepSeek 会话，发送提示词并提取本轮新回复。
3. Agent 核验事实、标题、引用和数字，完成排版、高亮及配图。
4. Agent 向用户展示标题、摘要、正文概况、来源和配图情况，等待第二次确认。
5. 用户第二次确认后，Agent 才可调用微信公众号草稿接口。

任何入口都不得跳过两次确认。确认状态只对当前稿件有效，不跨稿件复用。

## 固定 DeepSeek 会话

第一版中，热点深评和文学类共用以下固定会话：

```text
https://chat.deepseek.com/a/chat/s/f0cc031d-233f-4648-807d-354275738e61
```

OpenCLI 使用 `bind` 绑定用户当前前台 Chrome 标签，禁止为了写稿另开 DeepSeek 自动化窗口。绑定后必须校验：

- `location.href` 与固定会话 URL 的会话 ID 一致。
- 页面存在可用的消息输入框。
- 页面处于已登录状态。
- 页面没有正在生成另一条回复。

任务结束后执行 `unbind`，不得关闭用户 Chrome 标签。

## 登录与页面错误

以下情况统一失败关闭，不发送、不生成草稿、不调用微信 API：

- OpenCLI 扩展未连接。
- 当前标签不是固定 DeepSeek 会话。
- DeepSeek 已退出登录。
- 找不到输入框或发送按钮。
- 页面已有生成任务未结束。
- 提示词发送失败或刷新后未持久化。
- 回复超时、为空或无法确认属于本轮请求。

退出登录时，用户可见提示固定表达为：

```text
DeepSeek 当前未登录。请在 Chrome 登录 DeepSeek，打开固定的“公众号爆文秘诀”会话并保持为当前标签，然后回复“已登录”。
```

不得自动读取、输出或保存登录 Cookie、账号凭据和会话密钥。

## 浏览器写稿编排器

新增一个职责单一的浏览器编排模块，负责：

1. 校验固定会话与登录状态。
2. 记录发送前的消息边界。
3. 使用 OpenCLI 原生表单输入与点击发送提示词。
4. 等待生成完成。
5. 提取发送后新增的最后一条助手回复。
6. 校验消息已持久化且回复非空。
7. 保存本地交接记录。
8. 解除标签绑定。

模块不负责文章研究、改写、配图、HTML 渲染或微信 API。

回复归属以“发送前助手消息数量 + 本次用户提示词指纹 + 发送时间”共同判断。不得通过页面全文末尾文本直接猜测回复，避免误取历史长文。

## 本地交接记录

每次写稿在 `output/` 下保存结构化记录，至少包含：

- `workflow_id`
- `kind`: `hotspot` 或 `literary`
- `topic`
- `prompt`
- `prompt_sha256`
- `conversation_id`
- `sent_at`
- `raw_response`
- `response_received_at`
- `status`
- `first_confirmation_at`
- `second_confirmation_at`

记录文件属于本地运行产物，不提交 Git。状态按以下顺序单向推进：

```text
researched -> prompt_confirmed -> response_received -> edited -> push_confirmed -> drafted
```

异常进入 `blocked`，并记录不含凭据的错误码。`drafted` 之前不得更新公众号槽位。

## 热点深评路线

热点选题、研究和最终质量规则继续使用现有热点深评规范。DeepSeek 原始回复必须经过 Agent 的以下处理：

- 对照至少三个不同来源域核验事实。
- 核验人物、地点、时间、数字、裁判或政策结论。
- 删除无法证实的故事、引语和细节；不得把合成个案冒充真实采访。
- 明确原创核心判断，保留可站队、可反驳的讨论钉子。
- 检查标题吸引力但禁止虚假悬念。
- 加入两至三处高亮，确保控制符最终转换为富文本而不裸露。
- 优先使用可追溯的公开报道图片并记录来源。
- 通过现有原创、合规、长度、来源、图片和富文本门禁。

热点稿继续写入用户选择的现有热点槽位，不改变热点槽位覆盖规则。

## 文学与典籍路线

新增 `literary` 稿型和独立 `literary` 槽位。典籍节目与一般文学内容共用该槽位，不覆盖 `tv_review`、影视稿或热点稿。

文学稿提示词和编辑门禁要求：

- 第一段优先使用作品场面、原文细节或节目动作，不使用百科式时间导语。
- 叙述者保持隐形，不虚构“我看哭了”“昨晚刚看”等经历。
- 原文、节目台词、人物经历和版本信息必须核验。
- 直接引文必须控制长度并标明作品或公开来源。
- 不把文学常识、篇数、字数、时代和人物关系混写。
- 正文以一个明确钉子展开，不写作品梗概堆砌或空泛升华。
- 加入两至三处高亮，使用独立的文学稿末关注文案。
- 配图优先使用节目官方、出版机构、博物馆或权威报道公开页面；无法确认授权与出处的搬运图不得自动使用。

`literary` 使用独立的结构化草稿类型、正文缓存和槽位键，并复用现有 HTML 渲染、图片上传、合规检查和草稿 upsert 能力。

## 提示词构成

Agent 在第一次确认前生成的提示词由以下部分组成：

1. 稿型与目标读者。
2. 一句话文章钉子。
3. 已核验事实包及来源摘要。
4. 标题边界与字数要求。
5. 开篇、正文和结尾要求。
6. 禁止虚构、禁止假采访、禁止元叙述等约束。
7. 输出格式：第一行标题，空一行后输出纯段落正文，不附解释。

不得把账号内部评分、推荐算法猜测、Cookie、微信 token 或本地路径发送给 DeepSeek。

## 第二次确认内容

Agent 在推草稿前向用户展示：

- 最终标题与摘要。
- 正文字数和核心观点。
- 主要事实改动与删除项。
- 来源数量和来源域。
- 封面及正文配图数量、来源类型。
- 原创、合规、富文本和槽位检查结果。

用户明确确认后才能推进到 `push_confirmed` 并调用微信草稿接口。

## 命令与边界

新增统一入口，按 `--kind hotspot|literary` 工作。入口负责创建或恢复本地 workflow，不直接替代现有 `wechat_mp_draft` 和文学稿 repush 模块。

一期只实现单篇、前台绑定和同步等待，不实现：

- 后台定时写稿。
- 多篇并发。
- 自动登录。
- Cookie 提取。
- DeepSeek API 回退。
- 自动发表公众号正文。
- 为热点和文学分别维护两个 DeepSeek 会话。

## 测试与验收

自动测试至少覆盖：

- 固定会话 URL 判断。
- 登录页、无输入框和错误标签的失败提示。
- 发送前后消息边界与新回复提取。
- 历史回复不得被当成本轮成稿。
- 超时、空回复和未持久化消息进入 `blocked`。
- 两次确认不可跳过或跨稿复用。
- DeepSeek 失败时不调用其他模型和微信 API。
- `hotspot` 与 `literary` 槽位互不覆盖。
- `literary` 不覆盖 `tv_review`。
- 富文本控制符最终不在 HTML 中裸露。

人工验收使用当前 Chrome 固定会话完成一次热点测试和一次文学测试；两次都须看到 DeepSeek 新回复，第二次确认后只更新各自目标槽位，并在结束后保持 Chrome 标签打开。
