# “一字三诗”短视频生产 SOP

## 1. 适用范围

本流程用于《栀夏飞花令》抖音短视频栏目“一字三诗”。目标是用一套半固定模板，持续生产约20秒、9:16竖屏的国风诗词动画。

已跑通样片：EP01“花”。当前推荐成片为：

`exports/ep01-flower-subtitled-v02-fullscreen.mp4`

## 2. 成片结构

| 时间 | 内容 | 是否复用 |
| --- | --- | --- |
| 0.00—2.70秒 | 栀夏与阿砚同框片头、阿砚报题 | 画面半固定，题字与配音按主题替换 |
| 2.70—6.00秒 | 第一首诗的全屏诗境 | 每集重新生成 |
| 6.00—10.00秒 | 第二首诗的全屏诗境 | 每集重新生成 |
| 10.00—15.23秒 | 第三首诗的全屏诗境 | 每集重新生成 |
| 15.23—17.75秒 | 第三段余韵与过渡 | 主内容生成时一并提供 |
| 17.75—约20.20秒 | 同框片尾、阿砚邀请观众接句 | 画面半固定，配音可复用或微调 |

原则：片头与片尾负责角色识别，15秒主内容负责诗境。主内容必须覆盖整个画面，不再使用“书中微缩景观”。

## 3. 每集策划

### 3.1 选择主题字

每集只选择一个字，例如“花、月、风、雨、春、酒”。围绕同一个字选择三句辨识度高、画面差异明显的诗。

### 3.2 诗句排序

三句诗按以下原则排列：

1. 第一幕能快速建立环境。
2. 第二幕与第一幕在昼夜、色彩或空间上形成变化。
3. 第三幕具有最强的景深、情绪或视觉收束能力。

### 3.3 先确定时间轴

先生成配音并记录真实时长，再确定画面切换点。不要只按提示词预设的秒数直接拼接，否则容易出现“声音已经念到下一句，画面仍停在上一幕”。

EP01使用的字幕与配音时间以 `episodes/ep01/subtitles-flower.json` 为准。

## 4. 角色与声音

### 4.1 角色参考图

角色外观以 `docs/character-bible.md` 和 `assets/characters/` 中的定稿图为准。片头、片尾需要上传角色参考图；纯诗境主内容不强制出现角色。

### 4.2 固定音色

| 角色 | 豆包TTS音色 | 用途 |
| --- | --- | --- |
| 栀夏 | `ICL_uranus_zh_female_tianmeijiaoqiao_tob` | 第一、第三句等较柔和诗句 |
| 阿砚 | `ICL_uranus_zh_female_jiaxiaozi_tob` | 报题、第二句、片尾互动 |

角色到音色的固定映射保存在 `config/voices.json`。自动化固定生成24kHz、单声道、64kbps MP3，每段台词单独保存到：

`assets/audio/<episode-theme>/`

自动命名：

```text
01-ayan-opening.mp3
02-zhixia-poem-01.mp3
03-ayan-poem-02.mp3
04-zhixia-poem-03.mp3
05-ayan-outro.mp3
```

### 4.3 创建配音清单

每个新剧集创建 `episodes/<episode>/voice-lines.json`。第一版必须恰好包含五句；`role` 只能使用 `ayan` 或 `zhixia`：

```json
{
  "episode": "ep04",
  "theme": "雨",
  "theme_slug": "rain",
  "audio_slug": "ep04-rain",
  "lines": [
    {"id": "01-opening", "role": "ayan", "text": "今日飞花令，雨。", "start_ms": 0},
    {"id": "02-poem-01", "role": "zhixia", "text": "第一句诗。", "start_ms": 2500},
    {"id": "03-poem-02", "role": "ayan", "text": "第二句诗。"},
    {"id": "04-poem-03", "role": "zhixia", "text": "第三句诗。", "gap_before_ms": 150},
    {"id": "05-outro", "role": "ayan", "text": "第四句，你来接。", "gap_before_ms": 150}
  ]
}
```

`start_ms` 是绝对开始时间；`gap_before_ms` 是相对上一句结束时间的空隙，同一句不能同时填写两者。没有填写时默认紧接上一句。示例中的“第一句诗”等占位文本必须换成已确认文案后才能生成。

### 4.4 先预览，再生成

项目 `.env` 只需配置一次，且不能提交：

```dotenv
VOLCENGINE_SPEECH_API_KEY=
```

默认命令只展示待生成句数、角色分布、字符数、输出目录和预计 API 调用次数。它不读取 API Key、不访问网络、不创建音频：

```bash
python3 scripts/generate_episode_audio.py --episode ep04
```

确认预览后再运行：

```bash
python3 scripts/generate_episode_audio.py --episode ep04 --generate
```

程序会再次显示预计调用次数。只有手工输入完整的 `GENERATE ep04` 才开始收费调用；大小写、空格或剧集号不一致都会取消。普通测试和默认预览都不会调用真实 API。

中途失败后先重新预览。已经生成且元数据一致的台词会自动跳过；只恢复一句可运行：

```bash
python3 scripts/generate_episode_audio.py --episode ep04 --line 03-poem-02 --generate
```

### 4.5 输出、版本与人工检查

生成成功后，音频目录包含五个 MP3 和 `audio-metadata.json`。元数据记录台词、角色、音色、资源 ID、版本、真实时长和请求 ID。五句全部就绪后，程序才写入 `episodes/<episode>/subtitles-<theme_slug>.json`；字幕时间来自实际 MP3 时长。

如果台词或音色发生变化，必须把对应清单项的 `revision` 从1提高到2。新文件会追加 `-v02`，旧文件不会被覆盖。已有文件没有可信元数据时程序也会停止，需先人工确认归属。

自动字幕解决的是音频时间轴，不代表 Seedance 的三个诗境会按同一时刻换景。仍需人工抽帧确认真实换景点，再按第6节重新对时。TTS生成后还应把最终采用的资产登记到 `assets/inventory.csv`。

EP01至EP03是已完成的历史集，现有音频、字幕和成片保持原样；不要用新入口补生成或覆盖它们。

## 5. Seedance 视频生成

### 5.1 推荐设置

- 模型：Seedance 2.0
- 比例：9:16
- 分辨率：720P
- 主内容时长：15秒
- 生成数量：先1条
- 声音：允许生成环境声，但正式成片以本地配音为主

任何实际付费生成前，先确认本次模型、时长、分辨率、条数和预计费用。

### 5.2 主内容提示词结构

主内容提示词按以下顺序编写：

1. 总体画风和色彩。
2. 明确“全屏环境，不是书中插画，不是画中画”。
3. 按时间写三段诗境。
4. 写三段之间的自然转场媒介，如花瓣、薄雾、水墨或水波。
5. 对容易混淆的物种、道具和动作写可观察的形态特征。
6. 最后写负面约束。

不要只写“桂花”。应写成：

> 常绿桂花树，浓绿椭圆形有光泽的叶片，淡金黄色、米粒大小、四瓣的小花成簇生长在叶腋；禁止裸枝、梅树、粉白色大朵五瓣花、樱花和桃花。

这类描述比单纯重复“不要梅花”更稳定。

### 5.3 构图要求

- 三段诗境都要占满9:16画面。
- 不出现书本、书页、桌面、相框或卷轴边框。
- 不在Seedance内生成字幕或汉字。
- 人物只在必要时作为远景点缀，不做正脸大特写。
- 避免快速剪辑、镜头抖动、强闪光和花瓣风暴。

### 5.4 下载与归档

下载后先检查：

- 720×1280。
- 时长约15.04秒。
- 24fps或项目统一帧率。
- 是否含音轨。
- 三段场景是否都为全屏。
- 物种、人物、道具是否正确。

保留原始下载文件，归档到：

`assets/generated-video/<episode-theme>/content-fullscreen-vNN.mp4`

不要覆盖旧版，版本号递增。

## 6. 主内容重新对时

Seedance按照提示词生成的场景切换点，通常不会与TTS完全一致。应先抽取多个时间点画面，找到真实切换位置，再分段调整速度。

EP01新版主内容的处理方式：

| 原素材区间 | 目标成片区间 | 处理 |
| --- | --- | --- |
| 0.0—5.5秒 | 2.70—6.00秒 | 压缩至3.30秒，对齐第一句 |
| 5.5—9.5秒 | 6.00—10.00秒 | 保持4.00秒，对齐第二句 |
| 9.5—14.0秒 | 10.00—15.23秒 | 延长至5.23秒，对齐第三句 |
| 14.0—15.04秒 | 15.23—17.75秒 | 延长为余韵和片尾前过渡 |

重新对时后的文件单独保存为：

`assets/generated-video/<episode-theme>/content-fullscreen-vNN-retimed.mp4`

## 7. 本地声音与画面合成

本地后期统一使用FFmpeg：

1. 片头、重新对时的主内容、片尾合成。
2. 转场使用约0.3—0.4秒的淡化叠加。
3. 五段TTS放置到固定时间轴。
4. 统一音量，保留必要环境声。
5. 暂无固定授权音乐时，不强行加入背景音乐。

无字幕的配音版保存在：

`exports/<episode-theme>-voiced-vNN.mp4`

## 8. 竖排字幕规范

当前确认样式：

- 位置：左上角安全区。
- 排列：从上到下，列从右向左。
- 字体：系统“行楷-简”，内部字体名 `STXingkaiSC-Light`。
- 字号：720×1280画布使用62px。
- 主字：纯白实色。
- 主题字：亮朱红。
- 背景：无底色、无色块。
- 辅助：轻微深色细描边和阴影，防止亮背景吃字。
- 标点：画面中省略，保持竖排干净；配音仍按正常语句停顿。
- 动效：每条约0.12秒淡入和0.12秒淡出。

字幕文案与时间保存在：

`episodes/<episode>/subtitles-<theme>.json`

字幕图片由以下脚本生成：

`scripts/render_subtitle_cards.swift`

字幕成片由以下脚本生成：

`scripts/build_subtitled_ep01_flower.sh`

脚本支持通过 `INPUT_VIDEO` 和 `OUTPUT_VIDEO` 指定新版输入输出，默认仍保留EP01 v01路径。

## 9. 质量检查

### 9.1 必查时间点

至少抽查以下画面：

1. 片头报题中段。
2. 第一首诗配音中段。
3. 第二首诗配音中段。
4. 第三首诗配音中段。
5. 第三幕余韵。
6. 片尾互动中段。

### 9.2 验收清单

- [ ] 画幅为720×1280或1080×1920，比例9:16。
- [ ] 视频和AAC音轨均可完整解码。
- [ ] 片头、三段诗境、片尾顺序正确。
- [ ] 每句配音与对应诗境同步。
- [ ] 主内容没有退回书中微缩景观。
- [ ] 主题物种和关键道具没有生成错误。
- [ ] 字幕位于左上角，没有贴边或落到底部。
- [ ] 白字清晰不发灰，主题字朱红醒目。
- [ ] 字幕没有背景色，且不遮挡角色脸部。
- [ ] 转场没有明显黑帧、跳帧或硬切。
- [ ] 文件名、版本号和资产清单已更新。

自动检查：

```bash
bash tests/test_subtitle_cards.sh
bash tests/test_subtitled_video.sh exports/<final-video>.mp4
```

## 10. 每集需要替换与可以复用的部分

| 项目 | 每集替换 | 可以复用 |
| --- | --- | --- |
| 主题字与三句诗 | 是 | 选题规则 |
| 15秒全屏诗境 | 是 | 提示词结构、负面约束结构 |
| 报题和诗句TTS | 是 | 栀夏、阿砚固定音色 |
| 片头片尾画面 | 视效果微调 | 当前同框模板 |
| 字幕JSON | 是 | 字体、字号、位置、颜色、渲染脚本 |
| 后期合成 | 只改输入和时间 | FFmpeg流程、转场、编码参数 |
| 质量检查 | 否 | 抽帧点和验收清单 |

## 11. EP01经验结论

1. “书中展开诗境”适合作为短暂转场，不适合作为15秒主内容的持续构图。
2. 诗境全屏后，手机观看的识别度和沉浸感明显更好。
3. 画面切换必须跟随实际TTS时间重新对齐，不能完全依赖生成提示词的秒数。
4. 容易混淆的植物必须写形态学特征和禁止项，桂花尤其要限制梅花、桃花和樱花。
5. 字幕先做静态样图、再做单条视频测试、最后批量合成，返工成本最低。
6. 旧素材不覆盖；原始生成、重新对时、配音版和最终字幕版分别留档。
