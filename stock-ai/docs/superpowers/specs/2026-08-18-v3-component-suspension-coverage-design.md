# V3 组件归因停牌覆盖修正设计

## 背景与根因

V3 组件归因首次真实冻结运行生成了 `MARKET_DATA_INCOMPLETE` 空产物。
只读覆盖诊断确认：股票库包含 3,240 个主板序列和 1,200,016 个日线点，
两个所需指数均覆盖完整训练日历，全市场双端点成员数保持在 3,135 至
3,171。失败仅来自一个独立评分样本：起点存在收盘价，第五个市场交易日
没有收盘价，前一市场交易日同样没有、下一市场交易日恢复，符合连续停牌
形成的自然缺价。该样本在 16 个策略与折叠单元中重复出现。

现有父级市场归因允许固定五日个股端点缺失，记录
`FIXED_FIVE_STOCK_ENDPOINT_MISSING` 后排除该行；只有指数端点缺失或全市场
双端点成员不足 1,000 才将父产物标记为 `MARKET_DATA_INCOMPLETE`。组件归因
却把 `attribute_interval` 的所有 `ValueError` 都计作市场覆盖失败并整体中止，
导致子流程比冻结父口径更严格，也让正常停牌阻断全部消融实验。

## 决策

采用“一致排除并显式留痕”方案，不做价格填充：

- 个股在信号日或第五个训练交易日缺少有效收盘价时，从该策略与折叠单元
  的全部基线和消融实验中一致排除；
- 该排除计入 `coverage.excluded_missing_coverage`，不得伪装成零收益，也不得
  静默丢弃；
- 同一单元的 `BASELINE`、`WITHOUT_CONSISTENCY`、`WITHOUT_STRUCTURE` 和
  `WITHOUT_DOWNSIDE` 必须共享排除后的同一人口指纹；
- 指数端点缺失或全市场双端点成员不足 1,000 仍立即返回
  `MARKET_DATA_INCOMPLETE`；
- 无第五个训练交易日的样本继续计入
  `excluded_without_train_horizon`，与停牌缺价分开；
- 不向前填充价格，不读取验证集或测试集，不产生选股晋级、持仓、通知或
  交易权限。

## 数据流与边界

组件构建器先检查个股序列及两个端点。缺少个股端点时，只增加当前单元的
个股缺价计数并继续处理下一行；个股端点完整时，再调用冻结的双基准归因。
双基准归因抛出的 `MarketCoverageIncomplete` 仍视为全局市场覆盖失败。

为避免再次混淆两类缺失，异常处理必须按类型分流：

1. 个股序列或个股端点缺失：可比较排除；
2. 指数端点缺失或市场成员不足：产物级失败；
3. 非法价格、非法计划、分数重构错误：保持现有失败关闭语义，不转成覆盖排除。

组件产物结构与版本保持不变，因为现有覆盖字段已经能表达显式排除，且严格
加载器已经验证候选数等于“有效结果、无训练窗口排除、缺失覆盖排除”之和。
修正只改变构建器对已定义字段和状态的使用方式。

## 测试与验收

测试驱动顺序如下：

1. 新增失败测试：一个评分样本缺少个股第五日端点时，构建结果仍可完成，
   `excluded_missing_coverage` 增加，四个实验共享人口指纹；
2. 新增或强化失败测试：指数端点缺失与市场成员不足仍返回
   `MARKET_DATA_INCOMPLETE`，且不生成部分实验；
3. 实施最小修正并运行组件领域、报告、CLI 测试；
4. 运行完整五日研究回归套件；
5. 使用冻结父链执行真实 CLI，要求状态 `COMPLETE`、16 个基线复现、48 个
   折叠消融可比较、24 个组件标签齐全；
6. 完全相同参数复跑，要求路径、内容身份和文件 SHA-256 一致；
7. 确认产物仅含聚合数据、保持 `NO-TRADE`、未读取验证或测试结果，并被
   Git 忽略且未暂存。

真实验收允许存在显式记录的个股停牌排除；“完整市场覆盖”特指所需指数与
全市场基准覆盖完整，不再要求每只个股在每个自然市场交易日都有成交价。

## 非目标

- 不修改冻结 V3 排名公式或权重；
- 不补写、插值或向前填充停牌价格；
- 不改变父级市场归因产物；
- 不基于本次组件标签调参或创建挑战者；
- 不把研究结果转换为实盘建议。
