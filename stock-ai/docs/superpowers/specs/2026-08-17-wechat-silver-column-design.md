# 公众号银发内容稿型设计

日期：2026-08-17

## 目标与账号结构

在「牛马也智能」中新增面向 50—65 岁读者的银发内容方向。账号形成四个彼此独立、全部手动触发的内容方向：

1. `silver`：退休生活、健康生活、退休金与消费防骗。
2. `hot_business`：热点背后的收入、成本、渠道和利益关系。
3. `hotspot`：社会热点与公共事件深评。
4. `tv_review`：影视评论与话题讨论。

四个方向使用独立稿型和草稿槽位，不在标题中添加栏目名称或固定前缀，不进入任何定时批次。

## 目标读者与表达原则

`silver` 的核心读者是 50—65 岁、临近退休或刚退休、熟悉微信阅读的用户。文章直接写给读者本人，不站在年轻人或子女的角度研究、教育或管理他们。

公开稿必须：

- 使用平等、温和、具体的生活语言。
- 避免“老人不懂”“子女应该管好父母”等居高临下表达。
- 避免用衰老、疾病、孤独或养老金制造恐惧。
- 标题自然表意，不出现“银发栏目”“五十岁以后”等固定前缀。
- 开篇直接进入一个可识别的生活场景或问题，不展示选题、评分、写作步骤等内部元数据。

## 三类内容线

### `relation`：退休生活与家庭关系

覆盖退休后的夫妻相处、成年子女边界、带孙分工、独处、社交、再就业和兴趣生活。文章用具体生活场景展开，不编造专家、案例、调查数字或读者来信。

### `health`：健康与生活方式

覆盖睡眠、饮食、散步、力量训练、体检和日常健康习惯。至少引用三个不同来源域，其中至少一个为国家卫生健康部门、疾控机构、权威医院、医学会或同行评议医学资料。不得诊断疾病、解释个体检验结果、推荐药品、保健品或治疗方案；涉及明显症状时只能建议及时就医。

### `money`：退休金、消费与防骗

覆盖养老金安排、旅游消费、直播购物、免费体验、保健品营销、电信诈骗和金融骗局。至少引用三个不同来源域，其中至少一个为人社、公安、金融监管、市场监管、法院或其他权威机构。不得提供个性化投资建议、收益判断或具体理财产品推荐。

## 选题机制

银发流程全部由用户手动触发，但触发后可以自动选题：

```bash
uv run python -m scripts.tools.wechat_mp_draft --kind silver --dry-run
uv run python -m scripts.tools.wechat_mp_draft --kind silver --silver-lane health --dry-run
uv run python -m scripts.tools.wechat_mp_draft --kind silver --topic "退休后夫妻为什么更容易吵架" --dry-run
```

不传 `--topic` 时，从仓库内银发常青选题库选择。选题库按三类内容线维护，每个题目包含：题目、读者问题、检索词、场景提示和风险提示。默认在三类之间轮换，并根据本地使用记录避开最近 30 天已经使用的题目；`--silver-lane` 可以限制到指定内容线。

传入 `--topic` 时跳过常青选题选择，但仍执行研究、来源和公开稿门禁。`--silver-lane` 与 `--topic` 可以同时使用，用于明确手动题目的安全规则；未指定内容线时，由写稿器把题目归入三类之一，无法可靠归类则拒绝成稿。

银发内容不自动改写每日热搜。与银发读者有关的热点如果值得写，由用户通过 `--topic` 手动指定；普通热点继续由 `hot_business` 或 `hotspot` 处理。

## 结构化稿件契约

新增 `CodexSilverDraft`，字段如下：

```json
{
  "title": "自然标题，无栏目名前缀",
  "digest": "摘要",
  "body": "完整正文",
  "topic": "检索与文章主题",
  "lane": "relation | health | money",
  "research_urls": ["https://..."],
  "original_thesis": "不少于20字的原创核心判断",
  "reader_problem": "文章解决的一个具体问题",
  "facts": [{"claim": "可验证事实", "source_url": "https://..."}],
  "practical_steps": ["读者可执行但不构成医疗或投资建议的步骤"],
  "cautions": ["适用边界和风险提醒"],
  "rejected_claims": ["未采用且不得进入公开稿的说法"],
  "slot_key": "silver"
}
```

统一门禁：

- `slot_key` 必须为 `silver`，`lane` 必须是三个合法值之一。
- 正文去空白后为 1600—2600 字，移动端短段落，允许 3—5 个自然小标题。
- 至少三个不同来源域、至少一条有 URL 映射的事实。
- 每条事实的 `source_url` 必须精确存在于 `research_urls`。
- `original_thesis` 不少于 20 字，`reader_problem` 非空。
- `rejected_claims` 不得重新出现在标题、摘要或正文。
- 健康和钱财稿执行各自的权威来源与敏感表达门禁。
- 原创相似度继续复用现有长图文原创检查。

## 写稿结构与阅读体验

文章围绕一个具体读者问题展开：生活场景开篇、问题为什么发生、常见误区、可执行做法、适用边界和一个自然互动问句。正文避免论文式论证和密集术语；健康与钱财稿把事实、推断和建议边界写清楚。

渲染使用适合中长文阅读的较大字号、较高行距、短段落和清晰小标题。免责声明按内容线区分：健康稿明确“公开健康资料整理，不替代医生诊断”；钱财稿明确“不构成投资或具体金融产品建议”；家庭关系稿使用一般信息与交流声明。

## 短剧推广

`silver` 复用现有短剧池、题材安全过滤和评分机制，采用与 `hot_business` 相同的软失败策略：尽量选择一部不违和的短剧；没有安全候选或推广依赖失败时跳过推广，文章照常进入草稿。已插入组件时仍要求只能有一个短剧组件，正式保存并回读通过后才记录使用。

健康危机、死亡、诈骗受害等严肃主题必须触发现有题材冲突门禁，不得为了推广放宽安全规则。

## CLI、槽位与 dry-run

`silver` 加入 `DRAFT_KINDS`，但不得加入 `DAILY_DRAFT_KINDS` 或任何 `SCHEDULE_BATCHES`。CLI 新增 `--silver-lane relation|health|money`，该参数只允许与单篇 `silver` 一起使用；`--topic` 扩展为允许单篇 `silver` 或 `hot_business`。

dry-run 必须关闭微信素材上传和草稿写入，并输出：内容线、选题、来源域数量、事实数量、健康/钱财权威来源门禁结果、短剧选择或跳过原因。正式命令只更新 `silver` 独立槽位。

## 模块边界

- `wechat_mp_silver_topics.py`：常青选题库读取、三类轮换和 30 天去重。
- `wechat_mp_codex_silver.py`：结构化稿件类型、JSON 读取和门禁。
- `wechat_mp_silver_article.py`：研究 prompt、写稿 prompt 和文章构建。
- `wechat_mp_content.py`：注册 `silver`，复用公共渲染壳。
- `wechat_mp_draft.py`：手动参数、dry-run 报告和 `silver` 槽位。
- 展示、SEO、免责声明、阅读量清单和短剧模块仅增加明确的 `silver` 映射。

## 测试与验收

测试驱动覆盖：

- 三类常青选题轮换、指定内容线和 30 天去重。
- 手动题目的内容线归类与失败关闭。
- 结构化字段、正文长度、三个来源域、事实 URL 映射和拒绝说法回写。
- 健康权威来源、医疗建议红线、钱财权威来源和投资建议红线。
- 无固定栏目标题前缀、平等表达和公开稿免责声明。
- `silver` 只存在于手动稿型，不进入任何自动批次。
- dry-run 不上传、不写草稿，并打印质量报告。
- 短剧有合适候选时插入一个，无候选时软跳过。
- 现有 `hot_business`、`hotspot` 和 `tv_review` 行为不回退。

## 非目标

- 不自动发布文章。
- 不新增定时任务。
- 不经营独立银发公众号或更改账号名称。
- 不销售或推荐保健品、药品、保险、理财产品。
- 不建立健康档案、收集读者疾病或财务隐私。
