# 公众号主笔全程负责架构

状态：用户已确认设计并要求落地。范围：公众号完整创作的职责和文件衔接，不自动改写现有文章、上传或推送。

## 已确认的架构

一个主笔负责构思、初稿、处理审稿、补写和定稿；现有四个独立审稿角色只提意见，不改正文。协调者负责委托、取证协助、版本冻结、意见流转及交付验收，不在主笔之外另行统稿。

观点稿由主笔在outline.md内设计实际主张、依据、值得展开的关系、缺口及篇幅；记事稿按本身用途组织，不套观点配额或固定人格。原有基座继续作为表达唯一真源。

正文删改后，主笔重验内容和篇幅。内容未展开则补写，事实不足则补采；不能把“不凑字数”当作明显缩水的完成理由。验收未达本篇约定，退回当前主笔，不换一个代理从零起稿。切换执行者时明确继任主笔、保留当前约定及剩余轮次。

事实错误和必要条件必须解决；文体意见由主笔依据实际文字处理并记录取舍。协调者核对最终版内容承诺、篇幅、来源及文件一致性，不以角色投票代替判断。沿用最多三轮集中修改，补写不重置轮次；到限仍不足则如实标未完成。

## 文件归属

- 基座：通用内容完整性、删改后责任、篇幅与停止条件。
- references/lead-writer.md：新增的公众号主笔职责、权限和交付。
- drafting-loop.md：委托、连续主笔、修订回流、接管和最终验收。
- review.md：独立意见、正文修改归属、复核及轮次。
- delivery.md：本篇篇幅口径和最终文件核对。
- SKILL.md：接入上述入口，不复制共通规则。

验证包括本地链接、规则冲突、正式文章未变，以及独立临时场景中的缩稿返修、事实缺口、轮次到限和局部修改分支。文风改善须留待实际写作验证，不以流程核对代替。
