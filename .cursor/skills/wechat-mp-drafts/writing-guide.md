# 公众号写作法则（行业 + 本仓库）

面向 **工具工作区 / A 股观察类** 日更稿。与通用教程冲突时，以 [SKILL.md](SKILL.md) 中「本账号硬约束」为准。

## 2025 阅读与分发（摘要）

- **推荐权重上升**：完读率、停留、在看/互动影响「看一看」推荐（见 [青瓜传媒流量机制解读](https://www.opp2.com/329724.html)）。
- **跳读习惯**：很多人先看标题 → 滑到底看结尾 → 再扫中间小标题（刘润团队 2025 法则，[腾讯新闻](https://news.qq.com/rain/a/20250801A055SU00)）。
- **搜一搜**：标题、公众号名、摘要含领域词有助搜索；勿堆砌关键词（约 1%–3% 密度即可）。
- **AI 直发风险**：纯 AI 不修改易被识别、限流；本仓库用 **LLM 草稿 + humanize/静态精修 + 人工审**（[比邻 2025 运营](https://eastondev.com/blog/zh/posts/media/20251124-wechat-operation-2025/)）。

## 标题（吸睛但不标题党）

| 类型 | 示例结构 | 本仓库 |
|------|----------|--------|
| 数字+结果 | 「5 只观察标的，明日盯啥？」 | Top5 标题池 |
| 疑问+悬念 | 「情绪退潮怎么玩？」 | 龙头/宏观池 |
| 场景+反差 | 「收盘推送和证书续签，原来在同一套 git 里？」 | 工作区池 |
| 痛点+承诺 | 「脚本越写越散？后来全收进了一个仓库」 | 工作区池 |

**检查（发布前）**

- [ ] 核心信息在前 15 字内（手机列表截断）
- [ ] 长度 ≤ **32 字**（代码 `_clip_wechat_title`；行业常写 15–28 字，我们以平台上限为准）
- [ ] 含 `？` 或 `！` 之一（行情三篇吸睛池；工作区同理）
- [ ] 不虚假夸张（「震惊」「100 倍」）；不塞 git 目录名
- [ ] 与封面、摘要主题一致

## 开头（前 3–5 句定生死）

优先 **具体场景 / 结果**，少用空泛痛点：

- ✅ 「收盘后大约一刻钟，会跑完入库、战报、四条草稿覆写……」
- ❌ 「在当今数字化时代，自动化越来越重要……」

可选用 **SCQA**（情境 → 冲突 → 问题 → 下文答案），工作区/宏观都适用。

行情稿：首段给「今天盘面一句话」或「数据日 + 次日跟踪」；技术稿：给「读者看完能知道什么」。

## 正文结构与排版

**三三原则**（移动端，[xiangyugongzuoliu 方法论](https://xiangyugongzuoliu.com/wechat-article-creation-strategies-core-methodology/)）：

- 每段尽量 **≤3 行**（手机屏）
- 每 **2–3 段** 有一个视觉锚点：本仓库用 **引用块分块标题**（`> 标题` 或 `一、…`），涨跌幅用红绿色
- 关键点：**加粗** / 引用块；**不用 emoji**（本账号硬约束）

**行情三篇建议结构**

| 稿 | 分块 |
|----|------|
| 宏观 | 盘面一览 → 外围与资金 → 要闻精选 → 观点与推演 |
| Top5 | 观察名单 → 个股拆解（每只四行）→ 组合与纪律 → 次日跟踪 |
| 龙头 | 情绪与盘面 → 龙头拆解 → 主线与梯队 → 明日计划与纪律 |

**工作区稿**：`> 它是什么` / `> 里面分几块` … 静态维护，**不调行情 LLM**。

## 摘要 `digest`（订阅号列表第二行）

- 上限 **128 字**（代码截断）
- 写清：**谁该读 + 看完得到什么**（相当于列表页 SEO）
- 勿与标题完全重复；可含「工具工作区」「收盘」「草稿」等领域词

## 去 AI 味（合并 [Qson8/wechat-writing-skill](https://github.com/Qson8/wechat-writing-skill) + 本仓库实践）

| AI 味 | 改法 |
|-------|------|
| 首先/其次/最后 连用 | 改用「不过」「说到」「其实」 |
| 综上所述、值得注意的是 | 删掉或改成一句结论 |
| 对称金句「既要…也要…」 | 改成一次具体踩坑 |
| 程度词堆砌（非常、极其） | 换数字或场景 |
| 说明书式「一、二、三」排比 | 短段 + 引用块标题；工作区用 `>` |
| 赋能 / 一站式 / 链路 / 体例 | 禁用（见 `test_wechat_mp_workspace_article._AI_PHRASES`） |
| 文末「欢迎留言」「点赞让我知道」 | 本账号技术稿可省略；行情稿一句免责即可 |
| 无数字、无工具名、无时间线 | 补：一刻钟、四坑位、MySQL、微信推送等 |

**工作区稿额外**：勿 `humanize_mp_text`；勿 LLM 重写静态正文。

**自检**：读一遍出声；若像「产品官网」则删形容词、加一句踩坑。

## 与本账号硬约束（覆盖行业通用建议）

| 行业常见建议 | 本仓库 |
|--------------|--------|
| 文末强互动引流 | 不强制；行情稿已有免责声明 |
| 多用 emoji 做重点 | **禁止** emoji |
| 标题越震惊越好 | 吸睛但 **不标题党**；禁「震惊」「重磅」 |
| AI 一键出稿 | 行情 LLM + **humanize**；工作区 **手写** |
| 文末放外链二维码 | 敏感/翻墙工具不写；`WECHAT_MP_SOURCE_URL` 可选 |
| 个人持仓增强信任 | **禁止** 持仓、执行卡、「我」的仓位 |

公开稿红线全文：`stock-ai/scripts/tools/wechat_mp_public.py` → `PUBLIC_MP_WRITER_RULE`。

## 自动评分（`wechat_mp_eval`）

```bash
cd stock-ai
uv run python -m scripts.tools.wechat_mp_eval --kind all
uv run python -m scripts.tools.wechat_mp_eval --kind workspace --min-score 70 --max-ai-flavor 40
```

| 维度 | 满分 | 要点 |
|------|------|------|
| 标题 | 15 | ≤32 字、吸睛标点、无标题党禁词 |
| 开头 | 15 | 场景/结果、有数字或名词 |
| 正文 | 25 | 分块标题、短段、具体名词 |
| 去 AI | 30 | 禁词/连接词/程度词（另报 AI 味 0–100） |
| 结尾 | 10 | 合规句、少模板互动 |

**判定**：无合规失败 + 总分 ≥75 + AI 味 ≤40 → `可进草稿箱`；否则按终端建议改稿。

CI/脚本可加：`--min-score 70 --max-ai-flavor 45` 失败时 exit 1。
