# “一字三诗”豆包 TTS 自动化设计

## 1. 目标

为《栀夏飞花令》“一字三诗”栏目建立可恢复、可审计且默认不产生费用的语音合成流程。新一期只需登记主题、五句台词和角色，即可在人工确认后调用豆包语音 V3 API，生成固定角色配音、真实时长元数据和现有字幕渲染器可读取的时间轴。

首版只自动化语音、音频元数据和字幕时间，不接管 Seedance 视频生成，也不尝试自动识别 Seedance 素材的实际换景点。

## 2. 已验证前提

- 项目 `.env` 已使用 `VOLCENGINE_SPEECH_API_KEY` 保存新版豆包语音 API Key；密钥不得写入配置、日志或提交记录。
- 豆包语音 V3 SSE 端点为 `https://openspeech.bytedance.com/api/v3/tts/unidirectional/sse`。
- 栀夏和阿砚均可直接使用 `seed-tts-2.0`，不需要声音复刻接口：
  - 阿砚：`ICL_uranus_zh_female_jiaxiaozi_tob`
  - 栀夏：`ICL_uranus_zh_female_tianmeijiaoqiao_tob`
- 真实探针已确认两个音色均返回 `20000000 OK`，生成的 24kHz 单声道 MP3 可以完整解码。
- 当前两个 ICL 音色返回句子文本，但未返回字级时间戳；首版字幕以逐句时间为准。
- EP01 至 EP03 的现有音频和成片不重新生成、不覆盖，保留为回归样本。

## 3. 方案选择

### 采用：独立配音清单

每集新增结构化配音清单，配音输入、生成状态和字幕输出彼此分离。这样既能服务当前固定五句结构，也能在未来扩展为多人短对白。

### 不采用：扩展字幕 JSON 作为唯一输入

字幕 JSON 是派生产物。把角色、音色、台词输入、生成状态和字幕时间全部写入同一文件，会形成输入与输出互相覆盖的循环。

### 不采用：从 Markdown 提取台词

Markdown 继续用于人读的内容设计，不作为付费 API 的机器输入。依赖文档标题和段落格式提取台词容易误读角色、顺序或标点。

## 4. 文件结构

### 4.1 全局音色配置

新增 `config/voices.json`，集中保存角色与豆包音色的稳定映射：

```json
{
  "ayan": {
    "name": "阿砚",
    "speaker": "ICL_uranus_zh_female_jiaxiaozi_tob",
    "resource_id": "seed-tts-2.0"
  },
  "zhixia": {
    "name": "栀夏",
    "speaker": "ICL_uranus_zh_female_tianmeijiaoqiao_tob",
    "resource_id": "seed-tts-2.0"
  }
}
```

首版统一输出 MP3、24kHz、单声道、64kbps。FFmpeg 成片阶段继续转为现有的 48kHz AAC 音轨。PCM 暂不进入本期范围。

### 4.2 单集配音清单

每集新增 `episodes/<episode>/voice-lines.json`。示例：

```json
{
  "episode": "ep04",
  "theme": "雨",
  "theme_slug": "rain",
  "audio_slug": "ep04-rain",
  "lines": [
    {
      "id": "01-opening",
      "role": "ayan",
      "text": "今日飞花令，雨。",
      "start_ms": 0
    },
    {
      "id": "02-poem-01",
      "role": "zhixia",
      "text": "好雨知时节，当春乃发生。",
      "start_ms": 2500
    },
    {
      "id": "03-poem-02",
      "role": "ayan",
      "text": "空山新雨后，天气晚来秋。"
    },
    {
      "id": "04-poem-03",
      "role": "zhixia",
      "text": "渭城朝雨浥轻尘，客舍青青柳色新。",
      "gap_before_ms": 1800
    },
    {
      "id": "05-outro",
      "role": "ayan",
      "text": "雨停了，诗还没停。第四句，你来接。",
      "gap_before_ms": 150
    }
  ]
}
```

`start_ms` 是绝对时间锚点；没有 `start_ms` 的台词从上一句结束后开始，并叠加可选的 `gap_before_ms`。同一行禁止同时设置 `start_ms` 和 `gap_before_ms`，避免两套起点规则产生歧义。

### 4.3 生成产物

音频输出到 `assets/audio/<audio_slug>/`：

```text
01-ayan-opening.mp3
02-zhixia-poem-01.mp3
03-ayan-poem-02.mp3
04-zhixia-poem-03.mp3
05-ayan-outro.mp3
audio-metadata.json
```

标准音频文件名由台词 ID 和角色共同决定：在 ID 的数字前缀后插入角色键。例如 `02-poem-01` 与 `zhixia` 输出 `02-zhixia-poem-01.mp3`。版本 2 在扩展名前追加 `-v02`。

字幕时间轴输出到 `episodes/<episode>/subtitles-<theme-slug>.json`，继续使用现有字段 `id`、`text`、`start`、`end` 和 `highlight`，无需修改当前 Swift 字幕渲染器的输入契约。

## 5. 生成流程

统一入口为 `scripts/generate_episode_audio.py`。

默认只预览：

```bash
python3 scripts/generate_episode_audio.py --episode ep04
```

显式进入付费生成：

```bash
python3 scripts/generate_episode_audio.py --episode ep04 --generate
```

只补做指定台词：

```bash
python3 scripts/generate_episode_audio.py --episode ep04 --generate --line 03-poem-02
```

执行顺序：

1. 读取并验证全局音色配置、单集配音清单和 API Key 是否存在。
2. 比较目标文件、当前台词摘要、角色、音色和已登记状态。
3. 输出剧集、待生成句数、跳过句数、角色分布、字符数、目标目录和预计 API 调用次数。
4. 没有 `--generate` 时到此结束，不访问豆包接口。
5. 有 `--generate` 时再次要求人工确认；首版不提供跳过确认的无人值守参数。
6. 每句调用一次 V3 SSE 接口，流式接收并解码 Base64 音频块。
7. 先写临时文件，使用 FFmpeg/ffprobe 验证后再原子移动到目标路径。
8. 每句成功后立即更新 `audio-metadata.json`；中途失败时保留已验证成功的句子。
9. 五句全部可用后，根据真实时长和时间规则生成最终字幕 JSON。
10. 输出下一步需要人工确认的 Seedance 换景点和目标诗境时长。

## 6. 元数据与幂等

`audio-metadata.json` 至少记录：

```json
{
  "episode": "ep04",
  "theme": "雨",
  "lines": [
    {
      "id": "02-poem-01",
      "role": "zhixia",
      "speaker": "ICL_uranus_zh_female_tianmeijiaoqiao_tob",
      "resource_id": "seed-tts-2.0",
      "text_sha256": "台词内容摘要",
      "revision": 1,
      "path": "assets/audio/ep04-rain/02-zhixia-poem-01.mp3",
      "duration_ms": 4104,
      "sample_rate": 24000,
      "channels": 1,
      "status": "ready"
    }
  ]
}
```

重复运行时，仅当文件能解码，且台词摘要、角色、音色、资源 ID 和版本全部一致，才允许跳过 API 调用。任何一项不一致都停止并要求新版本，不能把旧音频静默绑定到新台词。

## 7. 版本规则

- 首次生成的 `revision` 默认为 1，沿用标准文件名。
- 已有音频禁止自动覆盖。
- 台词、音色或演绎参数变化时，在对应行显式设置更高的 `revision`。
- `revision: 2` 输出 `02-zhixia-poem-01-v02.mp3`。
- 元数据记录当前启用路径，后续拼接读取元数据，不靠扫描文件名猜测版本。
- 旧版本继续保留，便于比较和回退。

## 8. 字幕时间计算

- 片头默认从 0 秒开始。
- 第一首诗默认由清单显式锚定在 2.5 秒，以对齐现有片头转场。
- 后续台词默认从上一句结束时开始。
- 需要保留无对白诗境时，在下一句设置 `gap_before_ms`。
- 字幕开始时间与音频开始时间相同，结束时间默认等于音频结束时间。
- 主题字自动写入每条字幕的 `highlight`。
- 除非未来的短剧模式显式支持打断，本期拒绝音频或字幕重叠。
- 五句未全部就绪时不输出新的最终字幕文件，避免半成品覆盖可用时间轴。

## 9. 与视频拼接的边界

语音自动化负责给出三段诗境的目标时长，但不判断 Seedance 15 秒素材的真实场景边界。操作顺序保持为：

```text
自动生成配音、元数据和字幕时间
→ 人工确认 Seedance 三段实际换景点
→ FFmpeg 按配音目标时长重定时
→ 自动混音、叠字幕和导出
```

首版不把 EP01、EP02、EP03 的三个专用成片脚本合并为通用脚本；新一期先消费自动生成的音频和字幕，通用拼接器留给后续独立设计。

## 10. 费用与安全门禁

- 默认命令永不调用收费接口。
- `--generate` 后仍需一次交互确认。
- 预览必须列出预计调用次数和合成字符数，不做不可靠的金额承诺。
- 已匹配的成功句子必须跳过，重复运行同一配置时产生零次 API 调用。
- 日志不得输出 API Key、完整请求头或音频 Base64。
- `.env`、生成音频和临时响应继续遵守现有忽略与资产管理规则。
- 单句请求文本限制在豆包短文本安全范围内；“一字三诗”台词默认应远低于 300 个汉字。

## 11. 错误处理与恢复

- 网络中断、限流和服务端临时错误最多自动重试三次，使用递增等待。
- 鉴权失败、音色不存在、资源无权限和额度耗尽立即停止，不做无效重试。
- API 返回成功但音频为空、无法解码或时长异常，按失败处理。
- 某句失败不删除其他已验证音频；再次运行只处理缺失、失败或指定重试的台词。
- 元数据使用原子写入，防止中断留下损坏 JSON。
- 临时 SSE 响应只用于诊断，不进入版本库；错误日志只保留状态码、请求 ID 和不含凭据的消息。

## 12. 验证策略

### 12.1 不收费的自动测试

使用固定的模拟 SSE 响应覆盖：

- 多个 Base64 音频块按顺序解码。
- 成功结束状态和服务端错误状态。
- 已有一致音频的零调用跳过。
- 台词、音色或版本变化时拒绝复用。
- 中途失败后的断点续做。
- `start_ms`、`gap_before_ms`、真实时长和字幕起止计算。
- 时间倒序、字幕重叠、重复 ID、未知角色和空台词的拒绝逻辑。
- 日志不泄露密钥或 Base64 数据。

### 12.2 人工触发的真实探针

真实接口探针不进入普通测试命令。仅在人工明确同意少量字符计费后，合成一句短台词以确认密钥、资源和音色授权。

### 12.3 生成产物验证

- MP3 可完整解码，采样率为 24kHz，单声道，时长处于合理范围。
- 字幕开始时间递增且无意外重叠。
- 透明字幕卡继续位于左上角安全区，白字与主题字朱红样式不变。
- 最终视频继续通过现有画幅、编码、音轨、总时长和完整解码检查。
- 发布前必须人工试听全部五句，检查诗句断句、重音、情绪和角色辨识度。

## 13. 完成标准

- 新一期只需填写主题、五句台词、角色和必要留白。
- 默认预览不会产生费用；确认后一次生成五段固定角色音频。
- 自动生成真实时长元数据和兼容现有渲染器的字幕 JSON。
- 中途失败可继续，不重复调用已经成功且配置一致的句子。
- 重复运行同一配置产生零次 API 调用。
- 生成结果可用于现有 FFmpeg 成片流程，且 EP01 至 EP03 不受影响。
- 密钥不出现在配置、日志、产物或提交中。

## 14. 非目标

- 不自动调用 Seedance 或承担视频生成费用。
- 不自动识别 Seedance 素材换景点。
- 不在本期引入逐字卡拉 OK 字幕或强制获取字级时间戳。
- 不重制 EP01 至 EP03。
- 不自动发布抖音作品。
- 不为未来多人短剧提前实现打断、叠音、口型或多轨声场。
