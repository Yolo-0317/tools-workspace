# 中文文章逐句agent复核

脚本：[chinese_sentence_review.py](../../scripts/chinese_sentence_review.py)。只用Python标准库；自动复核另需本机已安装、登录的Codex CLI，沿用其配置模型。

程序负责枚举原文、保存版本和检查覆盖；agent负责语法、口吻和上下文判断。每个编号必须分别有三项结论及理由，不能只交“全文通过”。没有问题可以保留原句，不要求每句重写。

## 准备审核包

在工作区根目录执行，替换文章和输出目录：

```bash
python3 scripts/chinese_sentence_review.py prepare article.md \
  --out /tmp/article-sentence-review \
  --reader '上海六年级新生家长' \
  --style '聊天口吻，讲清真实家庭经历，保留来源归属' \
  --batch-size 6
```

输出目录必须为空，避免覆盖已有审核。文章按字节留快照，句子候选保留原文字符区间、所属段落、前后段及全文。主标题、短段、列表项、代码和独立图片链接也登记；后两者不是普通句子，agent不能据此改代码或假装看过图片。

切分保护小数、URL、句末角标、引号和省略号。它是中文文章的机械候选切分，不是中文句法解析器；引语或特殊排版的边界不合适时，由agent结合全文指出。程序另检查全部非空白字符是否被覆盖，不能漏掉没有句号的最后一段。字符偏移基于UTF-8解码文本，开头BOM不计入文字偏移。

输入为UTF-8纯文本或Markdown，不是PDF、图片OCR或HTML正文抽取器。图片内文字仍需实际看图。

## 让agent逐句检查

```bash
python3 scripts/chinese_sentence_review.py run /tmp/article-sentence-review
```

脚本依次调用本机`codex exec`，使用临时、只读会话和结构化输出。每批默认6项；需要一项一调用时，准备阶段设`--batch-size 1`。每批仍须逐项返回原编号、原句和三项结论，不能用一条批量结论替代。调用超时默认300秒，可用`--timeout 180`调整；不会无限重试。

准备时按句中实际出现的检索词召回少量本地搭配用例，附原文短语、语境、编辑分析和迁移边界。召回是文字匹配，不是语义判定；例子不适用就不用。`corpus_refs`只记录agent实际参考的已给定ID，不按召回数量冒充使用效果。

每项的`grammar`、`tone`、`coherence`分别填`pass`、`issue`或`uncertain`，并写具体理由。`suggestion`保存原句或改句，`meaning_risk`及`meaning_note`登记语义变化风险，不代替新闻事实核验。三项均通过时不得同时擅自修改原句。

运行中断后重跑同一命令，已保存且校验有效的批次会跳过。无效结果不自动跳过，也不自动循环修复。补查或替换无效批次时保留原结果记录，只处理对应批次。

如果执行环境限制Codex初始化本地运行库，`run`可能在实际审稿前退出；这不算agent已审核。也可以把`prompts/batch-xxx.md`交给当前会话中获授权的agent，按对应`requests/batch-xxx.json`及`response.schema.json`写出`results/batch-xxx.json`，再运行下面的校验。

## 校验与查看结果

```bash
python3 scripts/chinese_sentence_review.py check /tmp/article-sentence-review
```

| 产物 | 用途 |
| --- | --- |
| `article.snapshot.md`、`rules.snapshot.md` | 冻结原文和实际使用的基座 |
| `manifest.json`、`package-hashes.json` | 句子编号、区间、输入及审核包哈希 |
| `requests/`、`prompts/` | 每批的上下文、可用语料与审核要求 |
| `results/` | agent的原始结构化结果 |
| `sentence-review.json` | 汇总覆盖状态和全部结果 |
| `sentence-review.md` | 按句阅读问题、理由及建议 |

漏编号、重复编号、未知编号、原句不符、缺检查维度、空理由或编造语料ID都会被拒绝。原文、基座或参与检索的语料文件发生变化后，旧审核不能继续作为当前稿的结果，须换目录重新准备。审核包中的提示词、请求和快照也有哈希校验。

| 退出码 | 含义 |
| --- | --- |
| 0 | 覆盖完整，agent未标出问题或待核项 |
| 1 | 运行、格式、版本或输入校验失败 |
| 2 | 尚未收齐全部句子 |
| 3 | 覆盖完整，但仍有问题或待核项 |

退出码0只表示按协议收齐了agent判断，不保证判断必然正确。逐句遍历解决遗漏，不能解决agent把不合适的表达判为通过；遇到用户已否定而agent仍通过的句子，应保留这条分歧，不能用覆盖率覆盖用户意见。退出码3不能写成文章通过。脚本不修改原文、不自动接受改句；主笔仍需核对建议是否保留事实、引用和已确认表达，修改后重新冻结并复核改句及受影响上下文。这个工具纳入既有审稿流程，不另设无限修改loop，也不推送或发表。

## 验证

```bash
python3 -m unittest discover -s scripts/tests -p 'test_chinese_sentence_review.py' -v
```

测试覆盖切句、非空白字符保留、错版和漏句拒绝、维度分查、无依据改句、产物完整性、CLI退出状态以及有效批次续跑。CLI协议测试使用本地子进程替身，不将替身结论登记为真实agent审核。真实试跑记录在对应文章目录，和测试结果分开。
