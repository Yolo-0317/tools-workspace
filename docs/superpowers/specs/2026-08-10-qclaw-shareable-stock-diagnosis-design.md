# QClaw 无 MySQL 个股诊断共享版设计

## 目标

提供一个可复制给其他 QClaw 用户的 A 股个股诊断 Skill。接收股票代码或名称以及可选的手工持仓参数，按当前交易时段获取公开行情并输出交易指导。共享版不连接 MySQL，不依赖本工作区、不读取券商页面，也不包含任何本机凭据、真实持仓或账户信息。

共享版保留现有系统的核心安全原则：先识别交易时段，再选择完整收盘数据或盘中数据；证据不完整时明确降级；不自动下单，不把估算结果描述成确定事实。

## 交付形态

交付目录固定为 `a-share-short-term-trading/share/qclaw/a-share-stock-diagnosis/`，可以整体压缩分享，也可以复制到 QClaw 默认加载的 `~/.openclaw/workspace/skills/a-share-stock-diagnosis/`。

目录至少包含：

- `SKILL.md`：QClaw/OpenClaw 触发条件、参数收集、脚本调用方式、安全约束和结果解释规则。
- `README.md`：macOS、Windows 安装步骤、环境检查、使用示例和故障排查。
- `scripts/diagnose.py`：稳定的单一命令入口。
- `a_share_stock_diagnosis/`：行情访问、交易时段、指标、CYQ、持仓决策和结构化输出模块。
- `tests/`：不联网的固定样本测试及显式启用的联网冒烟测试。
- `.gitignore`：排除 Python 缓存、测试缓存和公开行情缓存。

Skill 使用标准 YAML frontmatter，仅声明名称、描述和 QClaw/OpenClaw 元数据，不修改对方的 `openclaw.json`，不要求重启 QClaw 服务。

## 运行依赖

- Python 3.10 或更高版本。
- 默认只使用 Python 标准库，避免要求对方安装 pandas、SQLAlchemy、PyMySQL、Tushare 或 OpenCLI。
- 运行时需要访问公开行情接口；不需要 API Key、数据库账号或 `.env`。
- 时间统一使用 `Asia/Shanghai`，数值计算不交给大模型完成。

如果公开接口不可访问，Skill 必须返回结构化的安全失败结果，由 QClaw 告知用户本轮未形成有效诊断，不得用模型常识补造价格、日期或技术指标。

## 用户输入

必填输入为以下两者之一：

- 六位 A 股代码；
- 可由公开证券搜索接口唯一解析的股票名称。

持仓参数全部可选：

- `shares`：当前持仓股数，必须是非负整数。
- `cost_price`：持仓成本价，必须为正数。
- `available_shares`：当前可卖股数，必须是 `0..shares` 的整数。

进入持仓诊断至少需要 `shares` 和 `cost_price`。若缺少其中之一，QClaw 每次只补问一个缺失值。`available_shares` 可以保持未知；未知时仍可给出价位条件，但不得生成具体卖出股数。三个参数只用于本次进程内计算，不写入缓存、日志或配置。完全未提供持仓参数时执行普通个股诊断。

命令行契约为：

```bash
python3 scripts/diagnose.py --symbol 603011 --output json

python3 scripts/diagnose.py --symbol 603011 --shares 300 \
  --cost-price 12.34 --available-shares 300 --output json
```

测试使用的 `--at` 只接受带时区 ISO 时间，并在 `SKILL.md` 中标记为复现参数，不作为用户手工选择交易时段的方式。

## 数据来源与缓存

共享版按需访问东财公开接口，获取：

- 股票名称、交易所和证券代码映射；
- 当前行情及行情时间；
- 最近最多 210 根不复权日 K，包括开高低收、涨跌幅、成交量、成交额和换手率。

公开接口返回必须经过字段类型、代码匹配、时间和价格关系校验。HTTP 状态异常、响应结构变化、股票停牌或关键字段缺失均保留具体错误码，但用户输出中只显示安全且可理解的降级原因。

允许缓存的内容仅限公开的证券映射与日 K，默认放在用户缓存目录下（macOS/Linux 为 `~/.cache/a-share-stock-diagnosis/`，Windows 为 `%LOCALAPPDATA%/a-share-stock-diagnosis/`）：

- 证券映射最长缓存 24 小时；
- 已完成日 K 按交易日复用；
- 实时行情不落盘；
- 持仓参数、诊断结论和用户对话永不缓存。

缓存写入失败不影响本次内存计算。缓存内容不得进入分享压缩包或 Git。

## 交易时段判定

共享版自动区分：

- `PRE_MARKET`：交易日 09:30 前；
- `INTRADAY`：09:30–11:30、13:00–15:00；
- `MIDDAY_BREAK`：11:30–13:00；
- `POST_MARKET`：交易日 15:00 后；
- `NON_TRADING_DAY`：周末或已确认的休市日。

交易日判断优先使用公开交易日数据；若无法确认节假日状态，则不得仅按工作日猜测。此时返回“交易日历未确认”的 `NO_TRADE` 降级结果。盘前、午间、盘后和非交易日只使用已完成日 K；盘中可以使用实时价格，但技术指标和筹码仍以最近完整日 K 为基准。

## 计算与诊断规则

共享版复用并固化以下确定性计算口径：

- MA5、MA10、MA20；
- ATR14；
- 最近 20 日高点和最近 10 日低点；
- 基于最多 210 根日 K 和换手衰减的 `eastmoney-cyq-v1` 筹码估算；
- 90% 筹码成本区、平均成本、获利比例和集中度；
- 触发价、入场上限、失效价及触发到失效的风险距离。

CYQ 必须明确标注为成交和换手衰减模型估算，不是交易所披露的真实持仓成本。输入少于 20 根有效日 K 时不生成筹码结论。

无持仓诊断只输出 `WAIT_ENTRY` 或 `NO_TRADE`，不生成可直接下单的许可。若触发到失效的风险距离不在 1.5%–5.0%，关键证据缺失，或数据日期不匹配，结果必须为 `NO_TRADE`。

持仓诊断在普通诊断之上结合成本、现价、近期支撑压力和可卖数量，输出以下建议之一：

- `HOLD`：继续持有并给出防守位；
- `REDUCE`：给出建议减仓股数、触发条件和剩余防守位；
- `EXIT`：失效条件成立时退出当前可卖部分；
- `OBSERVE`：数据或交易日状态不足，不给具体卖出数量。

建议减仓股数必须以 100 股为单位且不超过 `available_shares`。`available_shares` 为 0 时不得建议当日卖出。共享版不根据账户总资产推算仓位；没有用户提供的账户数据时，不输出组合仓位占比。

## 结构化输出

脚本标准输出只写一个 UTF-8 JSON 对象，诊断日志写入标准错误。JSON 至少包含：

- `schema_version`、`symbol`、`name`；
- `session`、`as_of`、`diagnosis_trade_date`、`data_freshness`；
- 当前价与最近完整日 K；
- `indicators`、`chip_estimate`；
- `decision`、`actionable=false`、`reason`、`next_action`；
- `levels`：支撑、压力、触发、失效和可选减仓区域；
- 可选的 `holding`：股数、成本、可卖数、浮动盈亏和建议数量；
- `warnings`、`source_refs` 和 `errors`。

QClaw 读取 JSON 后用中文输出简洁结论，必须展示数据时间、当前时段、核心价位、触发条件及风险提示。QClaw 不得自行改写脚本给出的数值和方向；脚本失败时不得切换为无证据的自由分析。

## 错误处理与安全边界

- 名称解析得到多个证券时，列出候选并请用户补充代码，不自动任选。
- 不支持的市场、退市证券或无有效日 K 时返回明确错误。
- 盘中实时行情失败时，可以退回最近完整收盘诊断，但必须标注“非实时”，持仓建议降级为 `OBSERVE`。
- 数据日期、代码或价格关系不一致时整轮拒绝，不混合不同交易日的数据。
- 不访问券商，不读取浏览器 Cookie，不保存持仓，不连接数据库，不发送消息，不设置定时任务，不执行交易。
- 输出属于规则化辅助信息，不承诺收益，也不替代用户自己的风险判断。

## 测试与验收

离线测试使用固定 JSON fixture，覆盖：

- 代码规范化、名称唯一解析与多候选；
- 五类交易时段、周末、确认休市日和交易日历未知；
- 指标和 CYQ 的固定数值回归；
- 少于 20 根 K 线、停牌、一字板、缺换手和异常价格；
- 无持仓、盈利持仓、亏损持仓、T+1 可卖数为 0；
- 减仓数量按 100 股取整且不超过可卖数；
- JSON schema、错误降级和敏感信息不落盘。

联网冒烟测试默认跳过，显式启用后至少验证一个沪市代码和一个深市代码。最终验收还包括：

1. 在临时目录安装 Skill，不引用本仓库外的 Python 模块；
2. 在未配置 MySQL、Tushare、OpenCLI 和 `.env` 的环境中完成一次诊断；
3. 使用 QClaw 的 Skill 检查命令确认 `a-share-stock-diagnosis` 可发现且就绪；
4. 实测无持仓和手工持仓两种中文对话触发；
5. 扫描分享目录，确认不含密码、Token、数据库地址、券商信息和真实持仓。

## 非目标

- 不复制 MySQL 仓储层、券商持仓刷新、组合账户、选股、回测或公告深度研究。
- 不提供看板、定时刷新、推送或自动下单。
- 不对全市场批量抓取或维护长期历史库。
- 不保证公开行情接口永久稳定；接口变化通过版本升级处理。
- 不替代本机完整版的审计快照、组合风控和历史复现能力。
