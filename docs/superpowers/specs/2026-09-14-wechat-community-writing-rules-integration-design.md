# 公众号社区写作规则择优整合设计

## 目标

不安装 `zdyya/writer-skill` 或 `isvlasov/rageatc-oss`，只把经过静态审计、适合「牛马也智能」教育热点稿的稳定规则并入现有 `wechat-mp-writing`。增强事实核验、编辑判断和去 AI 自说自话能力，同时保持现有选题、DeepSeek 手工交接、双确认、真实配图及独立草稿槽位不变。

## 方案选择

采用“独立参考规范 + 热点路由接入 + 现有代码门禁小幅增强”的方式。

- 不直接安装社区 Skill，避免宽泛触发器接管所有写作任务。
- 不引入社区脚本、外部模型子进程、本地网页服务或环境变量转发。
- 新增一份聚焦公众号热点稿的事实与编辑门禁文档，避免把大量规则继续堆入 `hotspot-deep-review.md`。
- 在 `hotspot-deep-review.md`、`deepseek-writer-sop.md` 和 `anti-ai-voice.md` 中只增加必要路由或摘要，不复制整份规范。
- 在已有 `wechat_mp_hotspot_quality_gate.py` 上增加少量高置信度自动检查；需要语义判断的项目保留为人工检查，避免关键词误伤。

## 纳入的规则

### 写作与编辑

1. 风格样本只决定表达方式，不能充当事实来源。
2. 不虚构第一人称经历、采访、家庭处境或人物心理。
3. 每个段落必须增加事实、解释、边界或判断；重复换词不算信息增量。
4. 全文保留一个可被反驳、可由证据支撑的核心判断，并回应最强的合理异议。
5. 事实限定应直接服务读者判断，不写成“不能把本文理解为……”一类自我审稿说明。

### 事实核验

1. 将关键表述区分为事实、当事方说法、解释性判断、作者观点和暂不可核实信息。
2. 政策名称、日期、金额、适用地区、适用对象、计算口径和引语优先回到原始来源。
3. 一个权威原始政策文件可以作为政策条文的主要依据，不机械要求每条政策事实都有三个来源。
4. 争议事件应补当事方回应或主管部门信息；当事方通报只能证明其公开表述，不能自动视为中立结论。
5. 检查多个报道是否共同转述同一个原始信源，避免把重复转载当成独立印证。
6. 检查时间、地区、学段、园校性质、收费类别和定义口径是否错配；证据不足时保留不确定性。

## 自动门禁与人工门禁边界

自动阻断只处理高置信度问题：编辑过程语言泄漏、自我审稿腔、标题数字未兑现、无权威来源的绝对政策范围、完全重复段落及现有择校录取承诺。

以下项目只做人工检查：来源是否真正独立、官方回应是否属于利益相关方陈述、段落是否有信息增量、最强异议是否被公平回应、事实限定是否自然。它们依赖上下文，不用简单关键词直接拒稿。

## 保持不变的流程

- 人工教育热点候选只保留北京、上海、广州、深圳发生的新闻。
- 通过地域门禁后，教育收费、退费、补贴和家庭账单题优先。
- Agent 提供事实包和 DeepSeek 提示词；用户自行取回初稿。
- 用户贴回初稿后，由 Agent 核事实、编辑、配图并展示门禁结果。
- 第一次确认用于交付提示词，第二次确认后才写入微信草稿。
- 正文目标 900—1100 字，去空白后少于 850 字拒绝。
- 正文图最多 3 张；找到不超过 3 张合格真实图时全部进入正文，其中一张同时作为封面。

## 验证

1. 运行 Skill 结构校验。
2. 为自动门禁补充正反例单元测试，重点验证编辑过程语言、自我审稿腔和正常事实限定不会互相误伤。
3. 运行热点质量门禁及浏览器暂存相关单元测试。
4. 检查差异，确认没有改动 DeepSeek 调用禁令、双确认、四城选题和图片数量规则。

## 非目标

- 不安装或执行任何社区 Skill。
- 不改变自动定时任务、候选评分程序或微信发布权限。
- 不重新生成或覆盖现有草稿。
- 不要求每篇文章机械加入固定数量的金句、钩子、反方观点或来源。
