# 公众号晚间批次改为仅手动执行

## 背景

公众号生产调度当前已经暂停，旧版 `launchd` 标签也会被安装脚本卸载，但代码、Skill 和文档仍保留“19:00 自动批次”“按日期自动选择 evening/weekend”等表述与入口。这会让人误以为系统仍会定时写稿，也留下未来误恢复自动触发的可能。

## 目标

公众号不再存在 19:00 自动写稿行为。保留显式手动命令：

```bash
cd stock-ai
uv run python -m scripts.tools.wechat_mp_draft_batch --batch evening
```

手动 `evening` 仍生成 `news + hotspot`，继续执行现有质量门禁、合规检查、封面选择、草稿槽位更新和通知逻辑。

## 设计

### 调度边界

- 删除通用公众号自动草稿任务在 host-jobs 中的路由，不再允许调度器通过 `wechat-mp-draft` 或 `wechat_mp_draft` 名称间接执行晚间批次。
- 旧 `launchd` 草稿标签继续由安装脚本卸载；安装脚本只保留公众号 IP 白名单监控，不宣称存在草稿定时任务。
- 已暂停的分时段热点任务不在本次恢复，也不新增任何替代定时器。
- 不修改手动 `wechat_mp_draft_batch --batch evening` 的文章生成逻辑。

### 命令行为

- `wechat_mp_draft_batch` 必须显式提供 `--batch`；不再根据当前日期自动选择 `evening`、`weekend` 或 `tv_trial`。
- `wechat_mp_draft_scheduled.sh` 作为旧自动入口退役，避免脚本名继续暗示可定时运行。
- 影视试跑、热点分时段和其他明确的手动脚本保持现状；本次只收口通用晚间自动入口。

### 文档

- 公众号 Skill 中把 `evening` 标为“仅手动”，删除“19:00 launchd”描述。
- 调度文档明确：公众号没有自动写稿任务；列出手动 `evening` 命令。
- 修正批次模块、CLI 帮助和安装脚本中的过时“19:00”“自动选择批次”文案。

## 错误处理

- 调用批次 CLI 而未指定 `--batch` 时，参数解析直接报错并列出可选批次，不再静默按日期选稿。
- 手动批次原有的 Codex、质量、合规、微信凭证和图片错误处理保持不变。

## 测试

- 单测确认批次 CLI 缺少 `--batch` 时失败。
- 单测确认显式 `--batch evening` 仍解析为 `news + hotspot`。
- 源码检查确认 host-jobs 不再包含通用 `wechat-mp-draft` 路由。
- 安装脚本测试或文本断言确认旧草稿 `launchd` 标签仍会被卸载，且不会安装新的草稿定时任务。
- 运行公众号退役稿型、批次通知和质量门禁相关回归，确保手动写稿能力不受影响。

## 非目标

- 不删除 `evening` 批次本身。
- 不自动发表文章。
- 不恢复或调整已暂停的 09:00、11:00、15:00、18:00 热点任务。
- 不改变账号角色卡、写作模型、稿型门禁或草稿内容结构。
