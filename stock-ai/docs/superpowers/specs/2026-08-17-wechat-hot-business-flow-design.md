# 公众号热点商业独立流程设计

## 目标

为「牛马也智能」增加一个长期独立稿型 `hot_business`，中文名称为“热点商业”。它与现有 `hotspot` 热点深评并列：都从当日公共热点出发，复用长图文研究、配图、合规和草稿箱链路，但热点商业专门解释事件背后的公司、生意和利益关系。

该流程只支持人工命令触发，不加入 Docker scheduler、launchd 或现有自动批次。每次触发只生成或更新一个独立草稿槽位，用户审阅后再决定是否发表。

## 定位与边界

热点商业的一句话定义：

> 从当天正在发生的热点出发，再往前走一步，讲清背后的公司、生意和利益关系。

它不是商业新闻摘编、公司软文、创业鸡汤或投资分析。文章必须先回答普通读者正在关注的事件，再解释一个具体商业问题，例如：

- 品牌为什么改变门店、会员或服务规则；
- 涨价、降价、补贴或低价竞争的成本由谁承担；
- 一个产品为什么突然走红，收入来自哪里；
- 明星、影视或体育热点如何连接品牌与产业链；
- 平台规则变化如何影响消费者、商家和从业者。

继续遵守「牛马也智能」的品牌边界：不荐股、不写买卖暗示、不冒充企业内部人士，不把公开资料推断写成已证实的公司战略。

## 用户入口

独立命令采用现有公众号 CLI：

```bash
cd stock-ai
uv run python -m scripts.tools.wechat_mp_draft \
  --kind hot_business \
  --dry-run
```

默认行为：

1. 读取当前微博、百度等已有热榜来源；
2. 筛出具有商业解释空间的候选；
3. 自动选择评分最高且达到门槛的题目；
4. 完成研究、写作、配图和质量检查；
5. `--dry-run` 只输出预览与报告，不调用微信草稿 API。

人工指定热点时使用：

```bash
uv run python -m scripts.tools.wechat_mp_draft \
  --kind hot_business \
  --topic "具体热点实体或事件" \
  --dry-run
```

人工指定只跳过自动选题，不绕过来源、事实、原创、配图和合规门禁。

确认预览后，移除 `--dry-run`，只更新 `hot_business` 草稿槽位。该命令不发表文章、不增加第二次通知，也不改变其他热点草稿。

## 每日热点筛选

候选必须来自触发时仍具有当日性的热榜或公开报道，不预先囤积海外商业案例，也不从纯商业案例反向制造“热点”。

每个候选按四项评分：

| 维度 | 权重 | 评分问题 |
| --- | ---: | --- |
| 热度 | 40% | 是否正在上升，是否有多个公开平台或媒体同时讨论 |
| 商业空间 | 30% | 是否能解释品牌、产品、定价、成本、渠道、竞争或平台机制 |
| 可核验性 | 20% | 是否能找到至少 3 个不同来源域，其中至少 1 个为一手或权威来源 |
| 普通人关联 | 10% | 是否直接关联消费、工作、收入、服务体验或日常选择 |

总分采用 100 分制，达到 70 分才允许进入研究。没有合格候选时命令失败关闭，展示候选评分和拒绝理由，不用低质量商业故事补位，也不回退普通 `hotspot`。

优先候选：

- 品牌争议、新品发布、门店或会员规则调整；
- 涨价、降价、补贴、佣金和服务变化；
- 平台竞争、消费趋势与商业模式变化；
- 明星、影视、体育热点背后的品牌合作或产业链；
- AI 产品、互联网平台和职场热点中的商业机制。

直接排除：

- 只有情绪、没有明确商业问题的娱乐八卦；
- 伤亡灾难及不适合商业化解读的公共事件；
- 司法结论未明、核心事实频繁反转的争议；
- 找不到原始出处的数据、销量冠军和逆袭故事；
- 只能靠猜测企业内部动机才能成立的选题。

## 研究与事实规则

每篇至少记录 3 个不同来源域，来源优先级为：

1. 企业公告、监管文件、财报、产品页和当事方原始回应；
2. 权威媒体或行业机构的独立报道；
3. 其他媒体报道，只用于补充背景，不单独支撑关键数字。

研究产物必须区分：

- `facts`：来源直接支持的事实；
- `inferences`：由多个事实推导的判断；
- `rejected_claims`：存在冲突、缺少原始出处或超出来源口径的说法。

正文中的推断使用“可能、可以理解为、从公开信息看”等边界词。`rejected_claims` 不得进入标题、摘要和正文核心论点。

禁止以下口径升级：

- 把“最高、最多、可达、曾经”写成“稳定”；
- 把单一渠道或细分类目领先写成“全国第一”；
- 把产品设计变化写成已经验证成功的公司战略；
- 把计划、目标、预测写成已发生的市场结果；
- 把同一来源的转载稿计作多个独立来源。

## 文章结构

每篇只回答一个可争论、可核验的商业问题，不写商业知识清单。正文结构为：

1. 80 字以内交代当日热点及反常点；
2. 提出普通读者能理解的商业问题；
3. 还原公司、产品与市场的必要事实；
4. 解释定价、成本、渠道、竞争或品牌机制；
5. 给出有证据支持的判断，并说明推断边界；
6. 落到消费者、从业者或普通人的实际影响；
7. 以一个具体问题结束，保留讨论空间。

文章继续复用热点深评的移动端短段、去元叙述、原创性和质量门禁：正文去空白后不少于 1920 字，至少 3 个不同来源域，`original_thesis` 不少于 20 字。

## 标题规则

标题必须同时包含热点实体和商业问题，避免“商业逻辑”“深度解析”等空泛标签。

可用结构：

- `{品牌/事件}为什么突然{反常结果}？`
- `{变化/争议}背后，{成本/利润/渠道}由谁承担？`
- `{产品}越来越贵或便宜，{公司}真正想卖什么？`

标题中的销量、排名、金额和市场结论必须有可追溯来源。推断不得写成已经发生的结果，标题不得出现投资建议或买卖暗示。

## 数据契约

`hot_business` 沿用 Codex 长图文 JSON 的基础字段，并增加商业研究字段：

```json
{
  "title": "热点实体与商业问题",
  "digest": "一到两句话说明文章回答的问题。",
  "body": "不少于 2000 字的纯段落正文。",
  "topic": "事件检索词",
  "research_urls": [
    "https://example.com/source-a",
    "https://example.org/source-b",
    "https://example.net/source-c"
  ],
  "original_thesis": "可被反驳和检验的原创核心判断。",
  "business_question": "本文解释的单一商业问题。",
  "facts": [
    {
      "claim": "来源直接支持的事实",
      "source_url": "https://example.com/source-a"
    }
  ],
  "inferences": ["由事实推导且正文标明边界的判断"],
  "rejected_claims": ["未采用的未证实说法"],
  "slot_key": "hot_business"
}
```

`business_question`、`facts`、`inferences` 和 `rejected_claims` 是 `hot_business` 必填字段。`facts` 中每条事实必须同时给出 `claim` 与位于 `research_urls` 内的 `source_url`，从数据契约上保证关键事实和数字可以回溯；普通 `hotspot` 的 JSON 契约保持不变。未知字段继续忽略，以保留向后兼容。

## 流水线与代码边界

数据流：

```text
现有每日热榜
  → hot_business 候选评分与硬排除
  → 最高分合格题目或 --topic 指定题目
  → 来源研究与事实/推断分层
  → Codex 热点商业成稿
  → 热点长文清洗与原创门禁
  → 真实报道图优先的现有配图链路
  → 商业事实门禁与公众号合规检查
  → hot_business 独立草稿槽位
```

实现边界：

- 新增独立的 `hot_business` kind 和 `hot_business` 草稿槽位；
- 新增热点商业选题评分、研究契约和事实门禁模块；
- 复用现有热榜抓取、热点正文清洗、配图、封面、合规和草稿 upsert；
- `wechat_mp_draft --kind hot_business` 支持自动选题、`--topic` 和 `--codex-draft`；
- 独立正文缓存，避免与普通 `hotspot` 同题缓存互相覆盖；
- 不加入任何定时配置或批次；
- 不改变现有 `hotspot`、`tv_review`、`newspic` 和财经稿型行为。

## 失败边界

- 没有 70 分以上候选：列出评分和原因后退出，不生成稿件；
- 少于 3 个不同来源域：在写稿或微信调用前失败；
- 必填研究字段缺失：在正文处理前失败；
- 关键数字没有来源映射：质量门禁拒绝；
- 正文把 `rejected_claims` 写回核心论点：质量门禁拒绝；
- 配图不足或来源不可追溯：沿用现有缺图协议，不静默使用无关图；
- `--dry-run`：不上传图片、不写草稿箱；
- 正式命令：只更新 `hot_business` 槽位，不发表文章。

## 验证与验收

单元测试覆盖：

- 候选四维评分、70 分门槛和硬排除；
- 自动选择最高分合格题目；
- `--topic` 跳过自动选择但保留研究门禁；
- 商业 JSON 必填字段与来源域校验；
- 事实、推断和拒绝说法的边界检查；
- 独立缓存与槽位不会覆盖普通 `hotspot`；
- `--dry-run` 不触发图片上传或微信 API；
- 不传 `hot_business` 时所有现有稿型保持兼容。

端到端验收：

1. 手动命令能从当日热榜选择一个 70 分以上的商业热点；
2. dry-run 输出标题、摘要、正文、候选评分、来源和事实分层报告；
3. 正式命令只创建或更新 `hot_business` 草稿槽位；
4. 调度配置与自动批次中不存在 `hot_business`；
5. 文章通过现有热点深评字数、原创、配图和合规门禁；
6. 普通热点深评流程的输出与测试保持不变。
