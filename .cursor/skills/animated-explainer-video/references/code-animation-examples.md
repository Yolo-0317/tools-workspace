## 按解释任务选择

| 要讲清什么 | 画面方法 | 适用条件 |
|---|---|---|
| 一个过程如何完成 | 同一空间保留主体，材料或状态逐步加入，说明与变化同步 | 操作说明、配方、流程；数量来自本集可靠来源 |
| 部件如何协同 | 整体定位→局部剖开／拆开→追踪路径→回到整体结果 | 器械、生活原理、生理机制；部件和连接先核对 |
| 微观机制在哪里发生 | 沿同一对象从整体进入组织、细胞或更小尺度 | 生物与材料；各层用位置、颜色或轮廓维持对应关系 |
| 条件改变带来什么结果 | 相同布局下只改变有关变量，保留前后对照 | 比较与因果解释；示意趋势不能伪装成测量数据 |
| 一个系统怎样关联 | 按关系逐步连线，沿正在讲解的路径推进 | 生态、信息流；连接方向必须符合事实 |
| 事件怎样发展 | 时间轴上的人物、地点、物件随阶段变化 | 历史与技术发展；年代只负责定位，不能占掉叙事 |
| 场景怎样接得自然 | 同一物件连续改变尺寸、形状或位置，带出下一层内容 | 关系真实且观众能追踪时；不强制整片一镜到底 |
| 需要艺术化空间感 | 前中后景分层、视差、沿具体门户进入下一幕 | 拼贴或文化题材；需要分层资产与遮挡区域补全 |

这里的分类与适配是本地设计归纳。每幕先选一个主要解释动作，旁白到关键内容时触发；语义和阅读时间决定节奏，广告案例的“每拍一个变化”不用于长段科普对白。

## 代码渲染约定

1. 先适配已有渲染入口；无入口时提供 `renderAt(t)` 或 `seek(t)`。场景、摄像机、文字、遮罩均由同一最终时间轴计算，不能让 CSS transition、setTimeout 或实时帧差决定导出状态。
2. 有随机运动时固定种子，并保存可定位的轨迹或使用确定性时间步预计算。随机游走不能在每次 draw 时重新抽样；累积物理不能仅靠传入时间就宣称可乱序定位。内容只需示意时不硬上数值模拟。
3. 图片、字体及外部资源加载完成后再抽帧；记录构图尺寸、fps、总帧数与资源版本。按 `t = frameIndex / fps` 输出，沿用单集帧率；依赖与离线资源先检查，不根据案例标签盲装框架。
4. 先出每幕起点、主要变化、结果的接触表，转场加前后帧。文字离场早于同位置新文字进场；移动对象保持锚点，放大内容受本幕遮罩裁切。已确认大段静态字幕时，只切换整段，不改成滚动字幕或跳字。
5. 顺序渲染与乱序定位回到同一时间应一致，可在同环境对比像素或图像哈希。移动预览检查速度、停顿和追踪关系；需要无缝循环时另查首尾状态及速度，不强迫叙事片循环。
6. 高速小物件确实难看清时再评估时间多采样和运动模糊。固定字幕、人物及静止图保持清晰；不为照搬案例全片升到 60fps 或固定 4／6 子帧。
7. 代码画出独立图层和运动，再交现有 FFmpeg 编码合成。保存可编辑源与最终时间轴；无声版后配音时修改动作锚点和区间，不以音乐节拍压缩对白。

## 当前系列的具体适配

沿用已确认的 2:3 外框、上方整段字幕、中部 16:9 内容、下方三角色区域。动画发生在中部解释空间；下方保留原角色，只在已授权配音后加入说话者嘴型。中部摄像机不连带缩放上方文字与下方人物。

高血压配图用清洁、平静的医学插画，有病人、医护、家庭人物与用途明确的道具。丰富程度来自组织结构、前后状态及操作细节；案例中的发光舞台、品牌大片和快速卡点不覆盖这个已调整的画风。

以下是本地分镜适配示例，医学表达仍以本集核验及用户确认的文案为准：

- 危害：整体人物定位心脏、脑与肾，再进局部剖面；各器官分别承接对应对白，避免三模型从头静止到尾。
- 心脏：保留相同剖面构图，逐步显示心肌增厚的示意变化。不要把“血压高”直接画成所有血管均已堵塞。
- 病因：围绕同一家庭／诊室场景依次建立与正文对应的因素，再分出可能引起继发性高血压的疾病；不把风险因素画成必然结局。
- 日常测量：椅子、桌面、上臂袖带与血压计独立布局，显示安静坐好、手臂与心脏同高、两次测量和记录。技术上如何动用分层图或矢量决定，不要求主持人做动作。

## 制作简报模板

只填写当前授权阶段需要的项；已有脚本与配置直接引用，不重复询问。

```text
解释目标：本幕结束后观众应理解的一个关系
已核验依据与全文：引用本集研究和确认文案
画面方法：过程／拆解／尺度／对照／关系／时间线
对象与图层：主体、可动部件、背景、遮挡关系、参考资产
状态：起点 → 过程 → 结果；跨镜头保留的视觉锚点
时序：完整口播空间、关键语义锚点、理解停顿；后配音时可延展区间
美术与布局：本集色彩材质、输出比例、内容区域、静态字幕位置
渲染与交付：现有引擎入口、资源加载、定位时间、当前应交图片或视频
检查：关键状态接触表、转场、乱序定位；视频阶段再做移动与编码检查
```

仅整理灵感或配图时不启动音频、视频模型与最终合成。选择代码动画可以减少对生成式视频的依赖，但不能承诺复杂角色表演或写实流体必然由现有环境完成。
