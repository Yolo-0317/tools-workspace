# 用户主动热点深评：DeepSeek 成稿与抖音优先配图设计

日期：2026-08-28

## 背景

现有公众号 skill 对用户主动热点深评存在互相冲突的规则：部分文档要求先走固定 DeepSeek 网页会话，另一些文档又将 Codex 手写稿列为推荐入口；配图规则一处允许少图，另一处仍要求固定“封面 1 张 + 正文 3 张”，并在缺图时创建原创图片请求。实际执行因此可能绕过 DeepSeek，也可能在真实图片不足时进入自动补图或原创图片流程。

本次修订只处理用户主动发起的 `hotspot` 热点深评。定时稿、文学稿、原创小说、栀夏生活分享、影视稿和其他稿型不在本设计范围内。

## 已确认决策

1. 用户主动要求热点深评时，DeepSeek 固定网页会话直接产出标题和正文初稿。
2. Agent 负责前置研究、提示词设计、事实核验、编辑、高亮、配图和质量检查，不得跳过 DeepSeek 自行改走 Codex 成稿。
3. 配图必须先检索抖音，只读取搜索结果卡片和封面，不打开或播放视频。
4. 抖音之后才允许补充政务、官方媒体、正规新闻机构、法规页面等可追溯图片或网页截图。
5. 热点深评禁止自动生成图片，不创建原创补图请求，也不调用 ChatGPT、ImageGen、DeepSeek 或其他模型补图。
6. 合格图片有几张用几张；正文允许 0—3 张，不再为满足固定数量补图。
7. 微信草稿至少需要一张合格图片作为封面；没有任何合格图片时停止推送，不使用品牌图、无关素材或生成图兜底。

## 目标工作流

```text
Agent 研究事件、形成事实包与轻量提示词
  → 展示来源包、核心钉子和提示词，等待第一次确认
  → 绑定当前 Chrome 中指定的 DeepSeek 固定会话
  → DeepSeek 直接生成标题和正文初稿
  → 只提取本轮新增回复并解除绑定
  → Agent 逐项核验事实、时间、数字、人物、引语和法律依据
  → Agent 编辑正文、加入 2—3 处 [[hl:…]]、生成摘要
  → 先检索抖音搜索结果封面，再补权威网页证据图
  → 按实际合格图片数量排版，不生成缺口图片
  → 运行原创度、写作质量、来源和可变图片数量门禁
  → 展示第二次确认清单
  → 用户确认后写入指定热点草稿槽位
```

DeepSeek 未登录、当前标签不是指定会话、发送失败、返回为空或无法确认新增回复时，流程停止并提示用户处理。不得自动回退到 Codex、Composer、DeepSeek API 或其他模型。

## Skill 真源与路由调整

### 单一成稿真源

`wechat-mp-writing/deepseek-writer-sop.md` 作为“用户主动热点深评”的唯一成稿流程真源。其他入口文档只做路由，不再重复定义模型选择。

- `wechat-mp-drafts/SKILL.md`：把“可走”“优先由 Codex”等冲突表述改为明确路由；Codex 手写入口仅保留给定时热点，不作为用户主动热点的回退路径。
- `wechat-mp-drafts/INDEX.md`：将“优先走 DeepSeek”改为“必须走 DeepSeek 双确认流程”。
- `wechat-mp-writing/hotspot-deep-review.md`：删除“Codex 推荐入口”和缺图生成说明，改为引用 DeepSeek SOP 与可变图片规则。
- `wechat-mp-drafts/rules-implemented.md`：记录规则与代码门禁的对应关系。

### 明确授权边界

第一次确认只授权把已展示的提示词发送到指定 DeepSeek 会话；第二次确认只授权把已展示的终稿写入微信草稿。两次确认不能互相替代，也不能沿用其他文章的确认。

## 配图策略

### 第一阶段：抖音搜索结果封面

每篇主动热点深评必须先执行一次同题抖音搜索。只允许读取搜索结果页，不点击视频卡片，不进入视频详情页，不触发播放。

候选图片必须记录：

- 搜索词；
- 账号名称及认证/机构属性；
- 搜索页显示的发布时间；
- 稳定原视频链接或视频 ID；
- 封面图片地址；
- 封面所证明的事实或承担的版面角色。

来源优先级为：政务原始发布、央媒、地方党媒或广电、全国性正规新闻机构。普通网友搬运、二创账号、来源不明账号、与事件无关的泛素材不进入正式草稿。

### 第二阶段：权威证据图

抖音合格封面不足以支撑全文时，可补充：

- 政务或公安机关页面；
- 党媒、央媒、地方主流媒体报道页；
- 法院、法规、政府公报等权威页面；
- 可追溯的媒体或政务微博原帖。

网页截图必须保留能证明身份、回应、时间线或制度依据的正文区域，去除无关二维码、推荐栏和广告。

### 数量与停止条件

- 封面：必须有 1 张合格图片；可由最适合横裁的抖音封面或权威报道图生成裁切版。
- 正文：使用实际可用的 0—3 张图片；封面源图不在正文重复使用。
- 没有合格封面：停止推送并报告“缺少可追溯封面”。
- 只有 1 张图片：用于封面，正文可以无图。
- 不创建 `codex-image-request.json`，不把 `manual-*` 自动解释为原创插画，不调用任何生图流程。

`figure_sources.json` 继续作为图片来源真源。图片进入排版前必须存在有效 `page_url`、`source_name`、`published_at`、`source_type`、`verified`、`page_title` 和 `caption`。

## 程序行为调整

1. 用户主动热点深评工作流必须保存并校验 DeepSeek 浏览器来源状态；没有 `deepseek_browser` 成稿来源时拒绝进入第二次确认和推稿。
2. `prepare_hotspot_topic_images` 不再为热点深评创建原创补图槽位或抛出要求生成图片的异常。
3. 正文图片数量门禁由“固定 3 张”改为“0—3 张均合法”，渲染器按实际图片数量分布插入位置。
4. 封面门禁保持严格：找不到至少一张已核验来源图时拒绝写草稿。
5. 自动新闻扩源只能在已完成抖音优先检索之后运行；不得覆盖已经核验的抖音封面或来源清单。
6. 任何缓存恢复、强制刷新或 dry-run 都不得重新启用原创图片补位。

为了证明“已经先搜抖音”，热点图片目录增加机器可读研究状态，至少包含搜索词、完成时间、候选数量和所选封面记录。缺少该状态时，用户主动热点不得直接进入其他图片来源阶段。

## 第二次确认清单

Agent 在请求推送确认时必须展示：

- DeepSeek 固定会话已产出本轮标题和初稿；
- Agent 对初稿所做的主要事实修正和结构编辑；
- 最终标题、摘要、正文长度和目标槽位；
- 来源数量及关键来源；
- 实际图片数量；
- 每张图片的来源、用途和页面链接；
- 原创度、写作质量、合规与配图门禁结果；
- 明确说明“本稿未自动生成图片”。

只有用户在看到该清单后明确确认，才能登记推送许可并写入微信草稿。

## 验证方案

### Skill 一致性

- 搜索所有公众号 skill 中“用户主动热点”“Codex 推荐”“图片不足生成”等表述，确保不存在冲突路由。
- 验证入口文档能直接导航到 DeepSeek SOP 和新的配图约束。

### DeepSeek 流程

- 用户主动热点在缺少 DeepSeek 浏览器来源时拒绝 stage、confirm-push 或 push。
- DeepSeek 登录失败、会话错误和空回复保持失败关闭，不触发其他模型。
- 两次确认状态顺序不可跳过。

### 图片流程

- 抖音检索状态缺失时，主动热点图片准备阶段拒绝继续。
- 1 张合格图片时：封面成功、正文 0 图、预演通过。
- 2 张合格图片时：封面 1 图、正文 1 图、预演通过。
- 4 张及以上时：封面 1 图、正文最多 3 图。
- 0 张合格图片时：因缺少封面拒推。
- 图片不足时不得创建 `codex-image-request.json`，不得生成 `manual-*`，不得调用生图模块。
- 已登记抖音封面和来源清单不得被自动新闻扩源覆盖。

### 回归检查

- 定时热点和其他稿型不因本次主动热点规则误改模型来源。
- 文学、原创小说和栀夏生活分享仍按各自 skill 处理原创视觉，不受本规则影响。
- 微信图片上传、封面裁切、来源图注和草稿槽位更新保持正常。

## 非目标

- 不修改已完成稿件的事实观点。
- 不恢复热点自动定时发布。
- 不改变文学、短剧、影视、银发或原创小说的模型与图片策略。
- 不允许通过降低来源核验标准来换取更多图片。
