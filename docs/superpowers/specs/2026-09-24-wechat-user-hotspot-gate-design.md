# 用户主动热点稿质检分流设计

## 问题

用户主动稿的正文目标为 900—1100 字、纯段落；草稿暂存已使用专用原创、公开文案和编辑结构门禁。通用 `wechat_mp_eval` 面向自动稿，仍奖励分块标题、技术名词和文末免责声明，并在自动热点分支保留约 2000 字要求。拿它评价用户主动稿会给出错误的修改方向。机器结构分数也无法判断整篇文章的主线是否真正成立。

## 决定

保留自动稿现有行为。为用户主动稿增加显式、只读的 JSON 预检入口，复用草稿暂存已采用的原创、公开文案和七项编辑结构检查，并检查公开合规。输出明确写明：预检只验证可机器检查的条件，不代替事实核验、段落推进和读者口吻的人工审稿，也不允许据此直接推草稿。输入不合格时返回非零状态。

写稿 Skill 将通用评分与用户主动稿预检分开说明，新增文章级人工否决：先写出目标读者的问题与一句核心判断，再逐段检查事实、解释、异议或判断是否围绕它推进。主线散乱时退回重写，不能用 75 分、AI 味分或局部润色宣称通过。

## 边界

- 不改变定时稿的 2000 字门槛、现有打分或草稿写入权限。
- 不把人工判断伪装成新的关键词算法。
- 不自动配图、暂存、写入公众号或发表。
- 保留工作区已有修改；本次只改预检入口、相应测试和命中的写稿文档。

## 验证

测试用户主动稿预检通过和失败两条路径，并确认通用评分仍保留原行为；运行相关单元测试及 Skill 验证器。用重写后的月饼稿做一次本地预检，再人工逐段审主线与事实。
