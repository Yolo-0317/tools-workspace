## 共通写作规则

先读[中文写作基座](../../../docs/writing/中文写作基座.md)，统一执行叙述身份、材料整合、自然表达、分段回读和语义保护。本Skill只补充题材与交付要求；用户明确例外、证据来源及操作权限继续按本专题执行。共通更新只维护基座，不在此复制一份。

# 公众号中老年健康稿

适用于中年、退休前后及老年读者共同关心的日常健康问题。年龄只用于理解生活处境，不用于推断个人疾病。稿件是有来源的健康生活文章，不冒充医生诊疗意见，也不附保健食品、药品或医疗器械的购物卡。

写稿前读 [健康作者卡](../wechat-mp-health-content/author-role-card.md)；需要提炼丁香医生写法时读[已有观察](../wechat-mp-health-content/dxy-writing-study.md)。一般健康事实及商品边界仍以[健康内容 Skill](../wechat-mp-health-content/SKILL.md)为准。只选题时用[健康选题 Skill](../wechat-mp-health-topic-discovery/SKILL.md)；起标题与审标题用[标题 Skill](../wechat-mp-title-writing/SKILL.md)。

## 近期选题：从丁香医生找问题，再独立写稿

近期新稿默认先人工阅读一篇与中老年生活有关的[丁香医生文章](https://dxy.com/)，记录其 URL、发表日期、读者问的具体问题，以及值得学习的一个写作动作，例如如何在开头呈现两种说法的冲突、何时给出核心判断、怎样用证据推进。再决定本公众号要回答的问题、适用人群和自己的角度。

“仿写”只指学习抽象的提问和论证方法：不复用原文标题、句子、故事、比喻、段落顺序或图片，不逐段同义改写，也不声称拥有丁香医生的身份或审稿背书。遵守[丁香医生用户协议](https://dxy.com/doctor-college/agreement/dxy-doctor.html)，不批量抓取、复制或保存原文。健康结论重新查当前有效的官方指南、公共卫生机构原始资料或高质量研究，并记录资料的日期、对象和适用条件。丁香医生旧文不能证明话题最近热门；若标题或汇报称“近期热议”，另按选题 Skill 核关注信号。

选题前先问：读者看到这篇文章，正准备做什么决定？如“每天散步够不够，为什么起身仍费劲”。用一张内部事实卡写明核心问题、3～5 条关键主张、每条原始证据、适用人群和不能推出的结论。不把这张卡原样写进正文。

取证先查中国权威资料，执行[作者卡的证据工作台](../wechat-mp-health-content/author-role-card.md#证据工作台)。禁止因海外页面更易获取而默认以国外机构为主要来源；国内资料充分时优先采用，确需国外研究补充时在事实卡说明必要性，并核对适用范围。

## 完整流程入口

用户说“写一篇”“继续写一篇”“重写”时，执行[完整终稿流程及自动修订循环](../wechat-mp-health-content/final-delivery-workflow.md)。不把选题、正常审稿和修订拆成多轮用户批准，默认交付选定标题和完整正文。用户只指定某个阶段时按其范围执行。

本套 Skill 各文件分工如下，避免维护多套相互冲突的规则：

| 阶段 | 负责文件 | 得到什么 |
| --- | --- | --- |
| 选题 | 本文件及健康选题 Skill | 中老年生活场景、可查证的主题 |
| 取证与定调 | 健康内容 Skill、作者卡 | 事实卡、作者位置、文章主线 |
| 写稿与多角色审稿 | 完整终稿流程、多角色审稿 | 独立发现问题、主笔统一修改、交叉复核后的完整正文 |
| 起标题与标题循环 | 标题 Skill | 具体场景加自然未说尽的信息 |
| 艺术拆解与配图 | 用户指定的艺术 Skill | 对应主线的场景；成熟正文定图文案 |
| 版式与图文循环 | layout.md、完整终稿流程 | 图文一致、实际手机宽度可读的成稿 |
| 推草稿与回读 | references/draft-api.md | 已授权的草稿创建或原草稿更新 |

完整稿的事实、行文、普通读者、标题与图文四个审稿角色按[多角色审稿](../wechat-mp-health-content/multi-role-review.md)独立检查；主笔统一修改，交叉复核，各角色共享最多三轮语言修订。正文循环、标题循环和图文循环都由 Agent 在当前请求内执行。读者看到的是文章，不是事实卡、检查清单或循环日志；自然程度与信息完整性是交付判断，禁词扫描和轮数不能替代实际阅读。

## 配图与版式

排版时读[健康稿排版](../wechat-mp-health-content/layout.md)：使用分节标题、克制的蓝色重点、必要的建议清单和文末资料，输出带内联样式的 HTML，并检查手机宽度。不要只给每段套一个普通 `p` 标签。

- 至少准备两张与内容对应的**真实图片**，不得用 AI 生成图补位。可把封面图在正文复用。打开实际图片核对画面，并记录原图页、作者、授权方式、文件路径和使用位置；来源与许可无法核实时继续找图。
- 用户明确选择艺术图解时，按其指定的艺术 Skill 拆解内容与图文案，沿用已确认的风格，替代上述真实配图要求。文章主线先确定，图解文案在成熟正文上定稿；艺术图解不伪装成病例、检测数据或真实现场，解释文字也执行同一叙述与审稿标准。当前稿型不在图中加入账号品牌。
- 艺术配图的静态封面、生活场景和图解，可用通用写稿 Skill 的[艺术配图流程](../wechat-mp-article/references/art-illustration.md)安排用途、画风、材质、提示词及验收；用户指定艺术 Skill 时以指定流程为主。不因补充艺术方法而取消真实配图边界或启动额外语言循环。
- 按最新用户偏好，图源统一放文末“图片来源”，注明对应图片、作者、原图及许可链接；使用比正文小的灰色文字；中老年阅读版优先 14px、较深灰 `#606b73`，普通版可用 `font-size:12px;color:#888`；需要时链接原图和许可。每张图分别列出对应来源，不把两张图的署名混成一条。封面裁切时注明“封面经裁切”。
- 结尾可用一句说明本公众号还会分享什么，并自然邀请关注、星标；读者可见文案写“本公众号”，不硬编码旧账号名。示例：“我们以后还会分享更多实用的健康话题，觉得有用的话，欢迎关注并星标本公众号。”不把这句当作每篇必抄模板。

## 草稿与检查

写作完成不自动推送。用户要求推草稿时，按[微信 API 草稿步骤](references/draft-api.md)操作：预检出口、上传正文图和封面、创建或更新原草稿、回读核对。回读失败时先保留 `media_id` 查明原因，不能盲目重建。草稿成功也不等于公开发表；发表仍由用户决定。

语言、信息与标题检查统一执行完整终稿流程；微信写入后的核对以草稿 API 文档为准。两套检查不能互相替代：本地语气审稿不能证明上传成功，接口成功也不能证明文章自然。
