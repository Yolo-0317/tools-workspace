# 公众号热点深评真实图片优先设计

## 背景

热点深评当前会从公开报道页提取图片，失败后请求 Codex ImageGen 补图。现有检索已经覆盖百度新闻和通用新闻搜索，但结果容易缺少微博原帖图片，也只给出笼统的“图源：公开报道（引用）”，无法让编辑快速判断图片是否与当天事件、地点和时间一致。

本次调整让「牛马也智能」的热点深评默认优先采用可追溯的新闻现场实拍。微博和百度作为素材发现入口；无法验证的热搜搬运图不自动进入草稿。原创图仍保留为解释机制和缺图兜底。

## 范围

本次覆盖：

- `hotspot` 长图文的封面与正文配图。
- Codex 手写热点稿和自动热点稿共用的讨论配图流程。
- 已有热点草稿的“只换图片、不重写正文”重推入口。
- 武康路积水现有草稿的图片替换与回读验证。

本次不覆盖：

- 晚间 `sector`、`top5`、`dragons` 的行情图。
- `newspic` 图片消息的版式或图片数量调整。
- 自动发表；流程仍只写入草稿箱，由人工预览后发表。
- 绕过登录、反爬或媒体版权限制。

## 方案选择

### 采用：真实现场图与原创解释图混合

封面和正文前部优先采用当次事件的现场实拍；后续图片可采用处置过程、细节实拍或原创机制图。该方案兼顾新闻现场感、论证需要和版权风险。

### 未采用：所有图片都来自热搜页面

热搜聚合页常出现转载链断裂、旧图复用、视频截图和来源不明的问题。全部使用热搜图会提高错配和版权风险。

### 未采用：继续全部原创

原创图安全可控，但社会热点文章缺少现场证据，读者会明显感到图片与具体事件脱节。

## 素材优先级

每个热点按以下顺序发现候选素材：

1. 草稿 `research_urls` 中指定的权威报道或原始发布页。
2. 微博热搜词对应的媒体认证账号、政务账号或可追溯原帖。
3. 百度新闻结果中的权威媒体现场报道。
4. 其他可验证的新闻媒体同题报道。
5. 已生成的原创解释图。
6. 仍不足时请求 Codex ImageGen 生成。

微博和百度是发现入口，不是自动可信来源。候选图必须能够回溯到具体页面，并通过事件相关性检查。

## 候选图片模型

每张下载图片在 `figure_sources.json` 中记录：

- `page_url`：图片所在的原始页面。
- `image_url`：实际下载地址。
- `source_name`：媒体名、政务主体或原始账号名。
- `published_at`：页面或原帖发布时间；无法提取时为空。
- `source_type`：`research`、`weibo`、`baidu_news`、`news` 或 `generated`。
- `caption`：面向读者的简短来源说明。
- `verified`：是否通过自动来源与相关性检查。

旧版元数据继续可读；字段缺失时按未验证处理，不冒充已核验素材。

## 搜索与筛选流程

### 搜索

从热点标题和实体拆出多组查询词，包括：

- 原始热搜词。
- “事件词 + 地点 + 现场”。
- “事件词 + 日期”。
- “事件词 + 图片”或“事件词 + 视频”。

现有百度新闻与网页检索保留，并增加微博结果页或原帖候选发现。运行环境无法访问动态页面、需要登录或遇到反爬时，记录失败并继续下一来源，不尝试绕过限制。

### 验证

候选图片进入草稿前必须满足：

- 页面标题或正文包含热点核心实体。
- 页面时间与事件时间相符；无法核对时间的候选降低优先级。
- 图片达到现有尺寸、体积和格式门槛。
- 排除头像、二维码、广告、通用图库、股票图、默认封面及明显无关图片。
- 感知哈希或现有去重逻辑判断为非重复图。
- 页面明确写有“未经授权禁止转载”等限制时不自动下载；只保留链接供人工查看。

对于微博用户自摄图，只有媒体、政务账号或明确标注可转载且可追溯原帖的内容可自动采用。普通用户图片默认不自动进入草稿。

## 排序与版位

候选图按“来源可信度、事件相关性、时间匹配、现场感、清晰度”综合排序：

- 封面优先选择横向现场全景，禁止用机制示意图覆盖已有合格实拍。
- 正文第一图优先人物、街道或事件发生地的现场图。
- 正文第二图优先处置过程或关键细节。
- 正文第三图优先另一视角实拍；没有合格素材时保留原创解释图。

图片图注使用具体来源，例如“图源：新民晚报现场报道”，不再对已知来源统一显示“公开报道”。来源不完整时明确写“图片来自相关报道，原始拍摄者待核”，并禁止自动进入正式草稿；仅允许在 dry-run 预览中出现。

## 缓存与续跑

- 合格实拍图和元数据写入现有话题目录，重复运行优先复用。
- `--force-figures` 强制重新搜索，但不会删除已生成的原创图，只有新素材验证通过后才替换对应版位。
- `codex-images-ready.json` 只表示原创补图已经齐备，不再阻止后续显式强制搜索真实图片。
- 搜索完成后若真实图片不足，继续沿用现有 Codex ImageGen 请求协议。

## 武康路草稿迁移

对现有文章执行一次定向重推：

1. 以“武康路积水”“8 月 9 日上海暴雨”等词检索微博、百度新闻和媒体报道。
2. 选择至少一张可核验的当天武康路现场图；若只能找到来源不明的社交图片，则不替换。
3. 优先替换封面和正文第一图，保留两张原创解释图。
4. 使用现有槽位更新草稿，不重写正文。
5. 回读微信草稿，验证封面、正文图片数量、图注和正文内容均正确。

## 失败处理

- 某一来源不可访问：继续其他来源，并在 dry-run 输出失败原因。
- 找到图片但来源或日期不明：不自动采用，输出待人工确认列表。
- 实拍不足：保留原创解释图或触发 ImageGen，不让低可信图片填满版位。
- 微信上传或草稿更新失败：保留本地素材与元数据，不覆盖原草稿。

## 测试与验收

新增或调整单元测试，覆盖：

- `research_urls`、微博、百度新闻和普通新闻的优先级。
- 新旧 `figure_sources.json` 兼容读取。
- 具体图注由来源元数据生成。
- 版权限制、时间不明和普通用户微博图不会自动采用。
- 合格实拍优先于原创图；实拍不足时原创图仍可兜底。
- `--force-figures` 能在已有 Codex ready 标记时重新搜索实拍。
- 重复运行复用合格缓存，不重复联网抓取。

实施完成后运行最相关的公众号图片测试、热点草稿 dry-run、正式草稿重推和微信 API 回读。验收标准是：武康路草稿至少包含一张可核验的当次事件实拍，图注明确，正文未被重写；若公开来源不足，则明确报告而不是使用来源不明图片。
