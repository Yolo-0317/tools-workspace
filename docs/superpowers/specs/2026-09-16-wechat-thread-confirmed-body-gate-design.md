# 公众号“当前任务已确认正文”发布门禁设计

## 背景

用户主动热点目前只能在“用户重新粘贴完整 DeepSeek 初稿”后进入编辑和推送流程。实际使用中，正文可能已经在当前 Codex 任务里完整展示、完成事实编辑，并由用户明确确认发布。此时再次要求复制同一篇正文，只增加重复操作，不能带来新的来源或质量保证。

## 目标

允许一篇在当前任务中已经完整展示并获得用户明确发布确认的正文，作为可追溯的成稿输入进入微信草稿流程，无须再次粘贴同一正文。

本次调整不取消以下门禁：

- 第一次选题或提示词确认；
- 完整正文必须实际存在，只有摘要、审核结论或零散修改时仍停止；
- Agent 事实核验与编辑记录；
- 热点真实图片和图片来源校验；
- 第二次明确发布确认；
- 草稿槽位隔离，不覆盖无关现有文章；
- 推送前质量门禁与微信出口检查。

## 方案

### 新增来源类型

工作流新增 `thread_confirmed_body` 来源类型，中文展示为“当前任务已确认正文”。它与 `deepseek_user_paste` 并列，不能伪装成 DeepSeek 初稿。

新增命令 `record-confirmed-body`，接收：

- 完整正文文件；
- 用户本次明确确认的原话；
- 工作流 ID。

命令只允许从 `prompt_confirmed` 状态进入 `response_received`。正文文件为空、确认原话为空，或只包含明显的审核结论而没有完整正文时拒绝记录。

工作流状态保存确认原话和确认时间，推送前报告明确展示正文来源。旧工作流文件缺少新字段时按空值读取，保持兼容。

### 来源门禁

原 `require_deepseek_browser_response` 调整为更准确的“热点正文来源门禁”，接受三种来源：

- `deepseek_browser`：旧兼容来源；
- `deepseek_user_paste`：用户粘贴的 DeepSeek 初稿；
- `thread_confirmed_body`：当前任务已完整展示并由用户确认的正文。

三种来源都必须保存非空全文。`thread_confirmed_body` 还必须保存非空确认原话。没有正文、只有审核结论或来源字段缺失时继续阻断。

### 文档口径

公众号 Skill 和 DeepSeek 手工交接文档改为：默认仍由用户把 DeepSeek 完整输出贴回；如果完整正文已经在当前任务中出现，并且用户明确要求按该正文发布，可以登记为“当前任务已确认正文”，不要求重复粘贴。不得把摘要、审核结论或 Agent 对文章的转述当作正文。

## 验证

新增和更新单元测试，覆盖：

1. 当前任务已确认正文可以进入 `response_received` 并完成 stage；
2. 确认原话为空时拒绝；
3. 正文为空或只有审核结论时拒绝；
4. 推送前报告显示“当前任务已确认正文”；
5. 原有 DeepSeek 粘贴路线继续通过；
6. 缺失来源、缺失 Agent 编辑记录、未进行第二次确认时仍被阻断。

完成后运行公众号工作流相关单元测试和 Skill 校验器。

## 非目标

- 不取消 DeepSeek 作为用户主动热点默认初稿来源；
- 不允许 Agent 在正文从未完整出现时根据摘要重建正文并发布；
- 不改写已确认正文的事实或立场；
- 不自动发布正式推文，只写入微信草稿箱；
- 不覆盖其他草稿槽位。
