# 公众号单剧强情节推广稿设计

## 目标

新增独立公众号稿型 `short_drama_feature`。系统先从微信短剧推广列表中选择一部预期收益较高且剧情资料可核验的短剧，再围绕该剧生成一篇单剧强情节推荐稿，并插入同一部短剧的一个推广组件。

该稿型以短剧佣金转化为首要目标，同时把剧情准确性设为不可降级的发布门槛。短剧池简介只用于候选发现，不能作为扩写整篇文章的唯一依据。

## 范围

- 新增独立的 `short_drama_feature` 稿型和草稿槽位。
- 每篇文章只写一部短剧，也只插入该剧的一个 `short-play` 组件。
- 只支持手动触发，不进入 `all`、晚间批次或现有定时任务。
- 复用现有短剧池、收益评分、归因建卡、使用记录和草稿回读能力。
- 新增针对单剧推荐稿的候选研究、事实台账、写作模板和质量门禁。
- 不改变 `hotspot`、`hot_business`、`silver`、`tv_review` 及财经稿型的行为。

## 手动入口

干跑命令：

```bash
cd stock-ai
uv run python -m scripts.tools.wechat_mp_draft \
  --kind short_drama_feature \
  --dry-run
```

去掉 `--dry-run` 后，只创建或更新 `short_drama_feature` 对应的独立微信草稿槽位，不调用发表接口。

## 端到端流程

1. 读取仍在有效期内的短剧池；缓存过期时按现有机制刷新。
2. 过滤下架、建卡字段不全、推广计划无效或没有匹配归因数据的候选。
3. 按收益评分排序，形成前三名候选。
4. 按排名逐部开展公开资料研究，并建立结构化剧情事实台账。
5. 第一部通过可写性门禁的候选成为本篇主题；不通过时记录原因并尝试下一部。
6. 三部候选均不通过时结束本次任务，不生成草稿，也不临时降低证据标准。
7. 仅依据事实台账生成 1200 至 1800 字的强情节推荐稿。
8. 对生成稿执行事实逐项核对、文案合规检查和单剧一致性检查。
9. 在正文约三分之二处、完整段落边界后插入同一 `drama_id` 的短剧组件。
10. 非干跑模式将文章写入独立草稿槽位，并从微信草稿回读组件。
11. 仅在回读确认恰好一个目标短剧组件后，记录本次短剧使用。

## 收益优先选剧

候选基础分沿用现有可解释的收益评分框架：

- 佣金占 50%；
- 热度占 30%，先取对数再归一化，避免极少数超高热度候选完全垄断；
- 强情节吸引力占 20%，从剧名、题材和简介识别逆袭、复仇、身份反转、豪门、追妻、家庭冲突、职场冲突等钩子；
- 七天内已经使用的短剧应用现有轮换惩罚；
- 同一部短剧默认不重复生成专题稿，除非后续显式提供允许重写的人工参数。本期不增加该参数。

收益分决定研究顺序，但不覆盖可写性门禁。高佣候选缺乏可靠剧情材料时必须放弃。

## 资料研究与事实台账

### 来源门槛

每部可写候选至少需要两个能够相互印证的公开来源，其中至少一个属于以下官方来源：

- 短剧官方播放页；
- 播出平台或推广平台的剧目页；
- 出品方、版权方或主创的官方发布内容。

第二个来源可以是另一官方页面，或能够明确对应同一部剧的公开报道、节目资料页等独立来源。搜索结果摘要、聚合站自动摘要、无原页转载和无法识别发布主体的营销文案不计入有效来源。

同名短剧必须通过 `drama_id`、播放 AppID、出品信息、角色名、封面或剧情组合证据完成消歧。无法确认时直接放弃候选。

### 事实台账

研究结果保存为结构化台账，至少包含：

- 短剧 ID、规范剧名、来源网址和来源类型；
- 主要人物及其可确认称谓；
- 人物关系；
- 故事起点和核心困境；
- 可确认的冲突升级；
- 可确认但适合用于悬念的第一层反转；
- 明确不能写入的冲突信息、完整结局和未证实细节；
- 每条事实对应的来源编号。

人物、人物关系、核心冲突必须得到两个有效来源的相互印证。只在单一来源出现的细节不能进入正文。来源相互冲突时不由模型猜测，应删除争议事实；若删除后不足以支撑完整文章，则该候选不通过。

### 模型边界

模型可以调整叙述顺序、压缩信息和制造段落悬念，但不得创造事实台账之外的人名、身份、关系、对白、事件、反转或结局。不得用模糊措辞包装未经证实的情节。

## 稿件结构

正文目标长度为 1200 至 1800 字，采用六段式结构。

### 1. 标题

标题直接呈现人物困境和最大冲突，不提前泄露最终结局。禁止使用“全网第一”“所有人都在追”“真实事件改编”等没有证据支持的表述。

### 2. 开场钩子

前三段内交代主角是谁、遇到什么困境以及为何退无可退。开场只能使用事实台账中已经确认的具体处境。

### 3. 冲突升级

围绕一条主线连续推进阻碍，只保留理解故事所必需的人物关系。不得写成演员表、百科简介或逐集复盘。

### 4. 第一层反转

呈现已经核实的身份变化、误会揭露或利益变化，但停在后续结果揭晓之前，以真实信息形成观看缺口。

### 5. 短剧组件

组件插入正文约三分之二处，并对齐完整段落边界。组件前一句停在自然悬念点；组件之后不再完整解释结果。组件中的 `drama_id`、剧名、计划 ID 和归因信息必须与文章主题完全一致。

### 6. 收尾转化

用短段点出该剧最值得继续看的矛盾，并给出明确、克制的观看引导。不得伪造观众评价、播放数据或稀缺性信息。

## 生成后事实门禁

系统在渲染 HTML 前将正文中的人物、关系、事件和反转声明与事实台账逐项核对：

- 未绑定来源的剧情声明视为失败；
- 正文出现台账外的具名人物或关系视为失败；
- 正文把不确定事实写成确定事实视为失败；
- 正文泄露台账标记为“不写入”的完整结局视为失败；
- 标题包含无法验证的热度、排名或真实性声明视为失败。

门禁失败时不自动改写成另一种事实。系统应删除不必要的未证实句子后重新检查；如果删除后文章长度或结构不达标，则放弃当前候选并尝试下一部。

## 干跑诊断

`--dry-run` 不上传素材、不写微信草稿、不更新草稿槽位，也不记录使用。输出至少包含：

- 最终候选的剧名和短剧 ID；
- 佣金、热度、吸引力、使用惩罚和最终收益分；
- 依次尝试过的候选及放弃原因；
- 来源网址、来源类型和同名剧消歧结果；
- 已确认的人物、关系、冲突和反转摘要；
- 标题、正文长度和计划插卡位置；
- 事实门禁、文案合规门禁和归因门禁结果。

诊断不得输出 Cookie、访问令牌、归因票据或其他敏感字段。

## 失败处理

- 短剧池或研究依赖失败：终止本次生成，不写草稿。
- 有效归因缺失：候选不合格，不得伪造组件或回退普通 CPS 商品。
- 三名候选均缺乏可靠剧情资料：返回结构化失败原因，不生成低证据稿件。
- 事实门禁失败且无法通过删除未证实内容修复：放弃当前候选。
- 写入前发现文章主题与组件 `drama_id` 不一致：阻止写入。
- 微信回读不是恰好一个目标 `short-play` 组件，或出现普通 CPS 商品组件：报告失败，不记录使用。
- 草稿已经写入但回读失败：保留微信返回的草稿标识供排障，不把该剧记为成功使用。

## 组件与草稿安全

- 每篇只能存在一个 `data-adtype="short-play"` 组件。
- 不允许普通返佣商品作为失败回退。
- 组件必须复用与候选完全匹配的现有归因链路。
- `short_drama_feature` 使用独立槽位，不覆盖 `tv_review`、`hotspot` 或其他稿型草稿。
- 只有正式保存并回读通过后，才原子更新短剧使用记录。

## 组件边界与代码职责

实现应保持职责分离：

- 现有短剧模块继续负责候选有效性、收益评分、轮换、归因、组件构建和回读校验；
- 新的专题研究模块负责来源发现、同名剧消歧和事实台账；
- 新的专题文章模块负责标题、正文结构和事实约束写作；
- 草稿命令层负责 `short_drama_feature` 路由、干跑诊断、独立槽位和整体失败编排；
- 通用排版、封面、合规和微信客户端能力继续复用现有模块。

研究模块返回结构化结果，不把搜索页面原文直接拼入提示词或公开正文。文章模块不访问推广归因数据，短剧组件模块也不负责生成剧情内容。

## 测试与验收

### 单元测试

- 佣金、热度和吸引力权重正确，七天轮换惩罚生效；
- 只研究收益排名前三的合格候选；
- 第一名资料不足时回退第二名，三名均失败时不成稿；
- 少于两个有效来源、缺少官方来源或同名剧未消歧时拒绝候选；
- 单一来源剧情、台账外人物关系和未证实结局不能进入正文；
- 正文长度、六段式结构和约三分之二插卡位置符合要求；
- 文章主题与组件短剧 ID 必须一致，组件数量必须为一；
- `short_drama_feature` 使用独立槽位且不进入任何自动批次；
- 其他稿型行为保持不变。

### 集成验收

1. 使用当前真实短剧池执行一次干跑。
2. 人工打开所有研究来源，核对剧名、人物、关系、冲突和反转。
3. 对照事实台账逐段检查正文，不允许出现来源外剧情。
4. 确认输出只包含一部短剧，卡片位置处于自然悬念点。
5. 人工确认干跑后生成“勿发”测试草稿。
6. 回读草稿，确认恰好一个目标短剧组件、零个普通 CPS 商品组件，归因字段匹配。
7. 在公众号后台预览排版并打开卡片，确认跳转到文章所写的同一部剧。

## 非目标

- 不自动发表公众号文章。
- 不一次盘点或推广多部短剧。
- 不根据短剧池单段简介直接扩写全文。
- 不抓取或复述完整付费剧集以替代公开资料研究。
- 不新增自动定时任务。
- 不承诺具体佣金收入，也不把收益评分展示给公众号读者。
