# 公众号起稿、返修与交付衔接

生成和表达执行[基座](../../../../docs/writing/中文写作基座.md)，完整创作同时读[主笔职责卡](lead-writer.md)。本页负责文件与任务流转，不另定文风。

## 协调者整理本篇委托

完整新稿或整篇重写，在既有outline.md中设置“起稿交接”，包含：

- 当前用户请求、读者与用途、确认过的标题及信息保留范围。
- 本篇篇幅范围与[计数口径](delivery.md#篇幅约定与计数)。有目标时在起稿前记清，不等到删稿后重新解释目标；没有目标不额外设置字数门槛。
- 事实材料与research.md具体定位、影响当前判断的条件，以及适配参考与不可迁移部分。按基座取舍防误解补句，不把潜在反对者当必交材料。

协调者整理材料和要求，不替主笔设定每段必须证明什么，也不把旧稿、失败全文、审稿自评和工程评分整包传入。参考选择与补采走[外部案例调用](external-article-cases.md#从参考进入当前提纲)。已被用户否定的旧任务撤下，记录当前真正有效的用途。

## 主笔完成内容设计与起稿

主笔在同一outline.md的“主笔内容设计”中落实[职责卡](lead-writer.md#你对什么负责)。先想清已有材料与思考能支撑哪些内容；不能把“输出观点”执行成给资料补好评。协调者不需要用户逐项批准这个内部设计，明确要求先给提纲时按用户顺序执行。

长期反复改稿后的完整重写，有可用且获准的代理工具时，以fork_turns="none"启动一个独立主笔，使用当前模型、不再派生、不对外操作。交当前委托、职责卡和所需文件位置，不传旧全文或预期答案。新稿可由当前执行者承担，标明当前主笔；无代理时同样执行职责，不冒称上下文已隔离。

主笔按基座阶段读取，按自然语意片段实际写入、回读article.md，再续写。将[句意还原动作](../../../../docs/writing/中文写作基座.md#句意还原与自然改写)放在这次回读内，可疑句的真实对照与同类回查简记在现有起稿记录或review.md，不另写一份全文或启动新循环。初稿先核本篇约定的内容和篇幅；明显缺失所需内容或低于范围时继续构思、起稿或补证，不把补足初稿交给审稿者。具备完整初稿后，协调者冻结当前全文及版本，交[四角色审稿](review.md)；意见收齐前不改这一版。

## 意见回到当前主笔

协调者收齐同版意见，汇总原文位置、具体问题与依据，回传当前主笔。沿用其任务继续修改，不新派写手从零起稿，不由协调者静默统稿；工具存在时使用同一代理的后续任务。确需换执行者，按职责卡明确接管并保留当前约定与轮次。

主笔处理意见、修改及补写，再按[基座的内容责任](../../../../docs/writing/中文写作基座.md#完整创作的内容责任)验全文：

| 发现的缺口 | 后续动作 |
| --- | --- |
| 原定内容尚未展开、删改后论述过薄 | 当前主笔继续构思与补写，不用同义解释填数。 |
| 必要事实缺失 | 协调者协助补采，主笔据核实结果入稿。不能用新故事回避原论述不足。 |
| 句法、指代或文体问题 | 主笔修改实际位置，并核受影响的交界及同类问题。 |
| 低于本篇篇幅范围 | 核是哪种内容缺口并处理；不把“不凑字数”当已完成，不自行降低范围。 |

原审稿角色复核受影响内容，事实与文体分别核。补写较多、调序或改观点时扩大到受影响的整体，不仅看新增句；只改一字不重审全文。补写、复核、返还均计入本篇既有修订轮次，不重开一套循环。

## 主笔定稿与协调者验收

主笔在review.md记录意见处理、内容验收、当前版本与未解决项，核全文后同步当前工作文件。协调者对照本篇委托检查内容承诺、篇幅、引用、版本与文件一致性；计数或格式可用工具，观点是否充分、语气是否自然仍看实际全文，不能用分数或关键词通过代替。

未达本篇要求且仍有修订额度，退回当前主笔处理。达到[轮次上限](review.md#轮数与记录)仍有缺口时如实标未完成，列明内容、篇幅或事实缺口，不自动增加轮次或把较短版本宣布完成。满足要求后按[交付页](delivery.md#文件与交付)交付；不新增上传和发布授权。

严格逐句任务使用既有[覆盖记录](sentence-grammar.md#严格逐句检查的覆盖与记录)。当前主笔、版本、已用轮次和状态写在现有review.md，局部任务无需为此新建一套流程文件。试用输出只放临时目录，不覆盖正式稿，不冒充用户正例。
