# 个股诊断自动融合大盘情绪设计

## 1. 背景与结论

现有短线交易系统已经具备 `evaluate_market()`、`ALLOW / LIMITED / FREEZE` 三态规则、`stt_market_states` 表和组合风控门禁，但统一个股诊断入口仍由命令参数传入 `market_status`，默认值为 `FREEZE`。这能防止误放行买入，却没有让每次个股诊断真正使用当前大盘环境。

本功能把大盘状态变成统一个股诊断的自动输入。大盘状态强约束新开仓，只允许维持或降低买入权限；已有持仓的保护性减仓和退出始终优先，不能被大盘状态阻断。

本功能继续只通过聊天响应，不增加看板、定时刷新、推送或自动下单。

## 2. 方案选择

比较过三种实现方式：

1. **复用现有游资情绪周期作为唯一大盘输入**：能快速得到冰点、启动、高潮、退潮等标签，但该模块属于独立游资轨，指标口径与短线规则基线要求的三指数、全市场广度和成交额比不一致，不采用。
2. **新增独立市场状态适配层并复用已有采集与存储**：以短线规则基线为唯一判定标准，使用现有 OpenCLI 指数与全市场涨跌采集、MySQL 日线、证据审计和 `stt_market_states`。这是采用方案。
3. **仅在聊天文案展示大盘情绪**：实现简单，但不能阻止弱市买入，也不能保证缺失数据时安全降级，不采用。

游资情绪周期可以作为解释性标签附加到聊天输出，但不得把 `FREEZE` 升级为 `LIMITED` 或 `ALLOW`，也不得独立放行交易。

## 3. 目标与非目标

### 3.1 目标

- 每次个股诊断自动获取与当前时段匹配的大盘状态，不再要求用户手工传入 `--market-status`。
- 盘前、盘后和非交易日使用最近完整交易日的收盘市场状态。
- 盘中沿用上一完整交易日状态，只允许根据实时广度和强势板块数量降级，不允许因早盘上涨升级。
- 大盘证据缺失、过期、日期错配或来源失败时固定输出 `FREEZE`。
- 诊断结果明确展示市场状态、关键指标、数据时间、降级原因以及它对个股结论的影响。
- 新开仓严格受市场状态约束；已有持仓的 `REDUCE / EXIT` 不受阻断。

### 3.2 非目标

- 不调整既有市场阈值、个股五项门禁、风险预算或仓位上限。
- 不把市场状态变成预测指数涨跌的模型。
- 不新增定时任务；只在用户发起诊断时按需读取或采集。
- 不把游资情绪、单一指数涨跌或单一涨跌停数量作为大盘状态的替代品。

## 4. 市场状态口径

### 4.1 收盘基准状态

沿用《短线交易规则基线 v1》：

- 指数：上证指数 `000001`、深证成指 `399001`、科创 50 `000688`。
- 趋势：统计三个指数中收盘位于 MA20 上方的数量。
- 广度：有效 A 股中上涨数量除以有效股票数量。
- 成交额比：当日全市场成交额除以前一完整交易日成交额。
- `ALLOW`：至少两个指数位于 MA20 上方、广度不低于 50%、成交额比不低于 0.90。
- `FREEZE`：核心字段缺失；或至少两个指数位于 MA20 下方且广度低于 40%；或成交额比低于 0.75 且广度低于 45%。
- 其余为 `LIMITED`。

收盘状态所需指数 K 线通过 OpenCLI 浏览器上下文采集或读取已审计缓存；全市场广度和成交额比优先使用 MySQL 中已完成的 `stock_daily`。未收盘日线不得参与收盘状态计算。

### 4.2 盘中状态

盘中以最近完整交易日状态为上限：

- 昨日 `FREEZE`：今日盘中保持 `FREEZE`。
- 昨日 `LIMITED`：今日盘中最多保持 `LIMITED`，不得升级。
- 昨日 `ALLOW`：实时广度低于 40%且已确认强势板块少于两个时降为 `LIMITED`；核心字段缺失或快照超过 15 分钟时降为 `FREEZE`。

盘中数据使用 OpenCLI 的指数与全 A 涨跌家数快照；强势板块数量使用已验证的行业/题材榜快照。涨停、炸板、跌停和游资情绪阶段只用于生成解释，不参与升级。

## 5. 组件与数据流

### 5.1 市场状态提供者

新增 `MarketStateProvider` 接口，对诊断运行时隐藏采集与缓存细节。输入为带时区当前时间和交易时段上下文，输出统一的市场状态视图：

- `status`：`ALLOW / LIMITED / FREEZE`。
- `trading_date`、`as_of` 和 `expires_at`。
- 三指数 MA20 关系、广度、成交额比、强势板块数量。
- `reasons`、`quality_flags` 和证据引用。
- 可选的解释性游资情绪标签。

提供者先读取同一交易日最新有效的 `stt_market_states`；满足时段和新鲜度要求时直接复用。没有有效快照时按需采集、计算、写入证据及市场状态，再返回结果。采集失败返回可审计的 `FREEZE`，不抛出后由调用方猜测状态。

### 5.2 仓储扩展

在现有市场状态仓储上增加“按交易日读取最新有效状态”的查询，不改变既有主键和不可变写入方式。原始市场字段写入 `stt_evidence_snapshots` 的 `market` 证据，`stt_market_states` 保存判定结果、原因和引用。

现有表结构足以承载本功能；若实现阶段发现字段契约无法完整保存三指数明细，明细只进入证据 JSON，不为展示字段新增重复列。

### 5.3 诊断运行时接入

`DiagnosisRuntime` 注入 `MarketStateProvider`。统一个股入口不再用默认 `FREEZE` 的命令参数构造市场门禁，而是在完成交易时段分类后取得相应市场状态：

1. 分类交易时段。
2. 获取该时段对应的市场状态。
3. 读取持仓、日线、筹码和个股实时证据。
4. 先执行持仓硬失效检查，再执行市场与组合门禁。
5. 生成唯一主结论，并附带市场状态摘要。

CLI 可以保留显式市场状态覆盖能力，但仅供测试和历史复现，必须改成名称明确的测试参数；正常运行不接受人工把市场状态升级。

## 6. 信号影响规则

### 6.1 新开仓

- `ALLOW`：继续执行组合风险和个股五项门禁，不代表直接可以买入。
- `LIMITED`：最多一个新计划，单票金额上限按现有规则收缩到交易预算的 2%。
- `FREEZE`：新开仓固定 `NO_TRADE`。

### 6.2 已有持仓

- 硬失效价触发时直接输出 `EXIT`，不检查市场是否允许卖出。
- 个股走弱但未触发硬失效时，大盘由 `ALLOW` 降为 `LIMITED / FREEZE` 可以提高 `REDUCE` 优先级。
- 大盘转强不能把个股 `EXIT / REDUCE` 升级为 `HOLD`，也不能覆盖个股资金、板块、盘口或失效证据。
- 大盘数据缺失时仍允许保护性退出；缺失只冻结新增风险。

## 7. 聊天输出

每次诊断在个股结论之前增加一段市场环境：

```text
大盘环境：LIMITED（数据截至 09:42）
依据：三指数 1/3 位于 MA20 上方；上涨家数占比 43%；成交额比 0.86；强势板块 1 个
对本股影响：禁止加仓；已有持仓的退出纪律不变
```

输出必须区分事实、规则结果和解释性情绪标签。旧快照只能显示“上次有效值及时间”，不得参与放行。

## 8. 失败与安全降级

- 交易日历不可确认：市场 `FREEZE`，不采集或生成盘中买入许可。
- 收盘指数 K 线不足 20 根、全市场日线不完整、成交额单位不一致：市场 `FREEZE`。
- 盘中指数、广度或板块快照超过 15 分钟：市场 `FREEZE`。
- 代码、日期或页面身份校验失败：记录采集失败证据并 `FREEZE`。
- MySQL 不可用：个股诊断继续返回不可交易结果，不使用命令默认值伪装成有效市场判断。
- OpenCLI 失败：不回退到 Python 直连东财；记录失败并安全冻结新增交易。

## 9. 测试与验收

采用测试先行，至少覆盖：

- 收盘 `ALLOW / LIMITED / FREEZE` 阈值和边界值。
- 盘中只能维持或降级，不能升级。
- 市场证据缺失、过期、日期错配和单位异常均为 `FREEZE`。
- 市场状态缓存按交易日和时段选取正确快照。
- 统一个股诊断默认自动调用市场提供者，不再依赖人工 `--market-status`。
- `FREEZE` 阻止新开仓。
- `FREEZE` 不阻止已有持仓触发 `EXIT`，且硬失效检查优先于市场门禁。
- `LIMITED` 正确收缩新开仓名额和金额。
- 聊天输出包含市场状态、指标、时间、影响和降级原因。
- OpenCLI 采集使用解析样例测试，不在单元测试中访问网络。
- MySQL 集成测试在事务内验证市场证据、状态写入与最新有效读取，不留下测试数据。

验收时再次诊断合锻智能：结果必须展示自动计算的大盘环境；若市场数据无法取得，明确显示 `FREEZE` 及缺失原因，同时仍能给出现有持仓的保护性退出方案。
