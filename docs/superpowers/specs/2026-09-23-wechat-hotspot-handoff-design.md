# 用户主动热点：证据、配图与草稿交付架构

日期：2026-09-23  
状态：设计已获口头确认，待书面复核；不改变现有草稿。

## 要解决的问题

2026-09-23 的酒店月租稿在入草稿前暴露了四个断点：客房数、企业动作和房源起价最初缺少逐项回源；报道相邻的两张图片中，房型画面容易被误当作价格截图；当前任务已经展示并确认全文，流程仍要求补一次提示词确认；首次草稿写入因本地网络出口预检失败而中断。这些问题分别位于写作、图片和交付环节，却需要同一次推稿决策处理。

本次只升级用户主动 `hotspot` 的既有 Skill 与对应门禁，不改定时稿、其他稿型、公众号群发规则，也不重写微信客户端。目标是让下一篇稿能回答：关键事实凭什么写、图片画的是什么、用户确认了哪一版、入草稿失败该从哪里续跑。

## 方案选择

- 只补 SOP：改动小，但确认状态和图片语义仍完全靠操作者记忆。
- **采用薄交付层**：保留现有文章 JSON、图片清单与推稿脚本，在它们之间加一份交付记录，并补少量校验与状态分支。能覆盖本次故障，影响面有限。
- 重写完整流水线：可统一所有稿型，但会触及现有定时、素材和草稿逻辑；本次没有必要。

## 职责边界

`wechat-mp-everyday-economy` 负责选题与经济解释，输出可核查的事实和推断，不管公众号草稿。`wechat-mp-writing` 负责正文、证据归属、时间口径与语言审校，不负责传图和微信 API。`wechat-mp-drafts` 负责图片、确认状态、预检、草稿写入与写后状态验证，不替写作层重判文章立场。三个入口只共享交付记录，不互相复制整套规则。

新交付记录暂名 `editorial_handoff.json`，由当前用户主动热点工作流持有，引用已有 `article.json`、`douyin-search.json`、`figure_sources.json` 和 `cover_source.json`，不重复正文与图片二进制。字段仅包括：工作流 ID、稿型、文章文件路径与摘要校验值；关键主张列表；图片选择与视觉核对结果；确认方式、确认原话和被确认正文的摘要校验值；当前交付状态及失败分类。稿型之外的通用文章不强制生成这份记录。

## 事实与时间口径

关键主张清单只覆盖标题、导语、关键数字、企业或政策动作、文章结论依赖的事实，不要求每一句常识性解释逐字登记。每条记录原文主张、来源页、发布日、事件或数据期、核对日、主张类型和正文对应位置。主张类型至少区分原始事实、被报道的页面快照、受访方说法、作者推断。页面快照必须以“报道时／页面当时显示”入稿，不能自动升级为实时价格或当前库存；作者推断不得归属给原始报告。

编辑前核对主张清单与正文；任一标题前提或关键数字无法回源时，修改或删去主张，而不是用更多转载站凑来源数。维持现有多来源域要求，但来源域数量不能代替对关键主张的逐项核验。

## 图片选择与核验

继续执行抖音搜索卡片优先、只看卡片与封面、不打开视频；无合格图时记录原因，再用可追溯的原报道或官方证据图。保持最多三张正文图；合格图总数不超过三张时全部进入正文，并选其中一张兼作封面。

`figure_sources.json` 的每张入选图除原有来源字段外，增加画面内容简述、人工视觉核对时间和该图在文章中的用途。视觉核对要看实际图片文件，不凭网页相邻图注推断内容；价格截图应能读出地点与价格，实景照不得被标成价格证据。新建的用户主动热点交付记录必须指向已核对的入选图；未列入清单的同目录 `still-*` 文件不得被自动送入正文。封面与正文复用沿用现有逻辑，不重新下载或复制成不同图片。

## 确认与写入状态

保留两条合法入口：

1. 标准 DeepSeek 手工交接：研究 → 提示词确认 → 用户贴回全文 → 核验编辑 → 用户确认 → 草稿。
2. 当前任务已展示全文：研究 → 登记完整正文与用户的明确确认原话 → 核验编辑 → 草稿。此分支不伪造提示词确认，但须记录正文文件摘要校验值和确认方式。仅审核结论、摘要或零散改动不能充当完整正文。

两条入口都只能写入草稿箱，不自动群发。`stage` 应输出事实核对、图片核对和质量未通过项的摘要；单独的“5/7”不能替代可解释的失败项。推送前核对被确认正文与当前待写正文的差异；只允许事实归属和措辞等已向用户说明的必要编辑，重大立场或标题变化需重新确认。

微信 API 出口预检失败归类为环境失败，保留 `staged` 与用户确认，不回退写作步骤，也不再次上传已成功的素材。操作者可在获准的网络环境以同一工作流重试一次；若仍失败，则停止并报告出口信息的必要摘要，不输出凭据。不得以临时关闭预检、修改白名单或更换未核实账号作为回退。

## 验证与验收

- 单元测试：关键主张时间类型不能缺失；页面快照不能被标为实时价格；未完成视觉核对的图片不进入新工作流；封面为两张正文图之一；已确认全文可从研究状态直接进入登记，标准手工交接仍要求提示词确认。
- 干跑：取本次月租稿及两张报道原图，验证事实、图片、正文摘要与用户确认记录一致；不向微信写入。
- 失败续跑：模拟出口预检失败，确认工作流保持可重试状态且正文和图片审核记录不丢失；模拟第二次失败，确认停止而非无限重试。
- 文档校验：运行 skill-creator 的 `quick_validate.py`，检查三个 Skill 入口的路由和引用；只读核对现有定时稿与其他稿型未受影响。

完成标准：同类稿件无需虚构一次“提示词已确认”；三处关键事实能独立回源；图片内容与图注一致；草稿失败后能从交付状态安全续跑；用户看到的是草稿成功或明确的失败原因，而不是工具内部阶段名。
