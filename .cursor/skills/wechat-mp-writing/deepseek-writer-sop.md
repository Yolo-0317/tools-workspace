# DeepSeek 写稿分工

2026-10-12配图更新：人工热点深评停止抖音检索，按[热点视频截帧规则](../wechat-mp-writing/hotspot-deep-review.md#配图原报道视频截帧)与[通用截图流程](../wechat-mp-article/references/real-video-stills.md)查原报道视频并下载核对；一条视频的不同合格镜头即可供全部配图。下文旧抖音卡片及douyin-search字段仅作尚未适配的旧工程说明，不作为当前取图任务，不能伪造记录。


> **适用**：用户明确指定 DeepSeek 的热点深评，以及沿用既有交接的文学/典籍稿。2026-10-12人工热点深评默认改为 [通用写稿](../wechat-mp-article/SKILL.md)，未指定 DeepSeek 不进入本流程。
> **Agent**：研究、定题、给提示词，并在推送前完成事实编辑。
> **DeepSeek 交接**：Agent 只把完整提示词交给用户；用户自行与 DeepSeek 交流并贴回输出。
> **两次确认**：提示词交付前一次，微信草稿写入前一次。

## 默认流水线

```text
Agent 研究并定题（钉子、禁假钩子、32字内）
  → 展示来源包和完整提示词，等待第一次确认
  → 用户自行把提示词交给 DeepSeek，并将完整输出贴回当前任务；当前任务已有完整正文并获明确发布确认时可直接登记
  → 正文尚未完整出现时暂停，不调用 DeepSeek，也不回退其他模型代写
  → Agent 核事实并编辑，在原句里包 2～3 处 [[hl:…]]；热点先查抖音搜索卡片封面
  → 展示 DeepSeek 来源、Agent 编辑记录、标题、摘要、字数、来源、真实图片与门禁报告，等待第二次确认
  → hotspot 写目标热点槽位；文学/典籍写 literary 独立槽位
```

Agent 禁止打开、绑定、操作或检查 DeepSeek 网页，禁止调用 DeepSeek API、OpenCLI DeepSeek 浏览器写稿命令或其他自动发送方式，也不处理 DeepSeek 登录状态、Cookie、会话 ID。DeepSeek 交流完全由用户完成。默认输入是用户贴回的完整输出；若完整正文已经在当前任务中完整展示，且用户明确要求按该正文发布，可登记为“当前任务已确认正文”。审核结论、摘要、零散修改或 Agent 转述不能替代完整正文。禁止回退其他模型代写初稿。

## Agent 定题时交什么

- 一句话钉子（本篇只讲一件事）
- 建议标题方向（热点用实体/反常结果；文学用场面/代价/数字；禁作者「我」）
- 轻量 prompt（下面模板，按集替换）
- 不要塞语料库全文

## 热点深评 prompt（完整复制给用户）

用户主动热点的文章声音与文章级改稿以 [essay-commentary-craft.md](essay-commentary-craft.md) 为准。普通消费等低伤害题材可以按 [humor-punchline-craft.md](humor-punchline-craft.md) 选择轻诙谐语气；伤亡、疾病、未成年人受害等保持平实。以下提示词不要混入事实包中的审校指令。

普通人的经济生活题先按 [专门研究 Skill](../wechat-mp-everyday-economy/SKILL.md) 核实事件、人群和账目；提示词可另列“算账输入、公式、遗漏成本”。已核事实栏只放正面事实与来源，风险、禁止项和文风要求仍放在“要求”中，不能伪装成事实材料。

```text
写一篇微信公众号热点深评，正文目标900—1100字，纯段落，不要小标题。信息复杂时允许略超1100字，但要优先精简，不为凑字重复观点。

主题：【具体热点】
核心判断：【一句可被反驳和检验的判断】
主要读者与想说的话：【写明本题替谁发问，以及他面对已核实事实最想问或最想反驳的那句话；这是写作角度，不是采访引语】
语气选择：【平实或轻诙谐；普通消费、价格、服务体验等低伤害题材可选轻诙谐，严重伤害事件选平实】
已核实事实与来源：【只放本次研究得到的事实、时间线、法条和链接】
当事方说法与待核信息：【分别标明谁说了什么、哪些信息尚无最终结论；没有则写“无”】

要求：
1. 直接产出标题和初稿；第一行标题，空一行后写正文
2. 标题32字以内，前15字出现可搜索实体或案由，不用震惊体
3. 开头50字内落地谁、在哪里、发生了什么；区分事实、当事人说法和待核部分
4. 不编造采访、场景、引语、动机或内部信息，不把推断写成定论
5. 用已核实的一件事或一个数字引出读者真正想说的话，尽早替他把疑问、委屈或不满说清楚；不要先写一篇四平八稳的政策问答，再在结尾补一句态度。让新细节或后果推动段落转折，不套固定论证顺序，不写“值得注意的是”等导读腔
6. 有证据时敢于批评具体行为、安排或信息落差；不把“尚未认定违法”写成“读者不能批评”。同样不能把作者推测写成所有读者的心声，不能虚构亲历、采访、引语、动机或已发生的损失。普通人的代价须有依据，风险用条件表达，保留已有配套、地域与对象限定；事实推翻读者猜想时如实解释，不为维持立场删事实
7. 像一个熟悉此事的人替读者发问、把道理说透，不像政策编辑、客服或事实核查员。不要把完整中文压成新闻提要，正常保留“来看、来说、已经、并没有、等到、至于”等让语气完整的成分；也别省掉表达追问和态度的“就、还、也、才、倒”等小词，以及承接上文的“这、那、问题是”。“啊、呢、吧、吗”等句末语气词只在读者真会这样说时使用，不按数量添加。少用“业务状态、相关情况、有关安排、执行层面、核心逻辑”等抽象词。需要说明“目前没有结论”时，把边界自然写进事情里，不写“这些回应只能说明……”“不能据此认定……”“后续执行情况仍待观察”等审稿腔
8. 不追求句句有力，不连续使用“不是……而是……”、对仗、反问和单句成段。允许普通句子平静地说明事实，关键判断却要把读者真正想问的话说透；不要另起一句“不能代表全国”“仅供参考”替正文做免责声明。需要限定时，把时间、地点和对象写进事实句。交稿前逐段读出声，检查语法是否完整、态度有没有被压没、上下句能否自然接上；凡是现实中不像一个人会完整说出口的句子都要重写，但不得删掉事实限定，也不要把每句都改成带语气词的吐槽
9. 若选轻诙谐，让已核实的数字、物件或实际花费先铺垫再转弯，包袱落回读者的生活选择；不要写成双人对话或每段一个笑话，不编造顾客、家长、客服原话，不拿受害者和弱势处境取笑。若选平实，不为了凑风格硬加笑点
10. 风格参考只用于学习表达，不得拿来补事实；当事方说法写明主体，待核信息不得改写成确定结论
11. 只输出标题和正文，不写写作说明、来源列表或配图建议
```

## 文学/典籍轻量 prompt（完整复制给用户）

```text
写一篇微信公众号讨论稿，约800字，纯段落，不要小标题。

主题：【钉子，如：典籍里的中国·尚书·伏生护书】
标题：32字以内，不要作者「我」；数字必须属实（尚书是二十八篇，不是二十八个字）。
写作视角：先想清楚读者看到这段故事或典籍时最想追问、惋惜或感到好奇的是什么，替他把感受说准确；不把文学文章强行写成投诉或控诉。

要求：
1. 第一段必须是戏里场面+对白+现场一个人的反应，不要用「某年某月开播」开头
2. 叙事人隐形；戏里台词可以有「我」
3. 不要安利、不要「我哭了」、不要升华口号
4. 结尾可停在一句问号上，再加一句轻互动（评论区聊聊…）
5. 只输出：第一行标题，空一行，然后正文
```

## DeepSeek 返回初稿后 Agent 做什么

1. 接收用户贴回的完整 DeepSeek 输出；若当前任务已经完整展示正文并获明确发布确认，可记录正文和确认原话，无需再次复制。正文尚未完整出现时暂停。
2. 热点稿完整读取 [editorial-evidence-gate.md](editorial-evidence-gate.md)，在内部区分可核事实、当事方说法、解释性判断、作者观点和暂不可核实信息；文学/典籍稿另核开篇是否有具体场面。
3. 核验标题、数字、人物、时间、引语、适用范围和来源独立性。编辑为结构化终稿，在原句里包 2～3 处 `[[hl:…]]`，补至少三个公开来源域，并以可重复的 `--edit-note` 记录核实和改动。不同域名若共同转述同一原始材料，不得当成三次独立印证。
4. 先看标题承诺是否兑现、正文有没有把读者最想说的那句话说透，以及段落是否随证据向前走，再逐段朗读调整句子长短与停顿。每段应增加事实、解释、边界或判断，删除同义复述；回应最强合理异议，不机械安排两派观点或固定数量金句，也不删必要限定。朗读时检查完整句式、态度小词和上下文承接有没有被省掉；句末语气词只在语境需要时使用，不按数量补。遇到“业务状态、相关安排、不能据此认定、仍待观察”等抽象兜底表达，先确认它在限定什么，再把限定改写进具体的人、动作和时间里；不做机械替词。轻诙谐稿另查包袱是否从已核事实生出、是否嘲错对象，以及删掉包袱后主线能否成立；平实稿不补笑点。
5. 用户主动热点配图必须先检索抖音，只查看搜索结果卡片与封面，禁止打开或播放视频；再按需补政府官网、官方媒体或法条页面证据图。合格真实图总数为 1—3 张时全部进入正文，其中一张同时作为封面；超过 3 张时正文最多 3 张。零图停止，禁止任何自动生成图片或 `codex-image-request.json`。
   新工作流对入选图逐张打开实际文件，记录画面简述、核对时间和用途；同时为标题、导语、关键数字与结论依赖事实建立 `editorial_handoff.json`。不能凭网页相邻图注认定图片内容，也不能把报道时的价格快照写成当前价格。
6. 暂存终稿并展示 DeepSeek 来源、Agent 编辑记录、标题、摘要、字数、来源、封面与正文图数量，以及“本稿未自动生成图片”，等待第二次确认。
7. 用户确认后才登记推送许可并写入微信草稿箱：热点写指定热点槽位，文学/典籍写 `literary`。

用户贴回初稿后的暂存与推送命令：

```bash
cd stock-ai
uv run python -m scripts.tools.wechat_mp_browser_write stage \
  <workflow-id> --article <edited-json> \
  --handoff <editorial_handoff.json> \
  --edit-note "核对关键事实与来源" \
  --edit-note "删除无法回源的推断"
uv run python -m scripts.tools.wechat_mp_browser_write confirm-push \
  <workflow-id>
uv run python -m scripts.tools.wechat_mp_browser_write push \
  <workflow-id>
```

当前任务已经完整展示正文并获明确确认时，先登记正文来源：

```bash
uv run python -m scripts.tools.wechat_mp_browser_write record-confirmed-body \
  <workflow-id> \
  --response-file <full-body-file> \
  --confirmation-text "就按照刚刚的正文发布"
```

`confirm-push` 只能在用户第二次明确确认后执行。`push` 失败时保留在 `push_confirmed`，修复网络或微信白名单后可重试，不重复生成正文。

## 禁止的自动写稿路线

`scripts.tools.wechat_mp_deepseek_write`、`scripts.tools.wechat_mp_deepseek_browser` 以及 `wechat_mp_browser_write write` 均不属于本流程。热点深评和文学/典籍稿不得用任何自动化方式把提示词发给 DeepSeek，也不得绕过两次确认。

推稿代码：`scripts/tools/wechat_mp_browser_write.py`（仅用于用户贴回稿件后的暂存、确认和写草稿，不执行 `write`）
规律沉淀：`stock-ai/data/wechat_mp_reference_corpus/dianji-zhongguo/distilled-patterns.md`
