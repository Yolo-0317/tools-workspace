# 语文基础知识库建设方案

2026-10-24。状态：设计稿。用户要求扩大到基础常用词语，当前仅完成五词示例，本方案不代表新增词条、数据导入、检索程序或批量审核已经实施。

## 目标与范围

建立能供模型查阅的现代汉语用法知识库。覆盖目标从已确认的基础常用词清单逐项展开，最终补齐清单中的常用义项、使用条件、搭配及近义差别。分批建设是工作次序，不把首批几百词当作“全部建完”。

“全部”的边界由有版本的词表确定，不以模型临时想到哪些词为准。区分词目数、义项数、用法卡数：一个词可能有多个意义和多种用法，不能一词一条释义就宣称完整。人名、地名、古语、专业术语、临时热点词另分范围，不能因为在某份大词表中出现就全部视为日常基础词。

用途以日常交流、公众号、小红书及普通说明文为主；正式文体保留必要正式程度。知识库是检索参考，不是模型训练，也不能保证只靠参考就消除所有文风问题。

## 建设方式选择

| 路径 | 作用与问题 | 决定 |
| --- | --- | --- |
| 手写少量高频词说明 | 容易启动，但目录随改稿零散增长，无法知道整体覆盖情况 | 保留现有成果，不作为最终组织方式 |
| 整本词典搬入提示词 | 体量大，释义不等于用法；还涉及内容使用条件，整篇加载会干扰写作 | 不采用 |
| 版本化完整目录＋分层用法知识＋按需检索 | 能追踪范围和缺项，区分义项与语境，优先完成最影响写作的部分 | 推荐 |

## 一、建立哪些知识

| 层次 | 收录内容 | 解决的问题 |
| --- | --- | --- |
| 词汇目录 | 词形、读音或异读、来源词表、词类、常见程度及建设状态 | 是否收录、是否常用、还有哪些缺项 |
| 词与义项 | 常用意义、义项下词性、适用对象、语境条件、程度和范围 | 一个词在这句话里实际表达什么 |
| 搭配与近义组 | 动宾/主谓/修饰搭配、可替换处与不可替换处、易混词比较 | 为什么每个字都认识，放在一起却别扭 |
| 句式与篇章关系 | 完成和变化、持续、否定、因果、条件、让步、比较、指代与省略 | 用词正确后，句子及上下文是否成立 |
| 实际改稿案例 | 原句、已知上下文、修改、改变的含义、用户确认状态 | 怎样应用知识，不把一次改稿变成普遍规则 |

分类同时使用词性和表达功能两种索引。一个词可跨多个分类；“是”在不同结构里不能只凭词头定用法。关系卡引用词义卡，不反复复制定义。

优先建设的功能分类：

1. 持续、重复与时间顺序：还、还是、仍然、已经、曾经、正在、又、再、先、才、就等。
2. 转折、让步与补充：但是、不过、可是、却、虽然、即使、尽管、而且、也、甚至等。
3. 因果、条件与目的：因为、所以、因此、如果、只要、只有、为了、以便等。
4. 否定、程度、范围与数量：不、没、未、很、太、比较、更、最、只、都、各、每、约等。
5. 可能、能力、意愿与义务：能、会、可以、可能、愿意、应该、需要、必须等。
6. 助词、指代、介词与数量结构：了、着、过、的、地、得、呢、吧、啊，这、那、其，对、把、被、给、从，及常用量词。
7. 常用实词：日常人物、物件、动作、状态与评价；重点补看/看到/看见、听/听到/听说、了解/认识/知道等常见区别，以及生硬搭配的实际案例。

这只是建设分组，不是已核实的完整词表；正式清单从来源数据归并后生成。

## 二、范围与来源各负什么责任

| 用途 | 优先依据 | 限制 |
| --- | --- | --- |
| 词目范围 | 权威常用词表；教育词表用于交叉核对基础层 | 字表不是词表；面向外国学习者的等级也不能直接当作母语写作难度 |
| 意义、词性与基本用法 | 有权限查阅的现代词典、虚词词典、语法教材及语言学资料 | 逐项记录版次和阅读范围，不能抄整本或以搜索摘要冒充正文 |
| 常见搭配和语体 | 现代口语、新闻、文学等分域语料 | 词频只作观察；出现过不等于规范，零命中也不能证明错误 |
| 当前账号口吻 | 用户已确认正例及本篇读者关系 | 只影响适用语境中的表达选择，不覆盖语义和事实 |

候选来源：

- 《现代汉语常用词表》第2版：厦门大学中文系出版介绍明确收录56790词。可以作为广覆盖范围参考；本轮只读出版介绍，未取得该版完整数据或导入许可。不能拿草案或第三方转录冒充已核实的第2版。
- 《国际中文教育中文水平等级标准》：教育部发布页可作为标准身份依据，后续核其词表及版本，用于基础层交叉核对，不能直接移作母语词汇总表。本轮检索返回发布说明，直接打开超时，未读取附件。
- BCC语料库：已实际阅读官方帮助的相关章节，具备按新闻、文学、口语等频道查上下文及词频的能力；数据实际下载、授权要求和查询结果另行记录，本轮未做实例采集。
- 现有五词的官方词典来源继续保留。大陆普通话用法优先用相应来源交叉核实；古义和地区用法明确标注，不把某地习惯或某本辞书分类视为唯一答案。

每份资料记录来源ID、名称、版本、URL/页码、可访问范围、获取时间、使用条件和实际采用范围。网站可访问不等于允许整站采集；先核使用条件，再决定导入方式。无法取得的资料只登记待核，不用模型自动补齐成已核实内容。

## 三、词条怎样组织

按“词目→义项→具体用法”组织，关系和搭配另建卡片。以下是未来数据结构的设计字段，不是已实现接口：

| 字段组 | 内容 |
| --- | --- |
| 身份 | 稳定ID、词形、读音、异形及简繁映射；不把异体、异读或不同词强行合并 |
| 来源与状态 | 所属词表及版次、来源链接、读取范围；候选/待核/有争议/已核/停用 |
| 义项 | 常用意义、该义项的词性、适用对象、时间/程度/范围等语义标签 |
| 语境 | 需要什么背景；可以由上文提供还是必须写明；不适用情形 |
| 结构和搭配 | 常见句中位置、共现结构、动宾或修饰关系；离合及否定位置等必要说明 |
| 比较 | 近义组ID；哪些条件下可换，换后程度、持续、语气或判断可能怎样变化 |
| 例句 | 带简短上下文的示例；必要时用只改一个因素的对照组；标注自编/语料/用户改稿 |
| 风险 | 可能新增的因果、持续、比较、态度或规范强度；确有依据的误用及修复条件 |
| 证据性质 | 辞书明确说明、语料观察、编辑归纳、用户局部偏好分别标记 |
| 追溯 | 修改日期、修改原因、核对资料、相关案例和冲突说明 |

不强求每个普通名词都有一组“易错用法”，也不为了字段齐全编造错误例子。没有必要的信息可为空并说明不适用；没有证据的信息必须保持待核。

一条词的词性可随义项不同，不用一个词性字段覆盖全词。语气强弱、书面/口语倾向须有适用范围，不建立“仍然一定正式”“不过一定比但是弱”之类绝对表。

“还是”示例：持续、选择、建议分别建用法；“读了一遍，还是没懂”与“坐车还是走路”不是同一种知识。用户喜欢“还是写不出”的口吻，并不证明某学生写不出，语义知识不能代替新闻取证。

## 四、文件与检索设计

推荐使用结构化词条作为唯一内容数据源，生成便于人读的Markdown和机器索引。基座仍是写作规则唯一真源；词条数据的真源不是第二份写作规则。

未来目录按需建立：

```text
语文基础知识库/
  README.md             入口和使用范围
  建设方案.md            本方案
  sources/              来源登记与词表版本说明
  data/                 分批结构化词条、关系及搭配卡
  indexes/              自动生成：按词、义项、关系、近义组定位
  views/                自动生成：供阅读的分类页面
  cases/                改稿案例及用户确认状态
  evaluation/           对照句和整段验证记录
```

初期用本地JSON/JSONL和关键词索引即可，无需先搭服务器或向量数据库。先解决精确找词、别名、近义组和关系标签；只有实际检索失败证明有需要，再增加语义检索。现有Markdown五词先保持可用，迁移完成并验证后再作为生成视图替代，不同时手改两份内容。

两种查询入口：

- 按词查：输入“还是”，返回义项和必要近义差别，不把所有解释一股脑塞进正文上下文。
- 按句查：输入原句、相邻上下文及写作目的，先识别可能的关系，再召回对应词义、搭配或关系卡。找不到就明确未知；命中多个义项时保留候选，不强行选定。

不靠自动分词给所有字强配词义；多字结构和多义词先看整句。检索结果只提供依据和候选修改理由，不直接执行全局替换。

## 五、建设步骤与分批次序

1. **先固定边界和样本**：核来源可用性，建立带版本的候选词表、筛选口径及来源登记。将现有五词迁移为样本，再扩到约20个不同类型的词，检验多义、搭配、近义和语气字段是否够用。
2. **建立完整目录**：对选定范围去重、规范词形、保留来源映射，生成完整建设清单。每个词都有状态；此时可报告目录覆盖，不能报告知识已完成。
3. **优先补高影响用法**：第一里程碑约100—200个虚词、常用副词、情态词和易混组，重点覆盖否定、时间、因果、条件、程度、语气。数字是排期规模，不是语言学上的固定常用词数量。
4. **扩到常用实词与搭配**：先做到约1000词，再到约5000词的阶段里程碑，按基础词表、分域词频和实际改稿问题确定先后；词频不能单独决定优先级。每批可安排20—50词，按多义复杂程度调整，不强求每批同量。
5. **补齐其余选定范围**：继续完成清单余项及其常用义项；低复杂词保留必要内容，高复杂词补足用法。范围外的新词另入候选队列，不静默改变总量分母。

每批执行：确定本批词及义项范围→查资料→编写释义/语境/对照→核证据与表达→检查索引及引用→验证代表句段→入已核库。自动化负责目录、重复、字段、链接和状态统计；不能把程序通过当作语言知识正确。

模型生成的内容先为草稿，不因能输出完整JSON就进入已核层。资料不足或冲突时记待核/有争议，不为了完成率强行消解。每批通常一次编写、一次统一校核；发现具体问题再修，来源仍不确定的暂缓，不设无止境润色循环。本方案不创建自动调度，也不擅自增加其他专题的审稿人数或轮数。

## 六、怎样证明它有用

分别验证资料、程序和写作效果。

- 资料：义项和定义有对应来源；语料观察保存语境；编辑归纳与用户偏好不冒充普遍语法。
- 程序：ID不重复，引用能定位，索引对应实际文件，状态统计不把候选当完成，生成视图与词条源一致。
- 语言：用同一句及明确上下文比较替换前后；既放应改的例子，也放原本正确、不该改的例子，检查是否误改和增加事实预设。
- 写作：用几段相同材料、相同文体的真实改稿，比较加入参考前后的错误和变化。考察具体的语义变化、搭配、口吻及承接，不用“AI味分数”或新增语气词数量证明效果。

初期验证应含：还/还是、又/再、才/就、也的承接对象、不/没、可能/能够、应该/可以、了的状态变化、但是的转折依据，以及一句有上下文才能判断的例子。它们目前只是拟用测试主题，未标为已建词条。

完成报告同时列出：选定范围词数、已入目录数、已核词数、已核常用义项数、重点用法卡覆盖、待核和争议项、具体测试结果。词目有记录不等于义项完整；达到5000词也不等于“全部常用词建完”。

## 七、怎样接进写作

基座保留入口和适用边界，公众号、小红书等Skill引用基座，不各复制一库。

起稿前按文章涉及的关系和既往问题加载少量相关资料。写一段、保存并回读时，具体到“这个仍然是否补进持续状态”“这个也的对象是谁”等疑点再查相关用法；无疑点时不逐词查库。正式稿依旧执行既有事实和文体分查。

修改时保护主体、时间、范围、程度和归属；知识库给得出近义词，也不代表本句需要换。用户已经确认结构时，语气问题先在原结构内解决。需要额外事实才能支持的改句，不能用语言参考补造依据。

方案编写时仅完成设计；截至2026-10-25，已完成首批20词结构验证并扩至1000词，具体状态见README及扩充检查。文章修改、推草稿和安装服务不在本次词库任务内。
