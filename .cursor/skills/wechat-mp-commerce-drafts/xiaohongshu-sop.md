## 一、定位（仅小红书）

| 项 | 内容 |

## 二、运营节奏（独立号）

| 阶段 | 频率 | 备注 |
|------|------|------|
| 冷启动 4 周 | **周 3～4 条**，同版式、同垂直 | 前 12 条：厨房 3 → 清洁 3 → 环境 3 → 个护 3 |
| 稳定期 | **周 3 条**；收藏/数据差 → **周 2 条** | 停更 >10 天伤搜索权重 |
| 时段 | 12:00–13:30 或 20:00–22:00 固定 | 与微信 20–22 可错开 1～2h 做对比 |

**单条结构（推荐）**：

1. 情绪 20%：处境 2～3 句（插排满、台面窄、怕吃灰）  
2. 理性 60%：三类容易买错的 + 两类通常更值的  
3. 安放 10%：买前对照三件事（收藏核心）  
4. 互动 10%：场景问句 + **合作推广/佣金** 披露  

标题公式（沿用 brand）：`[租屋/合租/单间] + [品类] + [结果/避坑]`  
话题：`#租房好物` `#小家电` `#避坑` + 当周品类词，≤5 个。

**分发**：搜索（场景词+品类词）+ 收藏率 > 点赞；首图清单感。  
**指标（只看小红书）**：搜索来源占比、收藏/曝光、挂链点击、违规次数；**不看**公众号完读/搜一搜。

**人力粗算**：图文约 1.5～2h/条 → 周 3 条约 5～6h。

## 三、收益（仅小红书闭环）

| 路径 | 阶段 | 说明 |
|------|------|------|
| 笔记挂链 / 店铺 CPS | 粉丝几百后即可试 | **一篇只推 1 品类 1 SKU**，与正文一致 |
| 蒲公英报备商单 | 垂直稳、均阅上去后 | 建议 **月 ≤1～2 单**；拒偏离栏目商单 |
| 直播 | 非优先 | 人设与「对照编辑」冲突大 |

**预期管理**：前 20 条多数佣金接近 0；稳定后单条 3k～8k 阅读、挂链合理时，直接佣金常为 **几十～一两百/篇** 量级（爆款例外）。蒲公英固定稿费往往 **早于** 单篇 CPS 像样。

**品类优先级（挂链）**：收纳、小加湿、手持吸尘、除螨 > 大件炸锅/破壁。

## 五、用户与情绪价值

- 平台 **女性占比高**，但家居/租屋笔记仍有不少 **男性静默收藏**。  
- **不必**改垂直为美妆；**不必**「姐妹们冲」。用 **租房党、合租、插排、台面** 等处境词（与 `discovery.md` 一致）。  
- 情绪价值 = **被理解 + 减负（减法）+ 可安放「怕买错」**，不是刺激囤货。  
- 视觉：无印式克制、真实窄厨房；避免粉红样板间。  
- 开头示例口径：「插排满员 → 三类先别急着买 → 对照三件事」。

## 六、内容形态：是否都要图文？

**不是只能图文**，但 **简选默认仍推荐「多图图文」**（对照表可截图收藏）。

| 形态 | 平台支持 | 简选建议 |
|------|----------|----------|
| **图文笔记** | ✅ 主流；创作服务平台 / App 发布 | **默认 3～6 图**（处境 / 三类买错 / 对照三件事） |
| **视频笔记** | ✅ MP4/MOV，封面关键 | **约 20%**；30～90s 实拍台面/插排，口播对照逻辑 |
| **文字笔记** | App「写文字」；部分版本会 **把文字排成卡片图**（非真正零视觉） | 可作轻量观点；**对照表体仍建议多图**，否则收藏弱 |
| **纯文字无图** | 历史上有「备忘录截图当图」曲线做法；规则与入口常变 | **不作为简选主形态** |

结论：

- 小红书 **不强制** 每条都是传统「拍照图文」。  
- 对 **买前对照** 业务，**多图清单 > 纯文字 > 纯视频**（视频作信任补充，不作唯一载体）。

发布入口（人工）：

- App：`+` → 图文 / 视频 / 写文字  
- 创作者服务平台：`creator.xiaohongshu.com`  
- 千帆等：**企业商家**后台，非个人号主路径

## 七、程序化发笔记 / API（与 stock-ai 关系）

### 7.1 官方开放平台（`open.xiaohongshu.com`）

- 主体是 **电商开放平台**：商品、订单、库存、ERP、打单等（见 Apifox 文档类目表）。  
- **不向个人创作者**提供「代替用户在 App 里发笔记」的公开、稳定、个人可申请的写稿 API。  
- 部分 **数据/合作** 能力（如笔记信息查询、品牌/商家侧分享链路）面向 **企业资质 + 审批准入**，且多为 **读数据或商家带货**，不是 Hermes 式 `upsert_draft` 日更覆写。  

### 7.2 与微信公众号对比

| | 微信公众号（简选已做） | 小红书 |
|--|------------------------|--------|
| 草稿覆写 | `wechat_mp_client` + AppID/Secret | ❌ 无对等官方能力 |
| 定时无人推送 | launchd + batch | ❌ 不建议对标；风控严 |
| 合规自动化 | 可控（合规脚本 + 人工发） | 发布环节宜 **人工确认** |

### 7.3 非官方路径（记录风险，仓库不实现）

- 网传 `edith.xiaohongshu.com` 等 **逆向接口** + 签名服务：易失效，**封号风险高**（行业反馈 2026 起严打 AI 托管 / API 发文）。  
- **RPA / 指纹浏览器** 模拟点击发布：不等于官方 API；频率与行为链需像真人，仍可能违规。  
- **第三方「自动发笔记」**：默认 **不纳入** stock-ai 流水线；若用户自行使用，需自担账号风险。  

### 7.4 若未来要在仓库「半自动化」

可做的 **低风险** 层（仍人工点发布）：

1. 从 `jianxuan-v1` 骨架 **生成** 标题、正文、话题、三图文案（Markdown/JSON）。  
2. **渲染** 3 张竖图（模板 + `inline-commerce` 素材）。  
3. 可选：导出到飞书/本地 checklist，**不**调用小红书写接口。  

**不要做**：未经官方文档授权的自动 POST 发笔记、批量点赞评论养号。
