# 普通人的经济生活：接入公众号选题、研究与写作设计

日期：2026-09-16
状态：设计已获用户口头确认，待书面审阅；尚未创建 Skill、研究本期热点或写入公众号草稿。

## 目标与边界

从当前可核实的经济、政策和消费热点出发，解释普通人的收入、支出、时间和选择如何变化。读者不必炒股，也不必懂金融术语。每篇要有真实的新事实、可复核的解释、有条件的作者判断，以及具体的人可能愿意转发或讨论的理由。

题材覆盖工资与就业、价格与消费、住房与房贷、储蓄、养老、养娃、汽车、黄金与汇率、平台经营和公共政策。行业和公司只是解释生活的材料之一，不把栏目收窄为 A 股评论。教育题仍服从现有教育选题地域与稿型要求；本设计不硬编码城市列表，以现行专题真源为准。

本次只接入手动选题、研究、写作与编辑流程。不得新增定时任务、自动发表、公众号草稿槽位、配图回退或 DeepSeek 自动调用；不改变既有两次确认。

## 架构选择

采用独立的 `.cursor/skills/wechat-mp-everyday-economy/SKILL.md` 编排选题和研究，链接既有 `.cursor/skills/wechat-mp-writing/SKILL.md` 与 `.cursor/skills/wechat-mp-drafts/SKILL.md`。新增 Skill 负责“哪件事值得写、证据是什么、怎么算、谁受影响”；既有散文式评论参考负责“文章怎样有作者声音”；既有热点与草稿文档负责来源门禁、手工交接、真实图和写草稿。入口互相指向，不复制整套稿型和运营规则。

不选择把全部流程塞进写稿 Skill：选题、查数和文体会相互遮蔽。也不建立新自动生产流水线：当前用户主动稿的人工 DeepSeek 交接和二次确认是明确边界。

## 一次运行的数据流

### 1. 找当前热点

记录执行时的北京时间与检索截止时间。先找过去 72 小时内政策、统计数据、消费与民生报道、明确金融事件；不足时扩至 7 天。更早的事件仅在有新数据、执行节点或进展时进入候选，并标明原始事件日期。只有搜索命中而无可靠讨论信号时称“近期议题”，不伪称“热榜爆款”；同源转载合并。没有足够证据的热点不强写。

来源分别承担角色：政府和统计机构核规则与数据；正规媒体提供可回源的事件线索；妙想技能提供宏观、公司和市场资料。妙想的 A 股热点能力不能冒充全社会热榜。

### 2. 把新闻转成生活问题并排序

每个候选写清：新变化发生于何时何地，具体影响谁，改变哪笔钱或哪项选择，有什么尚待解释，读者可能转给谁、评论能交流什么经验。硬筛掉日期不明、标题前提未证实、只有情绪或旧闻翻炒的题。其余按真实讨论信号、生活相关性、证据完整度、解释增量和可讨论性排序，只说明高/中/低及理由，不给伪精确“爆款概率”。账单清楚是同等条件下的优点，不凌驾于热度和事实质量。

默认最多三个候选、推荐一个。用户只要候选时停在这里；用户要求直接写时选最合适一题继续研究，不增加额外确认门槛。

### 3. 按问题查数并回源

物价、就业、利率、汇率等宏观问题按需用 `mx-macro-data`；公司收入、成本、利润用 `mx-finance-data`；明确公司、事件、政策线索用 `mx-finance-search`。涉及股票或板块深研才进入妙想股票工作台；财报点评和行业分析必须符合各专项 Skill 的触发边界。不为“用了妙想”而调用所有能力，也不复活旧股票链路。

任何实际未返回的指标明确记为缺项，转向权威公开原文或缩小论点。银行当前产品条款、地方补贴、租金、保险、金饰工费与回购价等不能只靠宏观或公司数据替代。关键数字逐项回原始出处核对日期、地区、人群、单位和统计口径；几家媒体转同一公告只算同一证据。政策区分建议、公布、生效与地方实施。

### 4. 建立可复核的算账底稿

为关键主张记录链接、发布日、事件日、数据期、适用对象、验证结果与主张类型；将事实、机构观点、作者推断和假设示例分开。能够测算时列输入、单位、公式、期间和遗漏成本，复核结果；不适合算出单一金额时说明缺少哪些变量，不为制造“干货”编造家庭账本或受访者。全国平均、相关性和企业样本都不能冒充某个家庭的实际账单或单一因果。

数据矛盾先查口径与修订；未解决不任选一个支撑标题。核心证据不足时缩小论点、换题或交付研究缺口。

### 5. 写作与现有流程交接

一篇只回答一个主问题。开篇以新事实和生活后果进入，随后让真实细节、账或比较改变读者对问题的认识，再讨论原因及不同人群的条件。这个顺序只是思路，不固定成逐段问答、同样的小标题或每篇强制“一笔账”。专业词首次出现用白话解释。作者可以表达有依据的个人判断，但不冒充家长、劳动者、采访者或目击者；文学性来自准确细节和停顿，不来自定额比喻与金句。

初次交付研究包、最多三个标题方向和完整手工 DeepSeek 提示词。用户自行取得并贴回初稿后，Agent 先核事实与算账，再按散文式评论参考改全文；随后按稿型原有来源、篇幅、真实图和质量门禁检查，展示终稿与编辑记录，等待第二次确认。未收到用户贴回稿件不另找模型代写；配图不足按原规则停止；未经第二次确认不写草稿。当前设计不改变热点稿目标长度或独立槽位。

讨论问题应能由真实经历或具体取舍回答，例如不同家庭为何保留现金而非提前还贷；不能强迫站队或催转发。选择“转给谁”只是编辑判断，不写成正文的分享指令，也不承诺传播结果。

## 交付、错误处理与验证

选题阶段交付候选、推荐理由和缺项；研究阶段交付事实/数据底稿、算账和边界、标题方向与完整提示词；收稿阶段交付核实编辑稿、来源、图数与待确认事项。无热点、无原始来源、关键数字不一致、妙想未返回或草稿条件不满足时明确停在哪一步及可行的缩小论点/换题办法。

实施时以当前工作树为基线，对已有未提交文件做局部补丁，不回退、不覆盖。验证包括 Skill 入口与链接、两个离线样题（一个家庭账单、一个消费现象）的选题与算账演练、提示词与原稿型门禁的一致性；若修改 Python 行为再补失败测试和相关 pytest。演练不调用微信草稿写入或发表。

首批建议人工试做六篇，家庭账单、消费现象、热点解释各两篇。发布后只有后台确实提供的指标才报告，并比较相同 24 小时和 7 天窗口的完读、分享、收藏、有效评论与流量渠道；少量样本只用于校准，不宣称找到了“爆款公式”。

## 验收标准

- 非股民能看懂热点与自己的收入、支出或选择有什么关系。
- “当前”有执行时的时间与来源证据；热度没有被搜索数量或转载放大。
- 妙想只提供实际返回的数据和研究线索，关键条款回原文。
- 算账有输入、公式、适用人群和遗漏成本；未知不能写成确定金额。
- 文章有作者判断而不伪造亲历，不写成 AI 问答卡片。
- 现有手工交接、两次确认、配图与草稿安全门禁全部保留。
