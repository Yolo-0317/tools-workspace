## 为什么网页版 DeepSeek 显得会写

1. **同一对话框有记忆**：这个会话里已有用户金样（倪大红对白）、打回稿（舞台灯光场记）、事实纠正（二十八篇不是二十八个字）。网页版是在「已对齐口味」之后写；无记忆 API 每次冷启动，容易写成说明书或假钩子标题。
2. **任务被改成场记不是观众**：不写「我哭了」，写动作+现场一人反应。
3. **中文信息流语感**：第一句要砸事件，不铺灯光。这是语料里公众号/热帖的常见节奏，不是魔法。
4. **它仍会错**：为押「代价换回报」会写成二十八个字。规律要沉淀，数字要人工核对。

写稿默认仍走 API；网页长会话用来定调、打样、纠错，再把规律写入 `distilled-patterns.md`。

## 核心判断

任务定义错误：让模型当「观众」→ 观后感 + 「我」。应定义为 **场记转写器**：只摆镜头、对白、动作，隐形叙事人。

第二层不是「润色」，是 **保护性剪辑**：删作者「我」、缩短冗句；**禁止改写第一段**。

## 标题三公式（32 字内，无「我」）

| 模板 | 格式 | 例 |
|------|------|-----|
| 台词梗概 | 最狠台词 + 已知反应 | 「我妻我子…舍命护它」——撒贝宁当场泪崩 |
| 代价速写 | 他…了一辈子…也没能… | 他护了一辈子竹简，也没能护住一个完整家 |
| 古今错位 | 古人没…却… | 古人没看过手机，却花了半条命守几卷书 |

## 假爆款开头 → 改法

1. **时间公文**「2021大年初一节目播出…」→ 伏生抱竹简+对白
2. **观后感**「看完我哭了…」→ 只摆妻儿护书事实
3. **安利**「强烈推荐…」→ 侧写反应（演完没人鼓掌直到字幕走完）
