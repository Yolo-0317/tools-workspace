# OpenCLI 筹码快照设计

## 目标

为 A 股个股诊断补齐可审计的收盘筹码快照，使诊断引擎能够在最近完整交易日数据齐备时计算触发价、入场上限和失效价。采集仅由用户发起诊断时按需触发，不增加定时刷新或自动交易能力。

## 已确认根因

- 现有 `capture.py` 只实现行情和资金流采集，没有 `chip` 生产入口。
- MySQL 的 `stt_evidence_snapshots` 当前没有任何快照，603011 也没有筹码采集尝试。
- 东财普通行情页 DOM 不直接展示所需筹码字段。
- OpenCLI 已安装在 Node 22 路径；代码的 Node 24 默认路径已失效，运行时需要优先读取 `OPENCLI_BIN`，再从 `PATH` 和本机 nvm 安装中发现可执行文件。

## 方案选择

采用 OpenCLI 浏览器上下文中的东财日 K 数据和换手率，按东财 CYQ 客户端方法计算筹码分布。拒绝 Python 直接 HTTP 请求东财；人工录入只作为未来独立能力，不在本次范围内。

该数据属于基于历史成交和换手衰减的估算筹码，不是交易所披露的投资者真实持仓成本。快照必须记录算法版本、来源交易日、输入 K 线数量和原始证据引用，用户输出中继续称为“筹码快照”，不得表述为真实持仓成本。

## 组件与数据流

1. `fetch_eastmoney_quotes.py` 负责发现 OpenCLI，并在浏览器上下文获取最多 210 根未复权日 K，包含日期、开高低收、成交量、成交额和换手率。
2. 新建独立筹码计算模块。输入按交易日升序的日 K，使用换手率衰减和 150 档价格分布计算最新交易日指标。
3. `capture.py` 增加筹码采集入口，通过 `CaptureRecorder` 完成字段校验、采集审计和快照写入。
4. 统一诊断运行时在盘前、盘后和非交易日读取最近完整交易日筹码；快照缺失时按需采集一次后重读。盘中和午间不临时重算收盘筹码。
5. OpenCLI、页面、解析或数据库写入失败时写入采集失败审计，并保持 `NO_TRADE`，不得使用推断值补齐。

## 快照字段与单位

快照至少包含：

- `source_trade_date`：筹码输入对应的最近完整交易日。
- `cost_90_low`、`cost_90_high`：90% 筹码成本区下限和上限，单位为元。
- `average_cost`：50% 累计筹码对应的平均成本，单位为元。
- `profit_ratio`：收盘价以下的估算获利筹码比例，存为 0–100 的百分数。
- `concentration`：`(上限 - 下限) / (上限 + 下限)`，存为 0–100 的百分数。
- `input_bar_count`、`method`：审计信息；`method` 固定标识 CYQ 算法版本。

校验要求：价格非负、成本下限不高于上限、两个百分数字段位于 0–100、来源交易日不晚于诊断日期、输入至少 20 根有效日 K。

## 新鲜度

筹码按交易日判断，而不是固定 24 小时 TTL：

- 盘后要求 `source_trade_date` 等于今日且今日完整日 K 已入库。
- 盘前要求等于上一确认交易日。
- 非交易日允许最近确认交易日。
- 盘中只复用盘前已确认的上一完整交易日筹码，不在连续竞价阶段重算。

旧快照可以保留用于审计，但不能通过当前交易计划门禁。

## OpenCLI 发现规则

发现顺序为：

1. `OPENCLI_BIN` 显式路径；
2. 当前 `PATH` 中的 `opencli`；
3. `~/.nvm/versions/node/*/bin/opencli` 中语义版本最高且可执行的文件。

若全部缺失，输出明确的安装提示并保持安全降级。只有确认未安装时才安装；本机当前已安装，因此本次不执行重复安装。

## 诊断集成

按需补采只发生在静态诊断路径。运行时先加载完整日线并确定目标交易日，再查找同日有效筹码；缺失时调用一次筹码采集器并重读。采集器不得改变市场状态、组合风控或发布模式。

即使筹码齐备，收盘诊断最多生成 `WAIT_ENTRY`；只有下一交易日盘中五项证据和组合风控全部通过，`LIVE` 模式才可能产生可执行的 `BUY_ALLOWED`。

## 测试与验收

- 使用固定日 K fixture 验证 CYQ 成本区、平均成本、获利比例和集中度。
- 验证百分数单位、无换手、一字板、少于 20 根 K 线和无效输入。
- 验证 OpenCLI 显式配置、PATH、nvm 回退和完全缺失。
- 验证成功采集写入 `chip` 快照，解析失败只写采集尝试。
- 验证静态诊断缺失时只补采一次，盘中和午间不补采。
- 验证筹码按目标交易日判断，周五快照在周一盘前有效，固定 24 小时不再误杀。
- 全量单元测试、家庭 MySQL 集成测试和 603011 真实只读/受控写入冒烟均通过；真实写入前只保存东财来源的可审计快照，不写人工推测值。

## 非目标

- 不实现看板、定时任务、推送或自动下单。
- 不抓取全市场筹码，只处理用户诊断的单只股票。
- 不将筹码估算替代公告、基本面、板块、盘口或组合风控。
