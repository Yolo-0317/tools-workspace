# 公众号热点深评贴图（newspic）草稿

本项目里，用户只说“贴图、图片消息、小绿书”时，默认先按栀夏虚拟生活方式贴图处理，使用 `wechat-mp-virtual-lifestyle` 与 `virtual_lifestyle` 槽位。只有用户明确说“热点深评贴图、新闻图集、事件现场图集”时，才使用本文的通用热点 `newspic` 流程。两者底层都是 `draft/add` 的 `article_type="newspic"`，但选题、图源、字数门禁和草稿槽位不同，均不是长图文 `news`。

## 稿型定位

- 默认写**当天热搜的热点深评**，不是泛知识清单、营销软文或长图文的删节版。
- 从微博、百度双榜选题，必须再找到至少一条同题权威报道、机构通报或原始研究；仅有热搜词则改写“传言为何传播”，不得把热搜当事实。
- 标题 8～20 字，写出具体对象与矛盾；**6 图写 600～800 字，7～9 图写 800～1000 字**，最大 1000 字。
- 说明固定 4 段：热搜事件与可确认事实 → 现场/规则/研究证据 → 不夸大的判断 → 给读者的追问或行动。
- 对未获认定的责任、数字和因果使用“网传、尚待核实、报道显示”；不代替监管或司法结论。

## 图片数量与分镜

- 热点深评默认 **6 图**；事实素材足够时可扩至 **7～9 图**。4 图只用于 demo 或材料极少的短评。
- 分镜依次为：**封面疑问 → 事件场景 → 当事人/处置 → 可核对证据 → 影响与分歧 → 评论追问**；加图只能补充新事实或视角，不重复画面。
- **必须先找同题公开报道图**，每张报道图都在 `image-sources.json` 记录报道页 URL 与标题。
- 公开报道图不足时才能生成原创事件插画；来源清单必须记录 `source_type=original` 与具体 `fallback_reason`。生成图不得伪造现场、机构标识、伤亡数字或当事人身份，并标注“原创新闻插画”。

## 固定链路

1. 拉取双榜热搜，确认至少一条可核验来源，再确定“事实—判断”主轴。
2. 运行 `--topic` 自动素材模式，先抓 6 张同题报道图；不足时程序写出 `codex-image-request.json` 并以退出码 2 暂停。
3. Codex 逐项读取请求中的 `slots`，每个图位单独调用一次内置 ImageGen；生成后从 `$CODEX_HOME/generated_images/` 复制到对应的绝对 `output_path`。只生成请求列出的缺口，不覆盖报道图。
4. Codex 重跑原命令；脚本识别 `manual-*` 原创图，自动生成 `image-sources.json`，再继续上传与草稿更新。
5. 按图数写 600～1000 字说明，逐项删掉未经证实的指控和情绪化结论。
6. 逐张核对图片对应的叙事位置和来源记录；CLI 会拒绝缺来源或缺原创补位原因的图片。
7. 脚本以槽位优先更新草稿，首次则创建；回读草稿确认 `article_type=newspic`、图片数与说明长度。
8. 草稿箱人工预览后再发表；贴图占当天一次群发机会，勿与长图文重复群发。

```bash
cd stock-ai
uv run python -m scripts.tools.wechat_mp_newspic_draft \
  --slot newspic_consumer --title "手机壳材料从哪来？" \
  --content output/newspic_copy.txt \
  --topic "手机壳 材料 来源" \
  --dry-run
```

首次先保留 `--dry-run`：它会完成取图、来源和内容校验，但绝不上传微信。Codex 补图并确认通过后，去掉 `--dry-run` 才创建或更新草稿。

可核验的报道页用重复参数优先提供，默认自动准备 6 图，允许 `--image-count 6..9`：

```bash
uv run python -m scripts.tools.wechat_mp_newspic_draft \
  --slot newspic_consumer --title "手机壳材料从哪来？" \
  --content output/newspic_copy.txt \
  --topic "手机壳 材料 来源" \
  --research-url https://example.com/report-a \
  --dry-run
```

原手工传图模式继续支持：

```bash
uv run python -m scripts.tools.wechat_mp_newspic_draft \
  --slot newspic_consumer --title "手机壳材料从哪来？" \
  --content output/newspic_copy.txt \
  --images assets/a.jpg assets/b.jpg assets/c.jpg assets/d.jpg assets/e.jpg assets/f.jpg \
  --image-sources assets/image-sources.json
```

`codex-image-request.json` 的每个 `prompt` 已包含稿型构图和新闻插画安全限制。Codex 不得改写为现场照片，不得增加可识别真人、机构标识、数字、文字、水印或未经核实的细节。内置 ImageGen 不接收目标路径参数；必须先生成，再把选定结果复制到请求给出的项目路径。

## 贴图与长图文的发布分工

贴图和 `news` 长图文都属于**同一公众号**：粉丝、主体、流量主资格和后台数据共享；贴图只是在主页、推荐和浏览时有独立内容形态，不能当作新号重新积累粉丝。

| 场景 | 首选形态 | 内容要求 | 后续承接 |
|---|---|---|---|
| 单一事件、现场感强、争议清晰 | 6～9 图贴图 | 600～1000 字，事实—证据—判断—追问 | 进入同主题合集 |
| 事实链复杂、需多来源与完整论证 | 长图文 `news` | 2000 字以上、封面 + 正文 3 图 | 贴图只做摘要或不重复群发 |
| 已验证高关注的垂类议题 | 贴图系列 + 周度长文 | 贴图追热点，长文做方法/背景 | 合集、历史文章、合规互选任务 |
| 明确产品决策需求 | 独立转化型贴图/长文 | 评测、清单、合作标识完整 | 站内商品/小程序/互选任务 |

- **公众号长图文只要出稿，就选复杂事实链**；不设每日固定产量。
- 需要出贴图草稿时，按星期选择主题。热点贴图负责推荐曝光和关注；长图文当天或随后发布，补足来龙去脉、规则与可执行方法。两者同题时必须各自提供新增信息。
- 长文不把贴图内容简单拉长，贴图也不把长文缩成卡片；两者必须各自提供新增信息。

### 选题路由

- **贴图优先选热点视觉事件**：有清楚现场、物件、人物行动或前后反差，能找到至少 6 张同题报道图；例如公共事件处置、消费现场、文娱现象、灾害避险。目标是让读者在滑图中先看懂发生什么。
- **长图文优先选复杂事实链**：涉及多方说法、时间线、法规/研究、利益关系或需要回答“为什么”的议题；例如 AI 行业变化、消费风险机制、劳动争议规则。目标是建立可信的解释能力。
- 不以热搜排名机械决定形态：没有图、但事实链复杂的热搜，写长文；画面很强、但没有足够可核对事实的热搜，不写。

### 每周手动发布节奏

所有安排均为**贴图选题框架，不开启定时群发**。只有用户要求贴图草稿时才按下表取当日主题；长图文按需另行选复杂事实链。

| 星期 | 当日贴图主题 | 占比/作用 |
|---|---|---|
| 周一 | 热点视觉事件 | 热点引流 1/4 |
| 周二 | 相邻专题：AI/职场/消费机制 | 专题沉淀 1/2 |
| 周三 | 热点视觉事件 | 热点引流 2/4 |
| 周四 | 相邻专题：延伸解释/清单 | 专题沉淀 2/2 |
| 周五 | 热点视觉事件 | 热点引流 3/4 |
| 周六 | 热点视觉事件 | 热点引流 4/4 |
| 周日 | 转化内容或专题复盘 | 转化 1/1；无真实价值则复盘贴图 |

- 贴图主题周配比固定为：**热点引流 4/7、相邻专题 2/7、转化/复盘 1/7**。
- 周日转化内容最高每两周一次，必须与已跑出阅读的专题一致，并明确合作或推广性质；没有真实价值就改为专题复盘。
- 每周复盘四项：贴图推荐阅读、关注率、合集点击率、长文完读/收藏；下周只调整一个变量（选题、标题、图数或承接）。

## 合规转化漏斗

1. **热点贴图（70%）**：社会/文娱/职场热点，目标是推荐、阅读和关注；末尾只指向一个站内专题合集。
2. **相邻专题（20%）**：把高频热点沉淀为 AI 内容、职场、消费避坑等固定栏目，目标是让泛流量自筛选。
3. **转化内容（10%）**：仅在有真实决策需求时做工具评测、清单或品牌合作，合作内容显著标注，不伪装成新闻。
4. **收入顺序**：优先流量主程序化广告；专题稳定后申请互选招募任务；最后才尝试与栏目强相关的站内商品或服务。

禁止复刻搬运、互赞互关、强制截图、二维码导流、夸张标题或将社会热点硬塞商品；这些做法会伤害推荐、信任和合规性。复盘只看四项：贴图推荐阅读、关注率、合集点击率、相邻专题的阅读率。
