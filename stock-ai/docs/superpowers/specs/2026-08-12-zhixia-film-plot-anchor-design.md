# 栀夏影视贴图剧情锚点设计

## 背景与问题

当前栀夏影视贴图常从片名、角色标签或宣传主题直接跳到职场、善意、选择等普遍观点。即使表达通顺，替换片名和人物后正文仍可能成立，读者看不到“为什么必须借这部电影来谈”，也容易被平台识别为低创作度的泛化感想。

这次调整的目标不是增加剧情梗概，而是让观点由具体剧情生长出来：先写角色在明确处境中的行动与后果，再讨论这一选择暴露出的关系、性格或现实问题。

## 写作模式

单片影视贴图默认采用“一场戏写透”。只有一条内容无法由单场戏承载时，才切换到“角色变化线”。尚未上映或只能核验官方预告的影片使用“预告观察”，不得写成观后感。

### 一场戏写透

适用于 `popular_film`、`classic_single` 和大多数 `ai_film`：

1. 交代角色当时的具体处境。
2. 描述角色做了什么，而不是只概括角色标签。
3. 写出另一个人物或环境怎样回应，以及行动造成的直接后果。
4. 从这个选择和后果中提出栀夏观察。

正文按“剧情锚点 → 人物选择 → 关系或处境变化 → 栀夏观察”推进。剧情及其直接因果约占六成，分析约占四成；比例用于指导写作，不按字符机械切割。

### 角色变化线

适用于需要前后对照的 `classic_single` 或较长人物稿。选取两至三个相互关联的场景，必须能说明同一人物关系、选择或认识发生了怎样的变化。不得把多个名场面并列成剧情摘要。

### 预告观察

适用于 `announced`、`presale`，以及虽已上映但当前只能取得官方预告材料的影片。标题或首段明确写“预告观察”，正文只讨论官方物料已展示的画面、台词、人物设定和冲突，不推断完整剧情，不使用“电影告诉我们”“这个角色最终”等已观影口吻。

## 选题卡数据

单片影视选题卡新增以下字段：

```json
{
  "film_writing_mode": "scene_focus",
  "plot_anchors": [
    {
      "scene": "可识别的场景或事件",
      "character": "行动人物",
      "action": "具体行动",
      "counterpart_or_pressure": "回应人物或外部压力",
      "consequence": "行动造成的直接后果",
      "source_url": "https://可核验原页"
    }
  ]
}
```

`film_writing_mode` 允许：

- `scene_focus`：一场戏写透，默认值。
- `character_arc`：角色变化线。
- `trailer_observation`：预告观察。

`scene_focus` 至少填写两个剧情锚点；两个锚点可以是同一场戏中的“行动”和“回应/后果”，但不得只是同义改写。`character_arc` 至少填写两个来自不同阶段的锚点。`trailer_observation` 至少填写一个锚点，来源必须是电影官方、出品发行方或可追溯媒体发布的官方物料。

经典片单 `classic_list` 不强制使用上述单片结构，继续以三至五部电影的明确选择依据为核心。

## 成稿规则

- 标题不超过公众号贴图现有的 20 字限制，并同时包含片名与具体动作、处境或人物关系；不以抽象情绪代替内容。
- 开头两个自然段内进入第一个剧情锚点，不从演员热度、票房或泛主题开始长篇铺垫。
- 正文至少自然呈现选题卡中的两个不同锚点；程序检查锚点的短语证据，人工检查因果关系是否成立。
- 观点必须回答“这个角色为什么在这里这样做，以及结果说明了什么”，不得只借角色标签讨论普遍人生道理。
- 每张图按剧情顺序承担一个功能：场景、行动、回应、后果或收束。海报和人物宣传照不能靠换构图重复凑数。
- 发布前执行“换片测试”：如果替换片名和角色名后正文仍基本成立，退回重写。
- 不为增加剧情贴合而复述完整故事。剧透继续遵守 S0、S1、S2 门禁；S2 首行保留“含结局讨论”。
- AI 身份披露继续沿用 `ai_disclosure_mode`；平台发表页已声明时，正文不重复添加。

## 字数与通道

不新增第三套字数区间，沿用现有简稿与人物/专题稿区间，避免把“更贴剧情”误解为一律写长：

- `popular_film` 简稿：180～320 字，只承载单一场景和一个判断。
- `popular_film` 四图人物稿：400～550 字。
- `popular_film` 五至六图专题稿：550～750 字。
- `classic_single`、`classic_list`、`ai_film` 暂沿用当前门禁。

后续若数据证明简稿无法形成有效剧情讨论，再单独调整区间，不在本次改动中扩大范围。

## 程序门禁

在 `wechat_mp_virtual_film.py` 中完成以下校验：

1. 规范化并校验 `film_writing_mode` 与 `plot_anchors`。
2. 根据模式检查锚点数量、字段完整性和 HTTPS 来源。
3. `announced`、`presale` 强制使用 `trailer_observation`；经典电影不得使用该模式。
4. 校验正文包含足够的锚点短语证据。短语检查只负责拦截完全脱离剧情的稿件，不替代人工判断。
5. 保留现有片名、图片数、字数、剧透、夸张表达、虚构观影经历和 AI 声明校验。

选题卡缺少新字段时直接报错，不静默退回旧写法。这样可以保证所有后续单片稿都经过剧情门禁。历史台账和已经推送的草稿不回溯修改。

## 文档调整

在 `wechat-mp-virtual-lifestyle/SKILL.md` 的“双影视栏目”和“每次执行”中加入三种写作模式、剧情锚点字段、换片测试和图片叙事顺序。

已有《欢迎来龙餐馆》单篇设计中“剧情事实不超过全文三分之一”的规则与本设计冲突，应在实现时改为“剧情及直接因果约占六成”，并要求具体场景锚点；不能继续仅凭角色设定和宣传梗概成稿。

## 测试与验收

单元测试至少覆盖：

- `scene_focus` 缺少两个锚点时拒绝。
- 锚点缺少行动、后果或 HTTPS 来源时拒绝。
- `character_arc` 的锚点不足或阶段重复时拒绝。
- 未上映影片未使用 `trailer_observation` 时拒绝。
- `trailer_observation` 使用结果性观影口吻时拒绝。
- 正文未命中足够锚点短语时拒绝。
- 满足剧情锚点、字数、图片和披露规则的稿件通过。
- `classic_list` 保持原有行为，不被单片门禁误伤。

验收时运行 `tests/unit/test_wechat_mp_virtual_film.py`，再运行受影响的 newspic 与虚拟生活方式相关单元测试。最后用一张新的单片选题卡做 dry-run，确认错误提示能明确指出缺少的剧情锚点，而不是只给出笼统质量失败。

## 不在本次范围

- 不自动理解整部电影或判断锚点事实真伪，来源和剧情对应关系仍需人工核验。
- 不回写或删除已发表内容。
- 不改变热点深评贴图、长图文影评和非影视栀夏贴图的结构。
- 不引入新的自动发表流程。
