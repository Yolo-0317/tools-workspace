# 通用公众号文章编写

## 使用入口与规则归属

按三层读取，不把同一要求重复执行：

| 层级 | 唯一维护内容 | 入口 |
| --- | --- | --- |
| 中文写作基座 | 叙述身份、材料整合、语法与口吻、承接、分段回读、语义保护 | [中文写作基座](../../../docs/writing/中文写作基座.md)及其关联知识库、用户正例 |
| 本 Skill | 主笔全程职责、参考案例调用、工作文件、审稿协作、标题、配图、手机排版、交付 | 本文件及下列按需参考 |
| 当前专题 | 题材范围、事实来源、篇幅、关键主张记录与工程交接 | 通过仓库 `wechat-mp-drafts` 决策树命中一个专题 |

用户当次要求优先。专题补充差异，不重复定义通用表达标准；旧例、钩子模板和账号角色不能覆盖基座，也不能新增发布授权。账号按当前 AGENTS.md 和用户确认内容识别，不因角色卡改名；不自动加账号品牌头。

新写完整稿执行以下流程；选题、局部改句、改标题只处理授权范围。重写先核对信息保留；原稿按用户留档要求处理，用户已要求清理的版本不另存快照。默认完成已授权的研究与改稿，不逐阶段重复索要确认。

仓库默认热点深评读取 [hotspot-deep-review.md](../wechat-mp-writing/hotspot-deep-review.md)。用户明确指定 DeepSeek 才走其手工交接，文学/典籍继续按对应专题；股票研究仅用当前妙想六 Skill。没有适用专题时直接使用本 Skill；必要资料缺失时说明阅读范围，继续完成不依赖它的部分。

## 文体入口

公众号普通非虚构文章采用[基座的随笔写作](../../../docs/writing/中文写作基座.md#公众号随笔写作)。用词、句法、叙述与思索、第一人称及收束均在基座维护；本Skill只补读者、题材、格式和交付，不再定义作者人格或聊天口吻。

结构前按既有参考流程查[随笔写作参考](../../../docs/writing/随笔写作参考.md)，选例仍须适合本篇材料。用户明确指定新闻报道、操作说明等文体时按要求处理；已确认稿件不因规则更新自动重写。

## 1. 选题与文章主线

有题目沿用；“继续”先查最近文章，避免重复。需要选题时给出少量有实质差异的候选；已授权写稿时不额外增加候选审批。

研究和结构用同一篇目录。常青内容不冒充近期热点；声称热门时须有本轮关注证据。主线按基座组织，标题策划接[公众号钩子适配](references/content-hooks.md)。

## 2. 取证与材料

多轮研究先建 `research.md`，逐批记录主张、来源链接、发布与事件日期、实际阅读范围、适用对象、条件和局限。使用原始资料和公开案例；专题规定具体来源优先级。需要实测的结论先完成实际测试，未验证只写来源支持的范围。

多来源材料按[基座的起稿前处理](../../../docs/writing/中文写作基座.md#起稿前让材料进入正文不先替正文讲道理)归拢后，完成下节参考文章选取与必要补采，再写 `outline.md`。协调者将材料、用户要求和篇幅约定放在“起稿交接”区；当前主笔另在“主笔内容设计”区形成实际写作内容，不由协调者预派每段讲解任务。研究备选判断及审稿工程字段留在各自文件。交接内容和独立主笔调用按[drafting-loop.md](references/drafting-loop.md)执行。补证时更新受影响交接，热点评论池和关键主张交接仍由专题管理。

### 参考文章的调用

完整报道、观察与评论稿按[基座的选例顺序](../../../docs/writing/中文写作基座.md#按材料选择写作范式)，在整理材料后、搭结构前进入[案例索引与联网补采](references/external-article-cases.md#本地缺例时联网补采并入库)。该步骤完成选例，或记录实际联网后仍未获得合适案例的结果，才进入结构稿。只改句子、标题或版式时不重开选例。正文中的同题评论来源继续走专题取证，不因入库免核。

实际采用的组织动作记入现有 `outline.md`，分段回读和行文审稿沿用同一记录核对；读了哪些篇目不能代替说明实际借鉴了什么。具体记录和选择边界只在索引页维护，不另加审稿轮次。

## 3. 交接给主笔，再连续起稿与回读

完整创作先读[主笔职责卡](references/lead-writer.md)，同一主笔负责构思、初稿、审稿后的修改补写及定稿，初稿完成不算交付。新稿和完整重写先落实[主笔与编辑的上下文分工](../../../docs/writing/中文写作基座.md#主笔与编辑的上下文分工)，不把诊断清单作为创作任务。执行[基座分段写作与实际回读](../../../docs/writing/中文写作基座.md#分段写作与实际回读)，写入当前稿再读取，不补造执行记录。公众号的工作文件和审稿衔接见[drafting-loop.md](references/drafting-loop.md)。

### 当前表达偏好

表达标准只查基座；起稿前读取[交付版式](references/delivery.md#正文版式)，正文格式只在该页维护。

遇到具体疑点才查案例，不逐篇全量加载：

| 疑点 | 参考用途 |
| --- | --- |
| 审核备注、政策摘录、活动简报 | [表达转换案例](references/editorial-language.md) |
| 案例折返、跨来源断点、信息顺序 | [承接案例](references/chinese-writing-coherence.md) |
| 搭配、数量、并列与句法 | [句法案例及严格逐句记录](references/sentence-grammar.md) |
| 比较解释、必要办理段 | [关系与办理案例](references/sentence-relations.md) |
| 评论停在表态、异议被略过、结论范围过大 | [外部文章案例的任务索引](references/external-article-cases.md) |

这些参考只提供诊断案例或公众号记录格式，不再维护一套语言规则。

## 4. 独立审稿与有限修改

完整稿按[四角色审稿](references/review.md)执行角色输入、集中修改、交叉复核、三轮上限和停止条件；局部稿只启用相关检查。四角色只读提意见，协调者回传，当前主笔统一修改并重验内容与篇幅，按[起稿与返修流程](references/drafting-loop.md)交付；协调者不另行删稿。流程与专题共享一次，补写不重置轮次，不另开语法轮、文体轮或热点轮。

## 5. 标题、配图与手机排版

正文成熟后按[钩子适配](references/content-hooks.md)定题；用户已确认标题保留。默认交付一个选定标题，用户要候选再列出。

默认封面用 huashu 方法设计与内容相关的艺术图，按[艺术配图](references/art-illustration.md)及[方法来源](references/visual-sources.md)执行；正文优先采用与内容相关的真实场景图，截图比例与内容筛选、文末不加评论钩子等要求统一见[交付规则](references/delivery.md)。不再默认采用评论文字截图；用户本次明确指定评论截图时，头像、昵称及回复身份信息用马赛克处理。公开图片默认不另加图题或小字说明。

用户指定真实视频或内容确需真实资料时，改走[真实视频截帧](references/real-video-stills.md)；不自动制作配音或视频。没有配图任务时不强制生成。工具依当前环境与授权选择，实际打开成图再验收，不能把生成图或评论当作新闻现场证据。

## 6. 推草稿边界

全文、工作文件与手机预览按[交付规则](references/delivery.md)处理。写完不自动上传、推草稿或发表；用户要求推草稿后，走 `wechat-mp-drafts` 工程入口，更新原记录并回读。未获授权不上传图床、不分发其他平台、不创建定时任务。

本 Skill 的 huashu 方法来源和取舍保留在[方法记录](references/method-sources.md)，不依赖作者私人素材库或固定模型。
