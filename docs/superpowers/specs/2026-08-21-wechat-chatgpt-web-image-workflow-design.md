# 公众号 ChatGPT 网页配图流程设计

## 目标

将公众号原创配图默认流程调整为：

`Codex 设计分镜和提示词 → ChatGPT 网页生成 → Codex 下载、检查人物一致性 → 插入草稿`

该流程只替换需要原创生成图片的阶段，不改变公开报道图优先、用户确认推稿、正文质量门禁和微信草稿回读规则。

## 适用范围

- 公众号小说、栀夏生活分享及用户明确同意原创配图的长图文。
- 公开报道图能够满足需求时，仍优先使用可核验的公开来源图。
- 用户明确说“直接用 Codex 生成”时，才临时使用 Codex 内置 ImageGen。
- 不调用 OpenAI 图片 API，也不读取或导出 ChatGPT Cookie、密码或会话存储。

## 执行流程

1. Codex 根据成稿设计封面和正文分镜，输出每张图的场景、人物、构图、光线、比例与禁用项。
2. 首先在当前已登录的 ChatGPT 网页新建对话并生成封面，以封面锁定人物形象和统一风格。
3. 后续人物图把已下载封面上传到同一会话作为身份和风格参考，再逐张生成。
4. 每张图生成完成后，通过 ChatGPT 图片详情页的“保存”按钮下载，不直接请求需要登录态的临时图片 URL。
5. Codex检查文件格式、像素尺寸、宽高比、人物年龄、脸型、发型、服装、主要道具、场景与禁用文字。
6. 单张不合格时只返修该图；不得重新生成已通过的图片。
7. 所有图片通过后，复制到对应公众号素材目录，写入正文图片标记并渲染草稿。
8. 推送后回读公众号草稿，确认封面、正文图片数、图序、虚构标识或来源图注及无残留控制符。

## 登录和标签页边界

- 使用当前 Chrome 中已登录的 `https://chatgpt.com/` 页面。
- 页面未登录、当前标签不属于 ChatGPT、页面仍在生成其他任务或图片入口不可用时，立即停止并提示用户处理。
- 自动化不得登录账号、读取 Cookie、切换到其他账号或清理用户历史会话。
- 任务结束后不关闭用户的 ChatGPT 标签页。

## 失败策略

- ChatGPT 网页生成、等待、保存、下载或文件校验任一步失败，流程立即停止。
- 失败后保留已通过的图片和本次分镜，不重复生成。
- 禁止自动回退 Codex ImageGen、图片 API、DeepSeek 或其他生成平台。
- 恢复后从首张未通过图片继续，不重做已通过图片。

## 工具边界

- 新增一个聚焦 ChatGPT 网页图片生成的浏览器适配器，负责页面校验、发送提示、等待成图、打开详情和保存。
- 适配器输出结构化结果：会话 URL、图片标题、下载文件路径、尺寸、状态和错误码。
- 人物一致性判断由 Codex在看图后完成；工具只执行可确定的文件与页面检查，不用像素相似度冒充人物一致性。
- 下载目录中的临时文件在复制到项目素材目录后保留，除非用户明确要求清理。

## 验证

- 单元测试覆盖：非 ChatGPT 页面、未登录、正在生成、成功识别新图、保存按钮缺失、下载未出现、格式或尺寸不合格、失败不回退。
- 浏览器适配器使用可注入命令执行器，测试不访问真实网页。
- 手动烟测使用一张无敏感信息的测试图，验证“发送—生成—保存—定位下载文件”的闭环。
- 技能校验确认新增规则可被公众号写稿入口发现，且没有把原创生成凌驾于公开报道图优先规则之上。

## 验收标准

- 默认原创配图入口明确选择 ChatGPT 网页。
- ChatGPT 网页失败后只返回可行动的提示，不触发任何替代生成器。
- 封面可作为后续人物图参考输入。
- 下载成品能够进入项目素材目录并被公众号富文本渲染器引用。
- 草稿回读能确认最终图片数量与顺序。
