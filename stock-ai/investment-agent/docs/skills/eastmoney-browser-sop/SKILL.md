### OpenCLI Browser 优先调用规范

每次开始采集前，**第一步**先验证 opencli 连通性：
```bash
export PATH="$HOME/.nvm/versions/node/v24.14.1/bin:$PATH"
opencli --version   # 必须返回 1.7.3 才继续
opencli browser state
```
> ✅ 成功 → 继续采集流程
> ❌ 失败 → 复盘检查 TOOLS.md → 修复后再继续，**不得跳过**

调用失败复盘检查（按顺序）：
1. `command not found` → 新终端未 source ~/.zshrc，先 `source ~/.zshrc`
2. 版本不对 → 确认 PATH 指向 v24.14.1
3. 页面空白/超时 → 东方财富JS渲染慢，增加 `wait time N`
4. Chrome未检测到 → 重开Chrome或 `opencli browser open` 触发

数据源优先级（调用顺序）：
1. **opencli browser 东财页面**（最全，优先）
2. **Tushare API**（实时行情，最稳）
3. **MySQL本地库**（历史K线，已调通）
4. **Playwright东方财富**（headless模式，需浏览器）

## ⚠️ 估值体系核心升级（v2）

**旧版问题**：只用 PE 估值，导致梅花生物 PE 7.67 被误判为"低估"，实际上盈利增速在下滑是"价值陷阱"。

**新版框架**：估值必须结合行业分类 + 成长性 + 周期定位三步判断：

```
第一步：判断行业类型 → 选择正确估值指标
第二步：计算 PEG（PE÷增速）→ 判断增速是否匹配估值
第三步：定位周期阶段 → 决定估值方法
```

| 行业类型 | 主要指标 | 旧版问题 |
|---------|---------|---------|
| 电力公用事业 | PB、股息率 | PE无用 |
| 光伏制造 | PS、毛利率趋势 | PE仅供参考 |
| 储能科技 | PEG、EV/EBITDA | 增速匹配才合理 |
| 周期股 | PB底部区间 | **完全不看PE** |
| 消费食品 | 连续ROE稳定性 | 当前PE是结果 |

## 核心分析维度（十一维）

### 第一层：数据采集（基础）
- 基本面（行情、估值、市值）
- 资金面（主力流向、机构行为）
- 北向资金（外资动向）
- 财务面（盈利能力、财务健康度）⚠️ **重点关注六维指标：ROE / 净利润增长 / 资产负债率 / 股息率 / PEG / 经营现金流 vs 净利润**
- 消息面（行业事件、公司公告）
- 研报面（机构观点、目标价）

### 第二层：量化分析（深化）
- 技术面量化：均线位置、成交量确认、技术形态
- 行业对比：板块相对强度、同行估值分位、涨幅排名
- 机构验证：龙虎榜数据、融资融券变化、北向持仓变化
- 成长性分析：连续3年增速稳定性、扣非 vs 归母净利润对比

### 第三层：综合研判（升华）
- **行业分类判断**：拿到数据先定行业类型，对号入座选指标
- **价值陷阱识别**：PE低+增速差 = 陷阱，不建议买
- **周期定位**：底部/复苏/顶部/下行，不同阶段用不同估值方法和操作策略
- 风险细节化：技术风险、基本面风险、事件风险、周期风险
- 操作策略分层：激进型、稳健型、保守型投资者的差异化建议

## 3. 各维度字段采集规则

### 3.1 基本面（行情页）

**必采字段**：
- 价格类：`最新价`、`涨跌`、`涨跌幅`、`今开`、`昨收`、`最高`、`最低`、`涨停`、`跌停`
- 成交类：`成交量`、`成交额`、`换手率`、`量比`
- 估值市值类：`市盈(动)`、`市净`、`总市值`、`流通市值`

**分析要点**：
- 涨跌幅是否超过板块平均？
- 换手率是否异常（过高表示分歧，过低表示筹码锁定）？
- 估值相对历史和同行是否处于低位？

### 3.2 资金面（资金流向页）

**必采字段**：
- `今日主力净流入`、`主力净比`
- `今日超大单净流入`、`超大单净比`
- `今日大单净流入`、`大单净比`
- `今日中单净流入`、`中单净比`
- `今日小单净流入`、`小单净比`

**分析要点**：
- 主力是净流入还是净流出？幅度多大？
- 机构（超大单+大单）与散户（中单+小单）的资金方向是否一致？
- 若机构流入、散户流出 = 底部建仓信号；反之 = 顶部出逃信号

### 3.3 技术面（量化分析）

**采集数据**：
- 5日、20日、60日均线价格
- 5日均量、20日均量
- 今日成交量与均量的对比（放量幅度）
- K线形态描述（如"一阳穿多线"、"放量吞没"等）

**分析要点**：
- 当前价相对均线的位置（站稳短期均线？突破长期均线？）
- 成交量是否有效放量（超过20日均量50%以上为显著放量）
- 技术形态是否处于底部突破或顶部压制的关键位置

### 3.4 行业对比（相对强度分析）

**采集数据**：
- 电力行业指数（如电力ETF 159611）当日涨幅
- 同行龙头（如申能股份、深圳能源、上海电力）当日涨跌幅
- 同行PE、换手率对比

**分析要点**：
- 个股涨幅是否显著超过板块指数？（α行情）
- 在同行中的估值分位如何？
- 涨幅排名在板块内的位置？

### 3.5 机构验证（龙虎榜 + 融资融券）

**采集数据**：
- 若涨幅上榜，查看买入前五席位中是否有机构专用席位
- 买卖净额（机构是否净买入）
- 近期融资余额变化趋势
- 北向资金（沪股通）近3-5日持仓变化

**分析要点**：
- 龙虎榜中是否有机构席位净买入？
- 融资余额是否同步增加（杠杆资金情绪）？
- 北向资金是否同步流入（外资认可度）？

### 3.6 财务面（基本面深化）

**必采字段**：
- `PE(动)`、`市净率`
- `总营收`、`总营收同比`、`净利润`、`净利润同比`
- `毛利率`、`净利率`、`ROE`、`负债率`

**分析要点**：
- 盈利能力是否稳定或改善？
- 财务杠杆是否过高（特别是电力企业）？
- 应收账款周转是否正常？

### 3.7 消息面与行业政策

**采集数据**：
- 公司公告、业绩预告
- 行业政策变化（如长协煤政策、容量电价、市场化交易价格）
- 成本变化（如燃料成本、原材料价格）

**分析要点**：
- 是否有业绩驱动（如业绩预告超预期）？
- 行业政策是否利好该公司？
- 成本变化是否改善公司盈利？

### 3.8 研报面

**采集数据**：
- 最近 2~3 条研报标题、发布日期
- 评级（买入/增持/中性/减持）
- 目标价（若有）

**分析要点**：
- 机构评级是否一致看好？
- 目标价相对当前价的空间？

### ⚠️ 估值体系升级说明（重要！）

**估值必须结合行业分类判断，禁止只用 PE。不同行业用不同指标：**

| 行业类型 | 主要估值指标 | 参考标准 |
|---------|------------|---------|
| **电力/公用事业** | PB、股息率 | PB < 1.5倍低估，> 3倍高估；股息率 > 4%优 |
| **光伏/制造** | PS、毛利率 | PS < 3倍低估；毛利率趋势比PE更重要 |
| **储能/科技** | PEG、EV/EBITDA | PEG < 1低估，> 2高估；看增速是否匹配PE |
| **消费/食品** | PE、ROE稳定性 | 连续5年ROE>15%比PE更重要 |
| **周期股** | PB、EV/EBITDA | PE无用（低PE可能是周期顶部），看PB底部 |
| **金融** | PB | 银行破净（PB<1）常见，需结合资产质量 |

**⚠️ PE 使用警示：**
- PE 低 ≠ 便宜，可能是**价值陷阱**（盈利在下行通道）
- PE 高 ≠ 贵，可能是**成长预期**（盈利在高速增长）
- **核心公式：PEG = PE ÷ 净利润增速（%），PEG < 1 才算低估**

## 10. 成本区分析（强制执行，与操作建议联动）

**每次完成个股深度分析后，必须执行此步骤，并将结论注入操作建议。**

### 执行方式

使用新浪历史K线接口，获取近250日日K数据，统计各价格区间成交量分布，估算筹码成本区：

```python
import urllib.request, json
from collections import defaultdict

headers = {'User-Agent': 'Mozilla/5.0', 'Referer': 'https://finance.sina.com.cn'}

# 获取近250日日K线（prefix = sh 或 sz）
url = f'https://quotes.sina.cn/cn/api/json_v2.php/CN_MarketData.getKLineData?symbol={prefix}{code}&scale=240&ma=5,10,20,60&datalen=250'
req = urllib.request.Request(url, headers=headers)
with urllib.request.urlopen(req, timeout=10) as r:
    data = json.loads(r.read().decode('utf-8', errors='replace'))

# 按0.1元区间统计成交量
price_vol = defaultdict(float)
total_vol = 0
for item in data:
    close = float(item['close'])
    vol = float(item['volume'])
    bucket = round(round(close / 0.1) * 0.1, 1)
    price_vol[bucket] += vol
    total_vol += vol

# 当前价以上套牢比例
current_price = float(data[-1]['close'])
above = sum(v for p, v in price_vol.items() if p > current_price)
below = sum(v for p, v in price_vol.items() if p <= current_price)
trapped_pct = above / total_vol * 100
profit_pct = below / total_vol * 100

# 成交量最密集的5个价位（筹码峰）
top5 = sorted(price_vol.items(), key=lambda x: x[1], reverse=True)[:5]

# 近30日均价
recent30 = data[-30:]
avg30 = sum(float(d['close']) for d in recent30) / len(recent30)

# 均线
last = data[-1]
ma5 = last.get('ma_price5', '-')
ma10 = last.get('ma_price10', '-')
ma20 = last.get('ma_price20', '-')
```

```
### 筹码峰（成交量最密集价位）

| 排名 | 价格 | 占比 | 意义 |
|------|------|------|------|
| 1 | X.X元 | XX.X% | 主要支撑/压力 |

### 成本区结构解读

[根据筹码分布，描述：

- 上方压力区（套牢盘密集区）

| 减仓/止盈 | X.X~X.X元 | 均线密集压力区/套牢盘密集区 |
| 解套目标 | X.X元 | 我的成本价 |
```

### 成本区与操作建议联动规则

| 我的成本位置 | 当前价位置 | 下方支撑 | 操作建议方向 |
|------------|----------|---------|------------|
| 在筹码稀薄区（高位） | 在大筹码峰附近 | 大筹码峰 | 持有，等待反弹至成本区 |
| 在筹码稀薄区（高位） | 远低于大筹码峰 | 无明显支撑 | 谨慎，考虑止损 |
| 在筹码密集区 | 在密集区内 | 密集区下沿 | 持有，密集区内震荡 |
| 在筹码密集区 | 跌破密集区 | 下一个筹码峰 | 止损或等待下一支撑 |
| 在筹码低位（低成本） | 在密集区上方 | 密集区 | 持有，回踩密集区可加仓 |

### 关键判断逻辑

1. **套牢比例 > 50%**：大多数人被套，上方抛压重，反弹乏力
2. **套牢比例 < 20%**：大多数人获利，筹码轻盈，上涨阻力小
3. **我的成本在筹码稀薄区**：解套需要较大涨幅，需耐心等待
4. **我的成本在筹码密集区**：解套相对容易，密集区内震荡即可解套
5. **大筹码峰 = 强支撑/强压力**：价格在峰值附近时，支撑/压力显著增强
6. **均线密集区 = 短期压力**：多条均线聚集处，是反弹的第一道阻力

### 注意事项

- 成本区分析基于历史成交量分布估算，非精确筹码数据
- 0.1元区间粒度适合5~30元价格区间的股票；低价股可用0.05元，高价股可用0.5元
- 若新浪K线接口失败，可跳过此步骤，标注"成本区数据获取失败"
- **此分析结论必须注入最终操作建议**，不得单独列出而不联动
