# 个股诊断交易时段感知设计

## 1. 目标

为聊天中的每次个股诊断提供一个统一入口。入口先依据上海时间和上交所交易日历识别当前状态，再调用对应诊断流程，避免把最近收盘价误称为盘中现价，也避免在盘前、午间休市、盘后或非交易日输出可执行的盘中信号。

本功能只负责诊断路由和结论约束，不增加定时任务、看板、推送或自动下单。

## 2. 时段模型

内部状态分为：

- `PRE_MARKET`：交易日 09:30 前。
- `INTRADAY`：交易日 09:30–11:30、13:00–15:00。
- `MIDDAY_BREAK`：交易日 11:30–13:00。
- `POST_MARKET`：交易日 15:00 后。
- `NON_TRADING_DAY`：上交所交易日历标记为休市的日期。

对用户展示时，`MIDDAY_BREAK` 归入“盘中休市”，因此聊天层仍呈现盘前、盘中、盘后、非交易日四类主状态。边界采用左闭右开：09:30 进入盘中，11:30 进入午间休市，13:00 恢复盘中，15:00 进入盘后。

交易日判断必须使用 SSE 交易日历缓存。周末恒为非交易日；工作日缺少可靠日历记录且刷新失败时，状态标记为不可确认并安全降级为非交易日诊断，不按普通工作日推断开市。

## 3. 统一入口

新增会话感知诊断服务，输入至少包含：

- 六位证券代码。
- 当前带时区时间；运行时默认取 `Asia/Shanghai`，测试必须显式注入。
- MySQL 日线与计划仓储。
- 交易日历查询接口。
- 盘中证据采集或读取接口。
- 持仓与组合风控事实。

服务先生成不可变的 `TradingSessionContext`，再路由到相应诊断器，最终返回统一的 `SessionAwareDiagnosis`。输出必须包含会话状态、诊断所用交易日、行情时间、数据新鲜度、主信号、是否可执行、理由和下一步。

聊天入口只渲染统一结果，不自行判断时段或拼接交易结论。

## 4. 各时段结论

### 4.1 盘前

使用最近一个已完成交易日的日线、已有冻结计划和持仓事实。可以输出 `WAIT_ENTRY`、`HOLD`、`REDUCE`、`EXIT` 或 `NO_TRADE`，但不得输出可执行的 `BUY_ALLOWED`。结论必须注明“盘前，仅供今日观察”，并列出开盘后需要重新验证的价格和五项门禁。

### 4.2 盘中

只有上午、下午连续交易区间允许进行完整盘中验证。实时行情、资金、板块、筹码、盘口、市场状态和组合风控全部有效时，规则层可以计算 `BUY_ALLOWED`；影子模式仍设置 `actionable=false`，聊天主信号显示 `NO_TRADE` 并说明影子规则命中。

已有持仓可以输出 `HOLD`、`REDUCE` 或 `EXIT`，硬失效价优先。

### 4.3 午间休市

可以使用上午最后一笔行情解释走势和持仓风险，但禁止新生成可执行买入放行。已有 `BUY_ALLOWED` 到午间时按五分钟有效期自然失效，主信号降为 `NO_TRADE` 或 `WAIT_ENTRY`，并提示 13:00 后重新采集证据。

### 4.4 盘后

只使用确认完成的当日收盘数据生成下一交易日计划。新开仓结论只能是 `WAIT_ENTRY` 或 `NO_TRADE`。已有持仓可给出下一交易日的 `HOLD`、`REDUCE`、`EXIT` 计划，但不得声称已经盘中触发。

### 4.5 非交易日

使用最近一个已完成交易日的收盘数据进行静态诊断，明确显示最近交易日和下一个交易日。新开仓固定不可执行，主信号为 `NO_TRADE`；已有持仓只给出风险预案，不声称发生当日触发。

## 5. 数据与失败处理

- 交易日历不可确认：安全降级为不可交易诊断，不抓取或使用盘中买入证据。
- MySQL 不可用：返回 `NO_TRADE`，不生成新计划。
- 盘中实时证据缺失、过期或代码错配：返回 `NO_TRADE`；旧值只用于说明，不通过门禁。
- 盘前、盘后和非交易日引用价格时，统一写明“最近交易日收盘”，不得称为现价。
- 当前时间为无时区时间时拒绝处理，不静默假定本地时区。
- 诊断结果中的所有时间内部使用 UTC，聊天展示转换为 `Asia/Shanghai`。

## 6. 聊天输出

每次个股诊断至少输出：

1. 当前状态，例如“交易日盘中”“交易日盘后”“非交易日”。
2. 数据口径和时间，例如“行情截至 14:32”或“使用 8 月 7 日收盘数据”。
3. 唯一主结论及是否可执行。
4. 支撑结论的关键价格、门禁和风险原因。
5. 下一步动作，例如“13:00 后重新验证”或“下一交易日开盘后验证”。

不得同时给出互相冲突的主信号，也不得在不可交易时段用“可以买入”等可执行措辞。

## 7. 测试与验收

- 交易日历：覆盖普通交易日、周末、工作日节假日、缓存缺失且刷新失败。
- 时间边界：覆盖 09:29:59、09:30、11:29:59、11:30、12:59:59、13:00、14:59:59、15:00。
- 路由：验证五种内部状态分别调用正确诊断流程。
- 结论：盘前、午间、盘后和非交易日均不能产生可执行 `BUY_ALLOWED`。
- 数据口径：非盘中输出不得把收盘价标为现价；过期证据必须降级。
- 回归：现有收盘诊断、盘中门禁、仓储和券商事实测试保持通过。
- 集成：家庭 MySQL 中以回滚事务验证最近交易日、冻结计划和诊断结果读取，不留下测试记录。

验收通过后，聊天中的“诊断某只股票”不再要求用户手动选择盘前、盘中、盘后命令，系统自动判定并给出与当前时段一致的结论。
