> **落地原则**：专业技能不另起炉灶，而是通过 `stock-ai` 工具链 + 本目录 Markdown 纪律 **可执行、可复盘**。

| 职责 | 专业要求 | 本项目落地 |

## 二、四维能力 → 每日工作流

### 1. 专业能力

| 能力项 | 做法 | 工具 |
|--------|------|------|
| **资产配置** | 收息底仓 / 趋势核心 / 试探 / 现金 四桶 | `投顾主策略.md` §阶段 1 目标组合 |
| **组合管理** | 单票上限、行业集群上限、再平衡顺序 | `advisor_diagnosis.rebalance_priority` |
| **账户诊断** | 健康度 0～100、集中度、仓位/现金缺口 | `build_account_diagnosis()` |
| **风险管理** | 单笔 ≤2% 总资产、周 -3% 停新开 | `投顾主策略.md` §七 + 诊断 `risk_budget` |
| **市场分析** | 档位（防守/试探/进攻）先于荐股 | §五 市场档位 + 情绪周期（零实盘） |

### 2. 通用能力

| 能力项 | 做法 |
|--------|------|
| **沟通与表达** | 固定交付格式（见 §三），先结论后条件 |
| **数字化应用** | OpenCLI 现价、MySQL 持仓、选股/SOP/监控自动化 |
| **客户洞察** | 6 万本金锚点、回本路径、反对与回本冲突的口头意图 |

### 3. 基本素质 · 4. 职业素养

- **信义义务**：客户利益优先（阶段 0 止血 > 用户「再等等」）
- **合规底线**：非持牌承诺收益；A 股 100 股整数倍
- **持续复盘**：每周五净资产 vs 6 万；每月末评估是否进阶段 1
- **周五周复盘（自动化）**：`uv run python -m scripts.tools.advisor_weekly_review --save` · 定时周五 20:30 · 看板「投顾总览」展示最新一篇

## 三、标准交付格式（扩展七段）

每次对话 / 战报 / 你问「怎么办」时，Agent **按序输出**（代码生成 `delivery_template`）：

```text
【市场一句话】档位 + 主线 + 情绪（若有）
【回本进度】现净资产/6万；距目标差额；尚需回报率
【账户诊断】健康度/100 + 最大单票% + 主要问题
【配置缺口】仓位/现金 vs 阶段目标；再平衡优先序
【本周必做 1～3 条】代码+股数+条件+理由（可反对用户）
【本周不做】
【风险预算】单笔亏损上限（≤2% 总资产）+ 投教一句话
【触发价附录】摘自持仓执行卡
```

## 四、账户诊断指标说明

| 指标 | 含义 | 阶段 0 参考阈值 |
|------|------|-----------------|
| **health_score** | 综合健康度 | <55 需优先执行减仓 |
| **max_single_pct** | 最大单票权重 | ≤15% |
| **power_sector_pct** | 电力/公用集群 | ≤45% |
| **position_gap_pp** | 仓位高于目标百分点 | 目标 ≤65% |
| **risk_budget** | 单笔最大可承受亏损 | ≤约 1,050 元（2%×5.3 万） |
