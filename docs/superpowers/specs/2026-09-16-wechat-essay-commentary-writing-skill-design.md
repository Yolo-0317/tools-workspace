# 公众号散文式评论写作 Skill 升级设计

## 目标与范围

升级现有 `.cursor/skills/wechat-mp-writing/`，让用户主动的教育与社会热点评论读起来像有作者声音的文章，而不是按“事实—政策—风险—建议—提问”逐项回答。保留一个主 Skill，不新建并行写作 Skill。本次只调整写稿与改稿规范及其路由，不改公众号草稿、发布权限、配图协议、来源数量、双确认和工程硬门禁。

工作区相关文件已有未提交修改；实施时以当前工作树为基线，逐项保留既有改动，不回退或整文件覆盖。

## 作者声音的边界

默认采用带个人判断的散文式评论，而非“微信群转述”或公文式政策说明。作者可以用第一人称表达自己的关注、疑问、取舍与价值判断；不得虚构自己是家长、教师、采访者或现场亲历者，也不得补写来源没有提供的对话、动作、心理和画面。第一人称不是篇幅指标，只有能推进主问题时才使用。

文学性来自材料的选择、句子长短、留白、照应与有依据的联想。比喻、典故、反问、单句成段均为可选手法；不设置数量下限，不为“活人感”插入口语词或文化引用。事实重要且证据有限时，准确说明来源与未决部分，不为了流畅删除必要限定。

## 写稿与改稿分层

`SKILL.md` 仍负责按任务路由，但要清楚区分写作、编辑、事实审校与草稿工程。新增一份只供散文式热点评论读取的文章写作参考，描述如何从标题承诺和一条真实细节确定主问题，沿证据改变读者理解的顺序组织段落。正文不预设固定节拍、固定钩子、固定反方段或必须以问句结束；现有稿型的长度、标题及末尾运营要求仍按其真源执行。

DeepSeek 提示词要将已核事实、当事方说法与待核信息留在内部事实包，同时明确请求一篇有作者判断的文章，不把审校指令、反例或“不能写成”句送成公开正文。用户贴回初稿后，编辑先核事实、政策范围和来源，再检查文章主线、段落转折、语气与节奏；最后做轻量去模板检查。事实门禁是最后的可靠性检查，不充当初稿提纲。

现有 `social-commentary-voice.md`、`hotspot-deep-review.md`、`human-say-pass.md`、`anti-ai-voice.md` 与 `traffic-copy-craft.md` 中若有重复或相互冲突的固定公式，应只在命中路径上整理：保留安全与运营硬约束，将“群聊人设”、禁词表和节奏数字降为有条件的编辑提示。其他稿型（财经自动稿、典籍、小说、影视）的语气不因本次调整而改变。

## 验收

1. Skill 入口可以让写稿任务只加载所需写作参考，事实核验和草稿操作另行路由；引用路径均存在，Skill frontmatter 可通过验证。
2. 选取两篇已有、来源完整的教育评论作离线前后对照。新规范下的改写要保留可核事实与核心判断，不能加入虚构经历；读者能指出段落为何接着上一段，且正文没有成串的“需要说明”“不能理解成”自我审稿语。
3. 运行相关文档/提示词测试和 Skill 校验；如调整生成提示词或门禁代码，再运行对应单元测试。验证只针对本地文件，不推送或覆盖微信草稿。
