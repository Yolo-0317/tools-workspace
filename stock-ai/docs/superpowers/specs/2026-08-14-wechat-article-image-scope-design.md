# 公众号报道图正文域校验设计

## 背景

热点长文《AI声线接广告，谁替本人同意了？》从一篇标题相关的新浪报道页抓图时，页面正文没有事件图片。现有抓取器扫描了整页 HTML，把推荐流中的“华盛顿号”航母图识别为候选图片。该图片随后通过尺寸、自然度和来源页标题校验，进入公众号草稿正文。

## 目标

- 门户报道页只从正文内容容器提取候选图片。
- 正文没有合格图片时返回空结果，不使用推荐流、头像、二维码、广告或页面导航中的图片。
- 保留现有网易正文容器裁剪行为，并为新浪正文容器补充等价约束。
- 当前文章删除错误报道图，保留真实事件截图和两张原创解释图，然后更新原草稿，不发表。

## 非目标

- 不引入图像识别模型、OCR 服务或新的外部依赖。
- 不重构整套热点研究、原创度或微信 API 流程。
- 不改变其他文章的正文和封面素材。

## 方案比较

### 方案 A：按站点裁剪正文容器

对新浪页面将扫描范围限制在 `#article` 或 `#article_content` 的正文区域，再执行现有 URL、尺寸和垃圾图规则。正文无图即返回空列表。

优点是改动小、可测试、直接阻断本次根因；缺点是需要逐站点维护正文容器规则。

### 方案 B：增加图片语义识别

对每张图片执行 OCR 或视觉模型判断是否与标题同题。

优点是覆盖面广；缺点是引入网络、成本、延迟和不稳定性，不适合推稿前的失败关闭门禁。

### 方案 C：热点正文全部使用原创图

停用公开报道图，只使用 ImageGen 生成图片。

优点是来源简单；缺点是损失事件证据感，也不符合现有“公开报道图优先、原创图补足”的策略。

## 采用方案

采用方案 A。新增一个只负责裁剪正文 HTML 的内部函数：网易沿用 `post_body` 到推荐区的范围；新浪优先裁剪 `#article`，找不到可靠正文容器时返回空扫描域，禁止退回整页。其他站点暂时保持现状，避免无关扩张。

## 数据流

1. 获取报道页 HTML。
2. 根据页面域名选择正文容器裁剪规则。
3. 只在裁剪后的 HTML 中收集 `img`、懒加载图片和 `og:image` 候选；新浪的 `og:image` 为空时不做整页兜底。
4. 延续已有 URL、尺寸、画面自然度和去重校验。
5. 如果公开报道图不足，现有流程使用 `manual-*` 原创解释图补足。
6. 清理当前话题目录中的 `still-02.jpg` 及对应来源记录，重新运行草稿 dry-run，确认正文不含航母图片 URL 后更新同一草稿槽位。

## 错误处理

- 正文容器缺失或正文无图：返回空候选，不把页面外围素材当作正文图。
- 正文图不足：走既有原创补图逻辑；原创图仍不足则由既有质量门禁停止写入。
- 微信 API、固定出口或原创度门禁失败：停止更新草稿，不绕过。

## 测试与验收

- 新增回归测试：新浪页面正文无图、推荐区含航母图时，候选列表必须为空。
- 新增正向测试：新浪 `#article` 内有事件图时，必须提取该图且排除推荐区图片。
- 运行 `test_wechat_mp_discussion_figures.py` 相关测试和公众号热点 dry-run。
- 检查最终素材列表与生成正文，确认不含军舰图片文件、原 URL 或“华盛顿号”文字。
- 正式命令显示原创度报告通过，并更新既有热点草稿而非发表。
