## 共通写作规则

先读[中文写作基座](../../../docs/writing/中文写作基座.md)，统一执行叙述身份、材料整合、自然表达、分段回读和语义保护。本Skill只补充题材与交付要求；用户明确例外、证据来源及操作权限继续按本专题执行。共通更新只维护基座，不在此复制一份。

# 妙想盘后公众号稿

把当日市场事实写成有完整解释的公众号文章，交付 Markdown 底稿、公众号正文 HTML 和手机预览。用户只要求其中一步时按指定范围做；写稿不等于推送草稿或发表。

## 取证

1. 先确认交易日、收盘口径和读者要回答的问题。沿用[妙想工作台的数据来源、预算与缓存规则](../miaoxiang-stock-workbench/SKILL.md)，股票研究数据只取自当前六个妙想 Skill；一次文章只调用需要的子技能。不得用旧行情接口、Tushare、网页采集或通用搜索补缺。
2. `mx-data` 核指数、成交额、涨跌家数和板块同日数据；`mx-search` 查当日事件、报道和原始公告，分清报道事实、受访者解释与作者推断。用户要东财热股榜时，用 `mx-xuangu` 查询指定交易日的**股吧人气排名**，核对名次、名称、代码、涨跌幅和字段日期；它不是涨幅榜。不要为一篇稿触发自选、模拟交易或社区发布。
3. 保存每次 Skill 的原始结果、查询条件、数据日期和调用台账。写事实卡：数字及单位、对应市场和时点、来源、尚不能推出的结论。接口失败或字段缺失就缩小文章范围并标明缺口，不凭记忆填数。指数涨跌、个股涨跌、板块涨跌与股吧人气分别表述。

## 写作与审校

- 标题默认把“妙想 Skill”放在前半句，再给当天最能说明问题的事实；按[公众号标题规则](../wechat-mp-title-writing/SKILL.md)核正文同题和长度。用户另有标题要求时遵循用户要求。
- 首段给当天发生的事。正文按“数字是什么、为何读者看到的持仓表现可能不同、哪些解释有证据、明后天看什么”推进。用涨跌家数、量价、行业差异解释盘面；外部事件只作为有来源的可能影响，不把单日行情归为单一原因。热股榜放在文末时说明关注度不等于上涨或买入信号。
- 借用[健康稿的作者语言原则](../wechat-mp-health-content/author-role-card.md)与[三遍审稿方法](../wechat-mp-health-content/final-delivery-workflow.md)：先逐句核事实、主语、比较对象和因果，再朗读查套话、假口语与压缩句，最后通读查重复、标题兑现和建议必要性。只借写作方法，不带入医疗声明、健康配图或商品规则。不要为了去 AI 味删掉解释，也不要为凑字数重复结论；用户指定篇幅时用可核实的新信息补足。
- 数字推导须重算。保留采访观点归属、事件时间及不确定性。不写未经证实的收益预测、荐股或仓位指令。文章正文不展示“我用了哪个 Skill 查询”之类工作过程；来源可在文末交代。

## 排版与交付

参考[健康稿手机排版](../wechat-mp-health-content/layout.md)：17px 左右正文、约 1.85 行高、较大段距、蓝色分节、至多一两处有证据的重点框；榜单用窄屏可读的行或表格。排版不改数字、条件和结论。没有已核实许可的图片就不插图。

先保存语义化 Markdown：`#` 标题，`##` 分节，`> ` 表示需要强调的原文判断，普通段落保留完整解释，榜单用有序列表，末尾用 `资料：`。运行[排版脚本](scripts/render_market_article.py)生成 `rendered_content.html` 与 `preview.html`；前者全是内联样式且不重复微信标题字段。脚本只负责排版，不补写事实。

```bash
python3 .cursor/skills/miaoxiang-market-review-article/scripts/render_market_article.py \
  /绝对路径/article.md --output-dir /绝对路径/输出目录
```

交付前比对 Markdown 与 HTML 的数字、段落、榜单名次及来源，核标题长度、日期和手机窄屏溢出。能打开预览时看约 390px 的效果；不能目测时说明实际验证范围。交付正文及预览链接。只有用户明确要求推公众号草稿时，才进入现有[公众号草稿流程](../wechat-mp-drafts/SKILL.md)并回读草稿；不要调用 `mx-poster` 代替公众号发布。
